# 交接：2D 实时战斗高分屏（DPR）适配

> 最后一次重写：本轮把上一轮"坐标全搬到物理像素"的做法**整段推翻重做**。
> 换会话先读这一份，再看代码。

## 1. 目标（没变）

手机上（华为浏览器，DPR 未知）2D 战斗画面发糊。要求：按 `devicePixelRatio` 渲染、
**PC（DPR=1）零行为差异**、可回滚、不破坏功能、最终由用户真机验收。

另有一条硬约束（用户原话）：**「不要面向结果编程」**——每一步都要有数据/像素证据。

## 2. 这一轮的结论（关键，别再走回头路）

上一轮把「世界 / HUD / 相机 / 世界坐标」全部搬到物理像素空间，还用第二台相机渲染
HUD、把 `scale.width` 虚拟化成逻辑值、在二三十个布局函数里乘密度。**那条路注定错位**：

> 项目里几十处布局常量（24 / 12 / RELIC_ROW_CY / 各字号…）是**逻辑语义**的。
> 坐标系一变，它们全都要乘密度；漏一处就是错位，而且相机跟随 / 死区 / 边界 /
> 命中矩形还要各自再乘一遍 —— 永远对不齐。真机表现就是"血条过粗、字号偏大、
> 相机看不到地面"。

正确的做法只有一句：**只动渲染，不动坐标。** Phaser 里这件事是成立的，因为：

| 事实（读 `vendor/phaser.min.js` 得到，不是推断） | 后果 |
|---|---|
| 投影矩阵是**全局一份**：`WebGLRenderer.setProjectionMatrix` → `ortho(0,W,H,0)` | 世界范围 `0..W,0..H` 只由它决定 |
| 相机只贡献「变换矩阵 + 裁剪矩形」两项（`Camera.preRender` / `preRenderCamera` → `pushScissor`） | 视口可以比投影的世界范围大 = ✅ 按密度放大 |
| `ScaleManager.updateScale` 是**唯一**写 `canvas.width/height` 的地方（RESIZE 模式） | 一处接住即可 |
| `zoom` 同时作用于 HUD、跟随、死区、边界、worldView | ⚠️ 所以 `zoom` **不能**当分辨率用（上一轮用 zoom 补，全错） |

于是接法就三件事：

1. `canvas.width/height = 逻辑尺寸 × 密度`（`gameSize/baseSize/displaySize` 仍写逻辑）
2. `renderer` 尺寸 = 画布物理像素；**投影矩阵仍按逻辑尺寸**
3. 相机裁剪矩形临时换成整张画布物理像素（画完换回来，相机自身的 width/height 保持逻辑）

游戏代码（世界坐标 / HUD 坐标 / 相机 / 指针 / 命中矩形）**一行都不用改**。
DPR=1 时三个尺寸完全相等 → 零行为差异。

## 3. 代码位置（`战斗2D.js`）

| 位置 | 作用 |
|---|---|
| `realDeviceDpr()` / `densityFor()` / `preseedDensity()` / `deviceDpr()` / `renderDpr()` | 密度决策（唯一口径 = 限流后的 `state._dprCanvas`） |
| `installDensity(game)` | 上面三件事的三个接点（`updateScale` / `renderer.resize` / `renderer.preRenderCamera`）；由 `API.init` 在 `createGame` 之后立刻调用 |
| `applyTextDensity(list, d)` | 文字按密度重新栅格化（`Text.setResolution`，不改显示尺寸）。`installFontDefault` 的工厂补丁让**新建**文字直接带上 resolution |
| `densityReport()` / `API.设备诊断()` | 真机只读诊断（密度 / 画布 / 投影 / GL 视口 / 相机 / 结论） |
| `iconTextureReady()` + `ensureIconTextures` / `ensureRelicTextures` | 图标纹理按密度生成（`g.setScale(d)` + `generateTexture(16d)`），显示端一律 `setDisplaySize(逻辑值)` |
| `barTexture` / `trackTexture` / `createMeter` / `placeMeter` / `paintMeter` | 血条纹理按密度生成（名字里带密度），**显示尺寸仍是逻辑值**；裁剪值按纹理像素算 |
| 场景 `update` 首部 | 密度变化 → `refreshDensityAssets()`；画布与渲染器尺寸不一致 → 补一次 `renderer.resize` |
| `BUDGET_PIXELS = 4000000` | 清晰 ↔ 帧率的唯一旋钮（超预算按 0.25 降档） |

⚠️ 两个坑（都实测过，别再犯）：

- Phaser 只在 `baseSize` 变化时才调 `renderer.resize`，而"画布变大、逻辑尺寸不变"
  不触发 → 必须在 `updateScale` 里自己补一次，否则 GL 视口停在旧尺寸，**画面只画进左下角一块**。
- Canvas 渲染器（`Phaser.CANVAS`）没有投影可放大，密度**强制为 1**（= 旧行为）。

  血条 `w=224 显示 224×18`、HUD 按钮坐标逐个相同（只有文字分辨率 1→3、纹理像素 224→672 变化）。

- PC 真页面（`主界面.html`，DPR=1）：画布/投影/GL 视口全是 1920×990 1:1，开一局正常。
- `node --check` 通过；`战斗2D.js` CRLF 13532 行、无 BOM。

## 5. 还没做（明确留给下一轮，别当已完成）

1. **世界美术仍是 1x 素材**：角色/怪物精灵表（`角色形象.js`，64×64 帧）、地面/平台/特效纹理
   都是按 1x 生成的，在密度 3 下会被最近邻放大 3 倍 → 方块感。UI/文字/矢量是锐利的。
   要做就得让精灵表按密度生成 + 所有 `setScale` 处统一除以密度（含物理体尺寸），
   属于独立工程，**没有验证过之前不要动**。
2. **Canvas 渲染器**不启用本方案（密度 1）——低端机退化到 CPU 光栅化时仍是旧观感。
3. 已知的独立问题：`#trial2DCanvasHost` 高度 = 舞台高度，而舞台顶部还有 28px 标题条 →
   画布底部有 28px 落在可视区之外（纯 CSS，与本次无关，上一版就这样）。

## 8. 用户复验后追加的两处修改（同一轮）

### ① 空血槽看不见 → 数值像"飘在条外"
用户反馈「狂怒条旁的『狂怒 0/100』没有固定在狂怒条旁边」。查下来不是定位逻辑的问题
（`placeFuryText` → `meterTextX` 一直是"条右边缘 + 10"，与生命/体力同一套），
而是**空槽几乎不可见**：`track` 白 6% + `trackBase` 深色 50%，在 `#07070f` 上实测只差
约 14 灰阶（狂怒条又常常是空的），于是"条"看起来只有左边那一段渐变，数值就显得离条很远。

- 改：`UI.trackAlpha 0.06 → 0.12`、`trackBaseAlpha 0.50 → 0.62`（全项目血条共用，一行）；
  `placeFuryText` 的兜底从 `x = 10` 改成"条右边缘 + gap"（那条兜底本身会把文字甩到屏幕左边）。
- 证据：截图里空槽现在读得出一条完整条身，数值贴在条尾（逻辑 286 = 24+252+10）。

### ② 属性入口从"遗物条上的 10px 小字"改为正式胶囊按钮
用户反馈「技能按钮旁有个小的属性面板按钮，只有一个图标和一行文字，某些设备上会被
技能按钮盖住；改成和图鉴/设置同风格的按钮，并且能在编辑器里调」。

- 新增常驻按钮 `stats`（标签「属性」，图标是 16×16 的**仪表盘**），排在按钮行第一位：
  `属性 / 商店 / 图鉴 / 设置 / 菜单`，与其它几颗同一套 `craftButton` + `layoutPillRow`。
- 动作：`onHudAction('stats')` → `openRelicStatsPage()`（直接开属性明细页）。
- 编辑器：`editableUnits()` 按 `hudButtons` 逐个生单元 → 自动得到 `h.fn.stats`，
  DOM 工具条里显示为「属性」，可单独拖动 / 缩放 / 隐藏（实测 dx=0.08 → x 24→178，s=0.8 → 75×28→65×22）。
- 旧的「▸ 属性」小字整块删除（含 `statsOnly` 那条"靠遗物条托着入口"的通道）：
  `relicStripWanted()` 在「极简」档现在直接返回 false；遗物条不再为属性入口让位。
- 顺手修掉两个连带问题：
  · 遗物条不显示时**容器本身**没设不可见，导致「遗物 / 暂无 · 精英与层主必掉」这排小字
    画在狂怒条与属性面板之间（`refreshRelicStrip` 的早退分支现在会隐藏容器）。
  · `hitBtnList` 不认 `_hidden`：编辑器里隐藏掉的按钮仍然能被点到（现已跳过）。
- 文案：设置里「HUD 密度」的说明改成"收起的内容仍可点画面里的「属性」按钮查看"。

### ③ 狂怒数值随镜头跑（第 11 条，真正的根因）
用户复验：**进房间不动时位置正常，人一走镜头一跟，数字就贴着条往左滑，最后压到条上。**
上一轮只核了"坐标算得对不对"，没核"对象在哪个容器里"。

- 根因：`furyText` / `furyHint` **从没加进 `this.hud` 容器**（`buildHud` 末尾那一大坨
  `this.hud.add([...])` 里漏了这两个）。坐标本身是对的（`meterTextX` = 条右缘 + 10），
  但对象留在**场景根**上：`scrollFactor = 1`、`depth = 0`，于是跟着世界一起平移。
  进房间时相机 `scrollX/scrollY` 恰好是 (0,0) → 看着分毫不差；一走镜头一跟就露馅
  （实测 levelWidth 2084 / 屏宽 1920 → scrollX 最大 164，文字就左移 164px；纵向
  `setBounds(0, -head, ...)` 留了 head≈1000px 余量，跳到高处时文字会直接掉到屏幕中间）。
  对照组：`hpText` / `staminaText` 的 `scrollFactor` 同样是 1，但它们在 `hud` 里
  （容器 `scrollFactor 0`），所以怎么走都不动 —— 差别只在"在不在容器里"。
- 改：`this.hud.add([... this.furyText, this.furyHint ...])`（一行，放在生命/体力数值旁边）。
- 顺手修：`resetCustomLayout` 里 `setScale(1)` 会把血条子对象放大回**纹理**宽度
  （252 → 256，纹理按 8 对齐），即"点一下编辑器里的重置，条粗 4px、数值右移 4px"。
  现在重置后按 `m.w / m.fillH` 重新 `setDisplaySize` 还回去。
- 验证（截图取进房间 / 走到房间末尾两张，怪用 `战斗2D.press('clear')` 清，没手动打）：
  - 修复前：`scrollX 0 → 164`，狂怒行文字像素从 x=286..348 消失（滑到 x≈122，压在条上）。
  - 修复后：`scrollX 0 → 165`，狂怒行文字像素两帧都在 x=286..348（体力行作为对照组也不动）。
  - 纵向：把主角移到 y=60（`scrollY = -183`），文字屏幕坐标仍是 (286, 76)。
  - 编辑器：`h.fury` dx=0.05 → 条右缘 276→372、文字 286→382（gap 恒为 10）；
    重置后条宽回到 252（4px 问题已修）。
  - 回归 28/28、密度验证台 19/19。
