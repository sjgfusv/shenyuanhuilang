## 1. F1 · 双层上层不能从下穿过，但它和单向浮台长得一模一样

### 现象

同一种"浮台"，短的能从下面跳穿上去，特别长的那种会顶头。之前（2.8）所有平台都会挡住，所以玩家的直觉是"平台都能穿"。

### 定位

2.9 给平台加了两套碰撞，但**外观完全相同**：

| 生成入口               | 用途            | 碰撞                                               | 位置           |
| ------------------ | ------------- | ------------------------------------------------ | ------------ |
| `spawnPlatformAt`  | 平厅浮台、断桥桥面     | **单向**：只留 `checkCollision.up`，down/left/right 全关 | 战斗2D.js:8266 |
| `spawnDeckSegment` | 双层骨架的**上层地板** | **实体**：四面全开，且标记 `_solidDeck`（加速下坠也不能穿）           | 战斗2D.js:8138 |

实测（视口 1553×749、第 20 层、无机制）：

| 骨架 | 平台条宽度                       | 实体块 / 总块         |
| -- | --------------------------- | ---------------- |
| 平厅 | 9 条 × 192px                 | **0 / 27**（全单向）  |
| 双层 | 704px + 896px（中间 128px 连通口） | **25 / 25**（全实体） |
| 断桥 | 192 / 384 / 320px           | **0 / 14**（全单向）  |

### 结论

实机里"超长 + 中间一个缺口 + 同高度还有第二段"的那条，就是**双层骨架的上层**。它不能穿是设计如此（上层是地板，穿过去就站不住了，连通口也就没意义了）。

**所以这不是 bug，是"两种地板长得一样"导致的认知错误。** 玩家没有任何线索能预判哪块能穿。

> 如果实机确认 `roomSkeleton` 不是 `double` 却依然顶头，那才是真 bug —— 去查 `TOGGLES.oneWay` 是否为 true、`_platformPass` 是否卡在 true（`setPlatformPassThrough` 只在加速下坠期间临时关 up 面）。

### 方案（**已定：采用 A**）

**A. 视觉区分 —— 采用**

|     | 单向浮台（可穿）            | 双层上层（实体）                        |
| --- | ------------------- | ------------------------------- |
| 厚度  | 薄（现有 64 的一半左右）      | 厚（现有 64 或更厚）                    |
| 下缘  | 渐隐 / 半透明，看得出"下面是空的" | 实心，带竖向支撑柱（桥墩感）                  |
| 上表面 | 一道高光条               | 高光条 + 边缘描边                      |
| 附属  | 无                   | 每 256px 一根暗色支撑柱，连到地面（暗示"这是一层楼"） |
| 材质  | 偏"悬浮物"：轻、薄、冷色       | 偏"建筑"：重、厚、暖色/砖石                 |

关键是**下缘**：玩家判断"能不能穿"看的是底面。底面虚化 = 能穿，底面实心 = 不能穿。

> **美术：impeccable** —— 两套平台贴图（薄+虚化下缘 / 厚+支撑柱）、上层支撑柱、上表面高光条。

**B. 连通口提示 —— 不采用（A 做完之后如果还有人找不到口，再考虑）**

上层连通口两侧加向下的箭头/光带（只在玩家站在上层时显示）。

**C. 把上层改单向 —— 不采用**

那样到处都能上下，连通口失去存在意义，站在上层的远程怪也会掉下来 —— 双层骨架的核心（"找一个口上去"）就没了。

### 验收

同一个房间里同时出现两种平台时，不看代码、只看画面，能说出哪块能穿。

### 2.2 F2 · 前期机制房和断桥出现太少

**现状（读代码得出）**

| 项   | 规则                                                   | 位置                  |
| --- | ---------------------------------------------------- | ------------------- |
| 机制率 | 塌陷 15% / 守点 10% / 限时 10%（**按战斗房算**）                  | 战斗2D.js:685         |
| 起效层 | 第 3 层起                                               | `MECHANIC.minFloor` |
| 保底  | 第 5 / 10 / 15… 层至少 1 间                               | 战斗2D.js:13425       |
| 骨架  | 1 层 100% 平厅；2–5 层 75/25；6–15 层 50/30/20；16+ 40/35/25 | 战斗2D.js:8023        |

**为什么体感更低**：机制率的分母是"战斗房"，而战斗房只占全部房间的 37.5%（8 种房型均匀抽，只有敌袭/精英/镜像算战斗房）。所以：

```
每层 6 间 × 37.5% ≈ 2.25 间战斗房 × 35% ≈ 0.79 间机制房/层（实测 0.74，差值来自层主 / 起点房不参与抽签）
```

**平均每 1.3–1.4 层才遇到一间机制房**，而断桥要到第 6 层才可能出现。10 层里只见到 2 次塌陷、1 次断桥、0 次守点，是符合概率的（守点为 0 的概率约 1/6），不过**"符合概率"和"体验好"是两件事**。

**方案（已定：采用 1 + 2 + 4）**

1. **教学三连（采用）**：第 3 层固定塌陷、第 4 层固定守点、第 5 层固定限时。玩家第一次见到新玩法是"被安排好的"，不是抽奖。之后才进随机池。
2. **每层保底 1 间（采用）**：把"每 5 层保底"改成"第 3 层起每层保底 1 间"，且保底优先选**本层还没出现过的机制**（用 `_floorMechanicKinds` 记一下）。预计机制房从 0.74 间/层升到 1.0–1.2 间/层。
3. **前期加权 —— 不采用**：靠"教学三连 + 每层保底"已经把前 7 层铺满了，再乘 1.5 会让前 10 层机制房过半，反而腻。
4. **断桥提前（采用）**：第 3 层起就进池子，2–5 层权重给 15%（平厅 70 / 双层 15 / 断桥 15）。
5. **一层内不重复机制 —— 不采用**：不做硬约束，只在保底时优先选本层没出现过的（即第 2 条）。普通抽签允许同层重复，避免"为了不重复"把机制挤到别的层。

**改完的预期**

| 层段     | 机制房      | 断桥          |
| ------ | -------- | ----------- |
| 3–9 层  | 每层 1–2 间 | 每 3 层 1 次左右 |
| 10 层以后 | 每层 1–2 间 | 每层 0.5–1 次  |

### 2.4 F4 · 影（附身）飞出画面，远程也打不到

**现象**：影有时会飞到画面外面，远程攻击打不到，房间清不掉 → 卡关。

**定位（已复现）**

飞行怪的垂直速度**只在追击分支里写**，其余所有状态都只写水平速度：

| 状态    | 代码                                                   | 垂直速度   |
| ----- | ---------------------------------------------------- | ------ |
| 追击    | 战斗2D.js:14570 `setVelocityY(clamp(dy*1.7,-170,170))` | 会写     |
| 巡逻    | 14577 起，只 `setVelocityX`                             | **不写** |
| 前摇    | 14417 起，只 `setVelocityX(0)`                          | **不写** |
| 攻击/后摇 | 14409 起，只 `setVelocityX(0)`                          | **不写** |
| 受击硬直 | 14385 直接 `return` | **不写** |

而飞行怪 `setAllowGravity(false)`（9197）—— 没有重力，**残留的 vy 会永久生效**。

实测：给一只巡逻中的影设 `vy = -170`：

```
0.7s → y=340    1.3s → y=226    2.0s → y=113
2.7s → y=0（飞出屏幕上沿）   4.0s → y=-227
玩家走到它下面（dy=1220）→ 它继续飞到 y=-567，直到物理世界顶 -600 才停
```

**为什么回不来**：索敌判定要求 `|dy| < 240`（14495）。它一旦比玩家高 240px 以上，就永远进不了追击状态，只能继续巡逻 —— 而巡逻不会改 vy，所以它就永久停在画面外。

**改法（三件都做，成本很小）**

1. 非追击状态给飞行怪 `setVelocityY(0)`：巡逻 / 前摇 / 攻击 / 受击硬直 / 玩家死亡这五处。
2. 每帧夹取飞行怪位置：`y ∈ [hudSafeTop() + 20, groundY - 16]`，`x ∈ [40, levelWidth - 40]`。
3. 兜底：连续 2 秒不在相机可视区内 → 传送到玩家附近（左右随机 300px、地面上方 200px），带 0.4s 淡入，避免突然贴脸。

顺带把索敌的 `|dy| < 240` 放宽到 320 —— 否则玩家站在高台上时，飞在下面的影对他是"隐身"的。

**验收**：让影跟着玩家上双层上层再跳下来，20 次全部能重新追上来；房间里 5 分钟不出现"剩余敌人 1"却看不到怪的情况。

### 2.5 F5 · 镜像怪不复制远程攻击（一行 bug）

**现象**：玩远程英雄进镜像房，镜像怪照样贴脸挥砍。

**定位**：复制逻辑其实已经写好了 —— `mimicDef`（9269）会按 `heroRanged()` 把镜像怪改成 shooter（同弹道、射程 330、保持 200px），`spawnEnemy`（9182）也确实调用了。

问题是**之后又被盖回去了**：

```
8764:  var def = ENEMY_TYPES[key];                    // ← 原始表（近战 chaser）
8773:  var e = self.spawnEnemy(key, x, y, floor);      // e.def = mimicDef(…) = shooter ✓
8784:  e.def = Object.assign({}, def, { name: … });    // ← 用原始 def 覆盖，shooter 配置全丢
```

`def` 是原始表，不是 `e.def`。所以每次都被打回近战。

**改法**：`Object.assign({}, e.def, { name: '镜像·' + self.hero.name })`。

**验收**：远程英雄进镜像房，镜像怪保持约 200px 距离放同款弹道；近战英雄进镜像房仍是近战。

### 2.6 F6 · 遗物拿满后，裂隙的前两个选项只剩诅咒

**现状**

- 遗物**不可重复**（`relicChoices` 过滤已拥有的，经典2D.js:817），全表 27 件，面板显示"27 / 27 件"（战斗2D.js:11658）。拿满 = 池子抽干。
- 池子空时 `openRelicPanel` 直接 `return false`（经典2D.js:861），**静默放行**。
- 裂隙的两个选项是「先扣诅咒，再开遗物面板」（1539–1549），所以诅咒照扣、遗物没有。

结果就是：选「浅尝」白扣 1 条诅咒，选「沉沦」白扣 2 条诅咒（金币还在）。

**方案（已定：采用 ① + ②）**

**① 兜底换算 —— 采用（先做）**

- 池子空 → 遗物奖励自动折成「金币 = 层数 × 12」+「回复 15% 生命」，并在卡片上写明实际收益。
- 裂隙面板**在打开前**就检查池子，空则改写两个选项的描述（不能写"获得 1 件遗物"却给钱）。
- 这一条同时修掉"精英/层主必掉遗物"在池子空时静默失效的问题。

**② 遗物精炼 —— 采用**

池子抽干后，三选一改成「选一件已有遗物，效果 +50%（每件最多 2 层）」。

- 拿满不再是收益枯竭，而是进入第二阶段；
- 不用新资源、不用新界面，复用现有面板；
- 实现上 `setRelics` 现在是按 id 累加（14296），叠层要么允许重复 id、要么加 `relicStacks[id]`，注意保持"基准 + 增量"的口径（同文件 337 行的注释踩过这个坑）。

**③ 遗物重铸 —— 不采用**

（原备选：把一件已有遗物换成"随机另一件 + 随机诅咒"。② 已经解决了收益枯竭，再加一层赌狗机制会让"拿满之后"的选择过载。）

### 2.7 F7 · 近战/远程专属遗物混发

**事实**

| 遗物   | 效果                       | 对另一种英雄                |
| ---- | ------------------------ | --------------------- |
| 追踪符  | 远程普攻追踪 +50%、弹速 +10%      | 近战：**完全无效**           |
| 穿透之矢 | 远程普攻穿透 +1                | 近战：**完全无效**           |
| 重击   | 跳劈 +0.4、埋人 +12%          | 远程：**无效**（远程英雄没有跳劈）   |
| 连击大师 | 连招窗口 +250ms、第 3 段横扫 +50% | 远程：**无效**（远程是连射，没有横扫） |

而 `relicChoices` 只按"已拥有 / 自定义黑名单"过滤（817–823），完全不看英雄攻击方式。

**方案（已定：采用 B —— 效果和名字都改）**

同一个 id 保留（存档、图鉴、去重都按 id 走），但**名字、描述、效果、图标**按英雄攻击方式切换。**不使用"原名 + 括号"的写法。**

| id              | 近战版      | 效果                           | 远程版      | 效果                     |
| --------------- | -------- | ---------------------------- | -------- | ---------------------- |
| `trackingCharm` | **觅隙**   | 挥砍自动朝最近敌人偏转 12°，判定宽度 +6px    | **追踪符**  | 追踪 +50%、弹速 +10%（原样）    |
| `piercingArrow` | **裂阵**   | 第 3 段横扫可多命中 1 个目标            | **穿透之矢** | 穿透 +1（原样）              |
| `heavyStrike`   | **重击**   | 跳劈 +0.4、埋人 +12%（原样）          | **坠星**   | 空中射击伤害 +0.4、命中溅射 40px  |
| `chainMaster`   | **连击大师** | 连招窗口 +250ms、第 3 段横扫 +50%（原样） | **连珠**   | 连射间隔 −12%、第 3 发伤害 +50% |

命名口径：两个字，动词/意象为主，和现有「追踪符 / 穿透之矢 / 轻盈之靴」同一层级的语感，不出现"近战版/远程版"字样。

**实现**

- `RELIC_FX[id]` 从单份改成 `{ melee: {...}, ranged: {...} }`；
- `setRelics` 按 `heroRanged()` 取对应那份（同一件遗物不会同时生效两份）；
- 名字/描述同理，按 `heroRanged()` 解析；
- 图标 `relicVis(id, weapon)` 按武器取图。

**美术：impeccable** —— 只需新画 4 张 16×16 图标（觅隙 / 裂阵 / 坠星 / 连珠），另外 4 张（追踪符 / 穿透之矢 / 重击 / 连击大师）沿用现有图标。区分方式：近战版加「刃/斜线」元素，远程版加「弧/箭」元素，外环颜色沿用流派色，靠形状区分。

**必须配套**：图鉴和商店按当前英雄显示对应名字与效果；图鉴列表可以两套都列（「觅隙 / 追踪符」），让玩家知道这件遗物换个英雄会变。

### 2.8 F8 · 轻盈之靴的「体力上限 +30」没生效

**结论：是真没加，不是显示问题。**

```
322:  RELIC_FX.lightBoots = { stamMax: 30, stamRegen: 0.30 }
344:  applyMechRelics(): STAMINA.max = MECH_BASE.staminaMax + num('stamMax')   ← 130 ✓
2677: this.hero.maxStamina = STAMINA.max;    ← 只在建号时赋一次
14302: setRelics() → applyMechRelics()       ← 没有同步 hero.maxStamina ✗
```

HUD 读的是 `hero.maxStamina`（5432 的"体力 x"、6717 的属性面板"体力 x / y"），所以永远显示 100；实际可用上限也是 100（恢复逻辑 `Math.min(h.maxStamina, …)`）。

**改法**：`applyMechRelics()` 之后同步一次上限，并处理"去掉遗物"的回退：

```
if (this.hero) {
  this.hero.maxStamina = STAMINA.max;
  this.hero.stamina = Math.min(this.hero.stamina, this.hero.maxStamina);   // 掉上限时当前值不能超
}
```

**同类隐患自查**：连携上限（`LINK.max`）是每次现读的（10768 / 10926），没有这个问题；只有"建号时复制一次"的字段才需要检查 —— 目前只发现 `maxStamina` 一个。

## 3. 守点重做：守住核心

### 3.1 为什么现在没压力

```
13517:  need = 8000ms，站进圈里累计 8 秒就开门
13527:  maxEnemies = 4，每 3000ms 补 1 只
13507:  圈优先放在"合格里最高的平台"（okPerches.sort → spot = okPerches[0]）
```


三个问题叠加：

1. **8 秒太短** —— 站着不动也就过去了；
2. **补怪太慢**（3 秒 1 只，上限 4 只），清怪速度远高于刷新速度；
3. **圈放最高平台** —— 近战怪爬不上来，玩家在圈里"发呆"即可。虽然有 35% 概率出远程（13577），但远程也是从地面刷的，站位一换就打不着。

### 3.2 新规则：核心 + 尸潮

在圈心生成一个**核心**，尸潮从两侧涌入并**优先攻击核心**；玩家在限定时间内保住核心即算守住，**按核心剩余血量发奖**。

| 难度 | 每波数量 | 同屏上限 | 波数 | 袭击时长 | 核心血量       |
| -- | ---- | ---- | -- | ---- | ---------- |
| 简单 | 5    | 4    | 3  | 14s  | 80 + 层数×2  |
| 普通 | 7    | 6    | 3  | 16s  | 100 + 层数×2 |
| 困难 | 10   | 8    | 3  | 18s  | 125 + 层数×2 |
| 地狱 | 15   | 10   | 3  | 20s  | 150 + 层数×2 |

> 血量只随层数**线性小涨**，怪物对核心的伤害才随层数放大（见 3.3），这样"清怪"的价值会随层数上升 —— 否则高层的核心会变成一块打不碎的铁板。难度是**两个轴一起涨**（血量 ↑ + 单次伤害 ↑）：只涨血量的话，地狱的血厚核心反而比普通更耐打，难度就倒挂了。

- 原来的「站圈累计 8 秒」变成「袭击持续 16 秒」（普通）：**时间到就结束，不看你站了多久**。
- 圈不再是目标，而是**护罩范围**（见 3.3）：站在圈里，核心受伤减半。
- 波次按袭击时间轴推进（0% / 25% / 50%），后 1/3 是「怪全到位」的清扫期。
- 就地文字从「守点 · 0.0/8s」改成「袭击 16s · 核心 100%」；HUD 上那行「剩余敌人」保持不动（**不新增 HUD 元素**）。

### 3.3 核心

**美术：impeccable** —— 这是全新对象，需要 4 个状态 + 血条 + 护罩圈。

| 项    | 值                                                                              | 说明                        |
| ---- | ------------------------------------------------------------------------------ | ------------------------- |
| 血量   | 见 3.2 表                                                                        | 随层数与难度增长                  |
| 位置   | 圈心，选址规则见 3.5（地面段 > 中低平台 > 高台）                                                  | 圈就是护罩范围，核心必须在圈心           |
| 受击 | 普通怪 −6 / 精英 −9 / 远程 −4，× 难度系数（简单 0.85 / 普通 1 / 困难 1.25 / 地狱 1.5）× `(1 + 层数 × 0.03)` | 只有被打中才掉血；同一核心 0.3s 内最多结算 1 次，防一帧多段 |
| 护罩   | 玩家在圈内 → 受伤 ×0.5；圈外 → ×1                                                        | 圈的唯一作用，也是"待在圈里"的理由        |
| 掉血速度 | 核心**不会自己掉血**，只有被打中才掉。0.3s 结算间隔把 DPS 压到约 26（普通 10 层）；血量与单次伤害随难度一起涨，四个难度都是**持续挨打 4.4–4.6 秒碎**，加上走到位 3–5 秒 → **第 8–10 秒** | 挂机的人拖不到 16 秒结束，中途就看着核心碎 |
| 血条   | 就地显示（核心上方 14px，宽 64）                                                           | **不进 HUD**，不新增 HUD 元素     |
| 状态   | 完好（100–70%）/ 受损（70–35%，裂纹）/ 濒碎（<35%，红闪+抖动）/ 碎裂                                 | 4 张图                      |

核心不是"要打的东西"，是"要保的东西" —— 所以它不还手、不移动、不可被玩家攻击。

### 3.4 敌人 AI：围攻核心

| 项      | 规则                                                |
| ------ | ------------------------------------------------- |
| 目标优先级  | 核心（默认）→ 玩家（被玩家打中后 1.5s 内转火）                       |
| 近战怪    | 靠近核心 56px 进入攻击前摇；前摇沿用现有 `windup`（**≥200ms 红线不动**） |
| 远程怪    | 站 260–340px 外朝核心射击；弹道不做格挡                         |
| 飞行怪（影） | 无视地形直扑核心 —— 正好用上 F4 的修复，否则它会飞走                    |
| 清怪的意义  | 不是"清完才开门"，而是"少一只怪 = 核心少挨一下"                       |

"打怪会拉仇恨"是这套玩法的核心手感：玩家可以站在核心前面把怪拉住，也可以放风筝清场 —— 两条路都成立。

### 3.5 圈的位置（这条是"发呆"的根因）

现在的优先级是"合格里取最高"，要反过来：

1. **地面段**（非缺口、离出口 ≥ 300px）
2. **中低平台**（`y ≥ groundY − 160`）
3. **高台**（仅当前两种都放不下）→ 此时**强制**本波至少 2 只远程 + 1 只飞行

因为圈=护罩范围，圈放在怪爬不上的高台上，护罩就等于白给 —— 这是必须改的。

顺带修一个已知问题：圈、核心、血条、文字都要压在 `hudSafeTop()` 以下（矮屏会顶进 HUD，见 2.9 改进建议 §2.8）。

### 3.6 波次与刷怪

| 项      | 规则                                                                       |
| ------ | ------------------------------------------------------------------------ |
| 波次触发   | 袭击进度 0% / 25% / 50% 各一波，时间轴推进，不看玩家状态                                     |
| 同屏上限   | 见 3.2 表；超出的排队，每 0.35s 补一只（"涌进来"比"一次刷满"更有压迫感）                             |
| 上一波没清完 | **下一波照刷**（压力叠加），但始终受同屏上限约束                                               |
| 位置     | 距核心 260–520px，左右交替；≥ 圈半径 + 80px（不刷在圈里贴脸）                                 |
| 地形     | 不落在坑/缺口上方；地面怪从 `groundY − 100` 落下（复用 `adjustSpawnX` / `isOverGap`）       |
| 种类     | 本波内洗牌取不重复；种类数不够时保证相邻两只不同                                                 |
| 远程占比   | 每波至少 2 只（死灵 / 织网）                                                        |
| 飞行     | 第 6 层起每波 1–2 只影                                                          |
| 常规刷怪   | 守点房沿用 `node.noEnemies = true`（现在就是这样），场上的怪**全部由核心逻辑刷**，不走 `spawnEnemies` |
| 圈的场地要求 | 圈所在的地面段宽度必须 ≥ 2×半径 + 80（断桥的碎段可能不够）→ 不够就换段，全部不够则这一间退回平厅                   |

> 注意：原来的"上一波没清完 → 圈内计时减速 50%"要**删掉**。现在计时就是袭击时长，减速等于给玩家送时间；压力应该来自核心掉血，不是来自计时器。

### 3.7 结算：按核心血量发奖

| 核心剩余    | 结果   | 金币       | 额外             |
| ------- | ---- | -------- | -------------- |
| 80–100% | 完美守住 | 基础 × 1.5 | 1 颗深渊魂晶        |
| 50–79%  | 守住   | 基础 × 1.0 | 30% 概率 1 颗深渊魂晶 |
| 1–49%   | 惨胜   | 基础 × 0.6 | 无              |
| 0（碎）    | 失守   | 无        | 无              |

基础金币沿用现在的公式（`10 + 层数 × 2`，满血再 +10 的逻辑并入倍率，不重复计算）。

**这一间怎么算结束**：不是「清场」，而是「撑到袭击结束」。三个出口，对应三种结果：

| 出口        | 结果          | 处理                  |
| --------- | ----------- | ------------------- |
| **袭击时间到** | **成功（主路径）** | 按此刻核心剩余血量结算发奖 → 开门  |
| 核心碎       | 失败          | 无奖励 → 开门            |
| 最后一波被清光   | 提前成功        | 按此刻血量结算（通常档位更高）→ 开门 |

**为什么「时间到」就是成功，而不是要求清完怪**：守点的目标定义就是「撑过这段时间」，这是它和普通战斗房的区别。如果要求清完才能过，守点就退化成「清怪房 + 一个圈」，而且最后一波刚好卡在时间点刷出来时，会出现「时间到了却还得打完」的别扭。

两个执行细节：

- **时间到的那一帧立刻冻结核心受伤**，避免「最后一帧被补刀」把档位从 80% 打到 79%。
- 时间到要有明确的收场表现（怪撤退 / 消散 + 音效 + `showCenter('袭击结束 · 核心 84%')`），否则玩家会觉得自己赢得莫名其妙。

提前清完不用额外发奖 —— **少挨的那几秒本身就是奖励**（核心血量更高、档位更高）。场上残留的怪不阻止开门（它们只是「没清掉」，不影响奖励，也不会追出门外）。

### 3.8 失守不卡关（替代原 3.5 第 5 点）

原第 5 点写的是"失败不是死：玩家血量归零照常结算，不要额外惩罚"。改成核心之后，**"失败"这个词要重新定义**：

- **核心碎 ≠ 玩家死**：核心碎 → 立刻结束袭击、门打开、没有奖励；已刷出的怪不再补，玩家可以清完再走，也可以直接走。
- **玩家血量归零** → 正常死亡结算，和核心无关（核心满血也不会救你）。
- **绝不因为核心碎而卡关**：门一定开。守点的失败方式只有"少拿奖励"，没有"打不过去"。

### 3.9 我补的几条

1. **护罩收缩**：袭击后半段（60% 进度起）护罩半径缩小 20%，后期必须贴着核心打。
2. **高血量档位奖励**：由 3.7 的 80% 以上倍率承担，不再单独发「满血奖」。
3. **守住后回复 10% 生命**：避免"守完残血直接进下一房"。
4. **波次预警 + 核心受击反馈**：每波前 0.8 秒圈边闪 3 下 + 屏幕两侧裂纹 + 音效 + `showCenter('第 2 波 · 7 只')`；核心掉血时屏幕边缘红闪一下、核心上方飘伤害数字。（**美术：impeccable** —— 圈边闪烁帧、屏幕两侧裂纹）
5. **挂机惩罚**：每 3 秒判定一次 —— 这 3 秒内**没有任何玩家操作**，就扣 1% 最大生命（最低留 1 点，不致死），**扣血同一刻**在英雄头顶弹灰字「请积极守护核心」（复用 `showFloat(x, y-104, …, '#8a9aa8', 13)`，和铁壁兵「绕后或用跳劈」同一种样式）。只要还在挂机，每 3 秒重复一次；一有操作立刻停。
   - **判定读输入层，不读位移**：移动、跳跃、攻击、技能、闪避、格挡、喝药、交互，任意一项有输入就算"在操作"。
   - 所以原地攻击、原地喝药、原地放技能**都不算挂机** —— 只有真的什么都没按（或设备没输入）才会被扣。
6. 原第 5 点「失败不是死」→ 已并入 3.8，并扩展成「失守不卡关」。

### 3.10 验收

| 项     | 标准                                                                              |
| ----- | ------------------------------------------------------------------------------- |
| 挂机（无任何操作） | 连续 3 秒没有任何输入（移动 / 攻击 / 技能 / 闪避 / 格挡 / 喝药 / 交互）→ 扣 1% 最大生命（不致死，最低留 1 点）+ 同时弹灰字「请积极守护核心」；之后每 3 秒重复，一有操作就停。原地攻击 / 喝药 / 放技能不算挂机。核心约在第 8–10 秒碎 → 无奖励、门照开 |
| 只打不站圈 | 核心撑到 50–70%（护罩重要但不必须）                                                           |
| 站圈且清怪 | 核心 80% 以上，拿到魂晶                                                                  |
| 核心碎   | 门仍开，不卡关，无奖励                                                                     |
| 同屏数量  | 任何难度不超过上限，帧率不掉                                                                  |
| 飞行怪   | 影不会飞出画面（依赖 F4 修复）                                                               |

## 4. 断桥重做

### 4.1 现在的问题

"地上挖两个坑"—— 视觉上像 bug（地面缺一段），玩法上只有一个动作（跳过去）。它目前是三种骨架里信息量最低的一种。

### 4.2 视觉：让它真的像一座"断掉的桥"

**美术：impeccable** —— 断面、缺口雾气、桥墩、残板、落点裂纹，全部是新增资源。

| 元素   | 做法                                    |
| ---- | ------------------------------------- |
| 断面   | 锯齿状断口 + 露出的钢筋/木梁（和现有 TEX 风格一致）        |
| 缺口下方 | 深渊渐隐（纯黑 → 透明）+ 缓慢上升的雾气粒子              |
| 缺口边缘 | 碎砖 / 裂纹贴花；落点一侧加"撞击裂纹"（暗示有人跳过）         |
| 桥面   | 每隔 256px 一道暗色"桥墩"竖纹，让"这是一座桥"成立        |
| 落差   | 三段桥面允许 ±40px 的高度差（现在是全平）—— 有落差的断桥才像断桥 |

**最重要的一条**：缺口下方必须有"深"的感觉。现在的坑是"地面少了一块"，看起来像贴图没加载；加上渐隐和雾气之后，玩家才知道"下面是空的、掉下去会死"。

### 4.3 玩法：四个可选加料（按成本排序，建议先做 ①②）

**① 对岸射手（成本最低，收益最高）**

缺口另一侧固定 1 只远程怪（死灵法师 / 骷髅骑兵），玩家不过去就一直射。

- 缺口从"地形"变成"战术点"：先远程点掉，或者顶着火力跳；
- 复用 `spawnEnemy` + 平台摆位（`platformPerches`），几乎零新代码；
- 掉落传送到"坑右侧最近安全块"时，正好落在它面前 —— 有戏剧性。

**② 落石（中等成本）**

缺口上方周期性落石：0.6 秒阴影预警 → 落下 → 砸中扣血 + 小硬直。

- 逼玩家"卡时机跳"，而不是"随时跳"；
- 落石只在玩家进入缺口前后 300px 时触发，不做全场随机；
- 必须可闪（阴影 + 音效），否则是抽奖。

**③ 残板（中等成本）**

缺口中央一块悬空残板，站上去 0.8 秒后掉落。

- 既是中继点（缺口太宽时的救命板），也是陷阱（站着不动会掉）；
- 视觉上是"断桥剩下的半块桥板"，正好服务 4.2 的叙事。

**④ 上升气流（高成本，可选）**

掉进缺口不扣血，被气流吹回桥面并滞空 1 秒。

- 把"惩罚"换成"节奏打断"，适合低难度；
- 但会削弱"断桥=危险"的认知，建议只在简单难度开。

### 4.4 缺口宽度分层

| 层段          | 缺口宽度             | 要求                 |
| ----------- | ---------------- | ------------------ |
| 6–10 层（现状）  | **固定 128px**     | 轻点跳即可（轻点射程约 153px） |
| 11–15 层（建议） | 128–160px        | 需要蓄力跳              |
| 16 层以后（建议）  | 160px + 允许 2 处缺口 | 蓄力 + 选路线           |

现在缺口宽度是写死的 128（战斗2D.js:8185 `var wGap = 128`），所有层一样；第 8 层起有 40% 概率变 2 处（8176）。**后期断桥等于没有难度** —— 同一道题从第 6 层做到第 99 层。

### 4.5 断桥 + 塌陷

已在《塌陷机制-多骨架方案》里定案：**缺口就是"初始已塌"的块**，剩余桥面按缺口切分继续塌。这里不重复，注意两条约束即可：

- 挂塌陷时缺口固定 1 处；
- 掉落传送到"坑右侧最近的安全块"，不能直接用"前沿 + 1"（天然缺口在未塌区域，前沿可能还在缺口左侧，会把人往回送）。

## 5. 预览页的判据要改

### 5.1 你的判断是对的

预览页现在写死的健康区间是：**平均 20–35s · 强制解锁 <20% · 掉落率 20%–50% · 平均收集 3.5–4.5 · 读条被打断 1–3 次**。

一批数据（16 局，普通难度、默认参数）套进这套判据：

| 指标      | 实测                  | 预览页判据   | 预览页给的结果                 |
| ------- | ------------------- | ------- | ----------------------- |
| 平均通关时间  | **14.2s**（9.8–29.8） | 20–35s  | ⚠ 「节奏偏快：放慢塌陷或加长房间」      |
| 平均收集    | 3.0 / 需求 3          | 3.5–4.5 | ⚠ 「钥匙够不到：调整地面钥匙位置或读条时长」 |
| 掉落率     | 18.8%               | 20%–50% | 低于下限（但这个下限本身偏高，见 5.3）   |
| 强制解锁率   | 0%                  | <20%    | ✓                       |
| 读条被打断   | 0.63 次              | 1–3 次   | 略低于下限                   |
| 开门时剩余段数 | **5.1 / 8 段**       | **未统计** | —                       |

两条 ⚠ 都是误报，而且第二条的措辞会把人带偏：收集 3.0 = **刚好拿满需求**，说明钥匙"拿得到、只是不贪"，不是"够不到"。按它去调钥匙位置，只会让房间更松。

### 5.2 为什么"通关时间"不是好指标

玩家拿到 3 颗钥匙就开门，而钥匙是"地上 3 颗 + 空中 2 颗"固定投放。所以通关时间 ≈ 跑图时间 + 3×读条时间，**跟塌陷压力基本无关** —— 只要钥匙在前半段，玩家就一定在 15 秒内走人，无论塌陷调多慢。

反推一下：8 段、相邻两块间隔 4.8 秒（4.0 间隔 + 0.8 预警）、首块预警 0.9 秒 → 第 3 块塌完约 11.3 秒。实测 14.2 秒、开门时还剩 5.1 段 —— 也就是说**玩家平均只等 3 段就走了**（11.3 秒塌 3 段，剩下 3 秒跑图 + 读条），塌陷全程只是背景音乐。

这也解释了为什么你觉得"十几秒通关轻轻松松"：因为**它本来就是这么设计的**，默认参数没问题，是判据选错了指标。

### 5.3 建议的新判据

| 指标                 | 现在      | 建议                | 说明                                |
| ------------------ | ------- | ----------------- | --------------------------------- |
| 通关时间               | 20–35s  | 10–25s（P90 < 35s） | 熟练玩家 10–15s 正常，不再当异常              |

### 9.2 批次 2：F1 视觉区分（方案 A）

**结论先说**：双层骨架房间里**没有单向浮台**（`buildDoubleSkeleton` 只调 `spawnDeckSegment`），

| 挂机 | 每 3s 判一次：这 3 秒没有任何输入 → 扣 1% 最大生命（最低留 1 点）+ 头顶灰字「请积极守护核心」。判据读**输入层**（键位 + 触屏 + 指针 + 按键时间戳），不读位移 | `inputActiveNow()`、`checkHoldIdle()` |

**验收**（`测试/P4机制验证.html`，守点段 25 项，全绿）：

- 挂机没有任何输入 → 扣 1% 且不致死；离开圈内计时照走；
- 只打不站圈 / 站圈且清怪 → 由护罩系数直接体现（圈内 ×0.5，实测 13 vs 26）；
- 核心碎 → 门仍开、`holdFailed` 落进快照、宿主不弹三选一；
- 同屏数量不超上限；影不飞出画面（依赖 F4 修复，P4 里 109 项覆盖）。

**偏离与补充（都记在这里，避免以后当成 bug 改回去）**：

1. **落石式"小硬直"没做**：§4.3 ② 只实现了"阴影预警 → 落下 → 扣血 + 镜头震动"。英雄本体的硬直状态机不在这一批的范围里，硬塞会导致"被砸时连闪避都按不出来"。**这是本批唯一没按原文做到的一条，需要你拍板是否要补。**
2. 波次预警音效复用既有的 `holdStart`，没有新音效（音频资源不在本批范围）。
3. 袭击结束后场上残留的怪不消失、不追出门 —— 与 §3.8「残留的怪不阻止开门」一致。

**两处按工程约束偏离原文，都记在这里**：

1. **缺口宽度取 192 而不是 160**：地面碰撞按 64 格复用，非 64 对齐的边界会出现"看得见坑、踩得着地"（这个 bug 2.9 已经踩过一次）。192 就是 3 格，效果与"要蓄力跳"一致。

### 11.5 批次 7：预览页判据（§5.3）

`其他/塌陷回廊预览.html` 的判据表按 §5.3 全量替换，并补了两项原来没有的统计：

提示语同步重写：两条"必须改"的（剩余段 >6 / <2）排在最前，其余按 强制解锁 → 多拿率 → 节奏 → 压力 → 怪 的顺序取前两条。
另外：`平均收集 3.5–4.5` 这一项取消判据（收集 3.0 = 刚好拿满需求，不是"够不到"，原来的提示语会把人带偏 —— 这正是反馈 §5.1 指出的第二条误报）。

**再打 20 局**（`测试/2.9.2预览判据校准.html`：自动机器人，直冲钥匙 → 够 3 颗就走门）：

```
掉落率        0%        ⚠ 低于 10%
多拿率        0%        ⚠

```

**结论与我不动参数的理由**：这套数字说明"**直冲型玩家**在默认参数下确实没有压力"（§5.2 的判断成立），
而你自己那批 16 局实测是 5.1 段 / 14.2s —— 正好落在新判据的健康区间里。
两者的差别不是参数，是**打法**：机器人不绕路、空中钥匙瞬收、从不贪第 4 颗。
所以我把判据改对了、把数据摆出来了，但**没有**去动钥匙位置或塌陷间隔 —— 按机器人校准会把正常玩家推进"太赶"那一档。
真正的杠杆写在提示语里：**把钥匙放到房间后半段**（一步就能改，等你实测后要不要动由你定）。
