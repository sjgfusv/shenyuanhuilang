## 0. 本规划的定位（先看这节）

### 0.1 这是新立项，不是旧规划的延续
上一轮会话日志考古的结论很明确：

- 《其他/试炼模式2D改造规划.md》（45KB）**从头到尾没有一条"与经典模式联动"的需求**，只写了"退出试炼恢复经典模式状态"。
- 上一轮实际交付的是**「深渊回响」**（试炼产出按 `点数 × 2 × 层数倍率` 折算金币回流经典，方向 A）。
- 当时诊断出的另外 4 个方向 **B 表现统一 / C 内容统一 / D 流程缝合 / E 元进度统一**，AI 明确记录"一个都没动"。

**→ 2.7 的"合并试炼进经典"实质是 B+C+D+E 的同时落地。** 也意味着它会在新版里**取代**深渊回响的角色（新版只有一个模式，不存在"两模式回流"）。

### 0.2 与历史红线的核对（这些不能违反）
| 历史约束 | 出处 | 2.7 的处理 |
|---|---|---|
| 只有 2D 场景强制横屏，其余界面不强制 | 用户原话 | 新版整个游戏主体就是 2D → 进入新版锁横屏；**返回开始界面 / 切老版时解锁**，与红线一致 |
| 「下落攻击把敌人砸进地里」是可保留特性，不许当 bug 修掉 | 用户原话 | 原样保留（`试炼2D.js:63-65` buryChance/buryTime/burySquash） |
| 不接受"回退文字界面"作为兜底 | 用户两次明确（华为机 / 苹果机） | 降级链必须真进 2D（现有 4 条渲染路径保留）；文字界面在新版**彻底移除**，不新增文字兜底 |
| 浏览器无法真正强制旋转，唯一路径是全屏 + `screen.orientation.lock`，iOS Safari 完全不支持 | 既有结论 | 沿用现有实现与提示条兜底，不承诺 iOS 自动横屏 |
| 遗物"要重新设计"（用户本次要求） | 本次 | 见 §3.4，逐条重做并给旧名映射表 |

## 1. 目标与不变量

### 1.1 五条目标
1. **经典模式全面 2D 实时化**：战斗由回合制改为 2D 实时动作（与现 2D 试炼同款玩法），楼层/房间/经济/结局/难度等经典系统保留。
2. **试炼并入经典**：诅咒、遗物、英雄技能、环境效果等资产并入主线；**试炼模式在新版关停**（仅老版可玩）。
3. **老版冻结**：现行 2.6（修完相机问题后）作为"老版"完整保留；侧边栏可切换，默认新版。
4. **新版风格**：以现 2D 试炼视觉为基准，界面设计调用 `impeccable` 技能统一。
5. **移动端**：新版强制横屏（沿用现有机制）；老版行为不变。

### 1.2 不变量（不允许在这些地方回退）
- **老版永远可玩**：切过去就是一个能跑完的 2.6，不依赖新版任何改动。
- **旧存档不丢**：旧档能被新版读入；老版的进度原样可见。
- **作弊 / 开发者模式 / 图鉴 / 音频 / 存档管理**在切换后都还能用。
- **降级链不断**：WebGL 失败 → Canvas → 兼容模式（`试炼2D.js:8652-8657` 四条路径），不进文字界面。

### 2.2 2D 引擎是"可插拔前端"，这是最大的利好
`window.试炼2D` / `Trial2D` API（`试炼2D.js:8575-8894`）与宿主之间的契约是干净的：

| 方向 | 接口 | 位置 |
|---|---|---|
| 宿主 → 引擎（注册） | `setBridge({ exit(result), toggleView(snapshot), shopData(points), shopBuy(id, points) })` | 8604 |
| 宿主 → 引擎（开局） | `startRun({ heroName, points, player, difficulty, skill, heroId, curses, environment })` | 8716 / 2990 |
| 宿主 → 引擎（运行中） | `syncPlayer / setSkill / setCursesEnv / setPoints / openShop / openCodex / fillFury / stopRun / pauseRun / resumeRun` | 8727-8810 |
| 宿主 → 引擎（布局） | `show / hide / init(container, force) / getGame / getQuality / setSettings / debug()` | 8586-8712 |
| 引擎 → 宿主（事件） | `game.events.emit('trial2d:floor' / 'trial2d:room' / 'trial2d:run-ended')` | 7863 / 8098 / 3134 |
| 引擎 → 宿主（收尾） | `bridge.exit({ reason, floor, points, hp, maxHp, kills, rooms, elapsed })` | 3121-3133 |

**`debug()`（8812-8894）会一次吐出房间/敌人/HUD/地图/商店/血条/坐标的完整内部状态** → 这是 2.7 做自动化回归的现成抓手。

### 2.5 横屏/全屏机制的完整位置
`试炼程序.js:1400-1552`：`_requestLandscapeLock()`（全屏 + `orientation.lock('landscape')`，必须在用户手势内）→ `_updateRotateHint()`（仅"触摸设备 + 竖屏 + 2D 战斗中"显示提示条，iOS 走"请旋转手机横屏"文案）→ `_relockLandscapeFromGesture()`（全屏被系统弹窗顶掉后点屏幕自愈）→ `_exitLandscapeMode()`（退出时解锁 + 退全屏）。

### 3.4 遗物重做（局内 Roguelike · 效果全部挂在**现成机制**上）
**设计原则**
1. 每条遗物必须挂在一个**已存在的实时机制**上（能被玩家看见、能被 `debug()` 断言），拒绝"攻击 +2"这类无声效果。
2. 数值用**百分比或机制开关**，不用绝对值（避免随层数膨胀失效）。
3. 品质三档沿用现有 `common/rare/legendary` 与自定义难度的权重/黑名单系统（`getRandomRelicByRarity` 6587）。
4. 产出：精英房必掉、Boss 房必掉、宝箱概率、祭坛献祭、商店购买。
5. 获取形式：清房后 **3 选 1** 面板（2D 画内），可跳过换取金币。

> ⚠️ 前置依赖：引擎**目前没有遗物承载点**，必须先在 P1 落地 §3.11 第 3/5 条（三选一面板 + `setRelics` + 3 个钩子），上面 24 条效果才可能真正生效。

### 3.5 诅咒重做（风险收益 · 玩家主动选择）

### 3.12 脉冲节拍（替代回合上限的压力旋钮 · 已定）
**为什么要它**：回合上限原本承担"防止玩家在一个房间里无限苟着不推进"的职责。取消上限后，用**脉冲节拍**（`PULSE`，`试炼2D.js:202`）承接这个职责——它只调"每 5 秒结算一次诅咒/环境"的**频率**，**不改敌人数值、不新增伤害来源**，因此与诅咒系统不重叠、不动平衡。

**公式**
```
interval = clamp( 基准(难度) − (层数−1)×50 − 本层已清房间数×步长(难度), 下限(难度), 基准(难度) )
warn     = min(1500, interval × 0.30)      // 预警窗口同步缩放
```

| 难度 | 基准 | 每房加速 | 下限 | 典型手感（清 6 房后） |
|---|---|---|---|---|
| 简单 | 6000ms | 250ms | 3200ms | 6.0s → 4.5s |
| 普通 | 5000ms | 350ms | 2600ms | 5.0s → 2.9s |
| 困难 | 4400ms | 450ms | 2200ms | 4.4s → 2.2s |
| 地狱 | 3800ms | 550ms | 1800ms | 3.8s → 1.8s |
| 自定义 | 基准 × `pulseScale` | 步长 × `pulseAccel` | 下限 × `pulseScale` | 可关（`pulseAccel = 0` 即固定间隔） |

**自定义难度新增两项**（并入现有 30 项体系，`DEFAULT_CUSTOM_DIFFICULTY` 3086-3120）
- `pulseScale`：脉冲间隔倍率，钳 0.5–2.0，默认 1.0（越高越慢 = 越轻松）
- `pulseAccel`：加速强度倍率，钳 0–2.0，默认 1.0（**0 = 完全关闭加速**，纯固定间隔）
- 悬浮说明写进 `CUSTOM_DIFFICULTY_HELP`（4109-4141）；面板输入项并入 `bindCustomDifficultyInputs()`（4144-4438）

**HUD**：右上角环境/诅咒列（`layoutEnvHud` 6805）已有脉冲倒计时（1433），它旁边常驻显示**当前间隔**（如「脉冲 3.4s」），让"压力在变快"这件事被玩家看见。

**与既有机制的关系（避免混淆，UI 文案必须分清）**
| 名称 | 是什么 | 归属 |
|---|---|---|
| **诅咒** | 玩家在「深渊裂隙」主动选择承受的负面效果（10 条） | §3.5 新增系统 |
| **腐化脉冲** | 让"每回合"类诅咒/环境到点生效的节拍器 | 引擎已有，本次改为可配置频率 |
| **深渊侵蚀** | 每层固定 −3 生命 | 引擎已有（`nextFloor` 7857） |

| 真因 | 证据 | 修法 |
|---|---|---|
| **① 关卡按旧画布高度铺好后画布又变了尺寸** | 手机读数：`画布 800×334` 但 `地面y 554`（554+96=650）→ 进试炼时先按 650 高建好关卡，随后画布缩到 334（全屏/地址栏让位），而 `groundY`/平台/相机边界**只在建关卡时算一次** → 地面被永久留在屏幕外 | `buildLevel` 记 `_builtH`；`onResize` 里**高度差 >24px 就按新尺寸重建当前房间**（重建不会回调 onResize，无递归；**不能 return**，后面还有面板重排与 `applyCustomLayout`，否则一改尺寸玩家自定义布局就丢） |

```
dz             = clamp(60, H×0.45, bandBottomMax − bandTop)
offY           = bandTop − (H/2 − dz/2)
```

## 9. 补充改动：选英雄 / 选增益搬进 2D 画面

**为什么**：2.7 最初把 `heroSelect` / `bonusSelect` 留给内核 DOM（`shouldTakeOver()` 里显式返回 false）。
结果是"点开始游戏 → 先看到一张文字按钮列表"，玩家会以为 2D 没生效 —— 实测反馈就是这么来的
（`{mode:"heroSelect", hero:false}` 停在 DOM 选人界面）。这两个界面属于游戏内流程，应该和房间内一样由画布承担。

**改法（能力层 → 宿主层）**

| 层 | 文件 | 改动 |
|---|---|---|
| 表现 | `战斗2D.js` | 卡片上限 6 → **12**；`buildChoiceLayer` 由"一行铺满"改为**每行最多 5 张、超了换行**，且**每行各自居中**（9 位英雄 = 5 + 4，左对齐会缺一块） |
| 内核 | `主程序.js` | `window.经典2D内核` 增加 `chooseHero` / `chooseBonus` / `getBonusChoices`（"选了谁"只有一个真相来源，宿主不另存一份） |
| 宿主 | `经典2D.js` | `shouldTakeOver()` 接入 `heroSelect` / `bonusSelect`；新增 `openHeroPanel` / `openBonusPanel`；`onChoiceResult` 加 `hero` / `bonus` 分支回写内核；抽出 `ensureBooted()`（只 init 不开局） |

**两个必须知道的坑（都已修）**

1. **空画布**：引擎是在某一次 `render()` 里才 init 的，而 Phaser 的场景要**下一帧**才 create ——
   在那一帧内 `state.scene` 还是 null，`openChoicePanel` 静默返回 false，而 `render()` 已经返回 true
   吞掉了这次 DOM 渲染。实测复现：点开始游戏 → `{mode:'heroSelect', booted:true, engineReady:false, choiceOpen:false}`，
   画布全屏但什么都没有（在这个宿主里因为标签在后台，场景要 1 秒后才就绪，问题被放大到必现）。
   修法：面板没开出来时 `schedulePanelRetry()` 每 120ms 补一次 `render()`，开出来就停；~5 秒仍开不出来才 `giveUp()` 回退文字界面。
2. **重试链会误开局**：`scheduleRetry` 的定时器原来无条件调 `startRun`，在选人阶段会把引擎开成一局**自造地图**。
   修法：定时器按 mode 分流 —— 选人 / 选增益阶段只 `ensureBooted()`，不 `startRun`。

**实测证据（真实浏览器，非推断）**

- 全新一局：清空存档 → 点开始游戏 → `mode=heroSelect` → 画布接管 → 轮询补开后
  `choiceOpen:true, choiceKind:'hero', cards:['0'…'8']`（9 位全在）
- 点第 1 张卡（走 `press('clickChoice',0)` 的真实命中路径）→ `chooseHero(0)` + `render()` →
  `mode=bonusSelect, hero=战士` → 画内弹出 3 张增益
- 点第 1 张增益 → `chooseBonus(0)` + `enterCurrentRoom()` → `room=shrine` → 下一帧 `render()` →
  `startRun` → `mode=classic2d, running=true, engine.floor=1, hero 28/28`
- 尺寸：用 `buildChoiceLayer(W,H)` 直接量卡片矩形（`fits` = 全部落在画布内）

| 画布 | 9 张卡 | 卡片尺寸 | 两行起始 x | 包围盒 | fits |
|---|---|---|---|---|---|
| 774×334（手机横屏 DPR3） | 5+4 | 129×94 | 37 / 108（居中） | x 37–738, y 104–306 | ✓ |
| 667×375（iPhone SE 横屏） | 5+4 | 115×84 | 26 / 89 | x 26–641, y 130–308 | ✓ |
| 1908×1014（桌面） | 5+4 | 134×96 | 591 / 665 | x 591–1317, y 442–648 | ✓ |

**回归**：`测试/2D引擎回归.html` 断言 25 → **28 项全通过**（新增"传 13 张 → 承载 12 张""9 张在 774×334 下排成 5+4""不溢出"）。
顺带修掉该页一个环境依赖：后台标签里 rAF 不跑 → Phaser 的 scale 停在 0×0 → 面板尺寸守卫会让断言随机失败；
现在断言前给 scene 一个真实画幅，跑完还回去。

## 10. 补充改动：选英雄界面的提示 + 进游戏时两条提示不再打架

**提示文案（用户指定原话）**：选英雄画内面板的说明改成
**「选完英雄和增益后才能进入实时战斗哦」**（原来是"选完英雄与开局增益，直接开始第 1 层的 2D 实时战斗"，
读起来像"点完英雄就开打"）。选增益面板呼应一句：**「三选一 · 选完这一项就进入实时战斗」**。

**"位置打架"是怎么回事（实测确认）**

| 层 | z-index | 位置 |
|---|---|---|
| 画布 `#trial2DStage` | 9000 | 全屏，面板垂直居中 |
| DOM toast `.toast-container` | **999999** | 屏幕底部居中 |

选英雄这一刻恰好也是 `loadGame()` 的时刻，而进游戏时会有两条 toast 落在底部：

1. `⚠️ 此存档曾被其他页面/标签页修改过，可能存在进度覆盖`（`主程序.js` 的 sessionId 不一致分支）
2. `📂 已继承 2.6 存档（N 项）· 新版与老版进度各自独立`（首启迁移后 700ms 弹）

手机横屏画布只有 334px 高、选英雄面板占了 8..326px，角色卡第二行正好在底部 —— 两条 toast 会糊在卡上。

**改法：DOM toast 给画内面板让路**

- `经典2D.js` 新增 `deferToast(msg, type)` / `flushPendingToasts()`（队列保留 `type`，`info` 样式不丢），
  并在 `window.经典2D` 上导出 `deferToast`。
- 只有"选英雄 / 选增益 + 画布已起来"两个条件同时成立才拦；画布没起来、引擎被关掉（`?classic2d=0`）都照常弹。
- 上面那两条 toast 改为先问 `经典2D.deferToast(...)`，返回 true 就自己不再弹。
- **补弹点有两个**，缺一不可：
  1. `startRun()` 开局成功后（面板已收起 → 现在可以说了）；
  2. 宿主 `render()` 里"选英雄/选增益分支之后"。
     为什么必须加第二个：**读档续玩时引擎本来就在跑，永远不会再走 `startRun`** —— 只放在 1 里，
     队列里的提示会被永久扣住。这是实测测出来的（注入"引擎已在跑 + 面板阶段排队 → 补弹"复现）。

**实测证据**

| 场景 | 面板开着时 | 离开选人阶段后 |
|---|---|---|

| 引擎已在跑（读档续玩） | `seenWhilePanel: []` | `seen: [['T-info','info'], ['T-plain','(undefined)']]`（**类型保留**） |

- 选英雄面板实测：`title='选择英雄'`、`desc='选完英雄和增益后才能进入实时战斗哦'`、`cards=9`（战士/刺客/贤者…）

- 拦截判定：画布未起来时 `deferToast` 返回 false（照常弹）；面板阶段返回 true
- `测试/2D引擎回归.html` **28 项全通过**

**顺手修掉测试页的一个环境依赖**：上次我用"给 `scale.width` 赋值"绕过面板的尺寸守卫，
但 **Phaser 的 `scale.width` 是只读 getter**（赋值静默无效），`scale.resize()/refresh()` 在后台标签

## 11. 回退：选英雄 / 选增益回到老的文字界面（本节推翻 §9、§10 的主体）

**做法：用备份干净回退，而不是手写反向补丁**

动手前按惯例存了两个备份，这次正好派上用场：

| 备份 | 用途 |
|---|---|
| `其他/备份/经典2D.js.bak-before-in2d-b` | 搬入画布**之前**的宿主 |
| `其他/备份/主程序.js.bak-before-hint-a` | 加 toast 让路**之前**的内核 |

先做差异比对确认"备份 ↔ 当前"的**全部**差异都属于要删的那件事（宿主 +207 / −14 行，内核 +9 / −2 行，
逐行看过），再整文件复原。回退前又存了一份 `*.bak-canvas-select-undo-<时间戳>`，随时可反悔。

**删掉的**（都在宿主）：`openHeroPanel` / `openBonusPanel`、`render()` 的选人分支、
`onChoiceResult` 的 `hero` / `bonus` 分支、`schedulePanelRetry` / `clearPanelRetry`、`deferToast` / `flushPendingToasts`
及其在两个 toast 调用点的接入、`shouldTakeOver` / `takeOverReason` 里对这两个模式的特殊处理、
`ensureBooted` 抽取（连同重试定时器的 mode 分流一起回到原样）。
**内核**：两条 toast 恢复成直接 `showToast`。`chooseHero` / `chooseBonus` / `getBonusChoices` 三个桥接键保留
（零成本，且属于内核窄接口的一部分）。

**保留的（有真实受益人，不跟着回退）**

1. **引擎卡片上限 6 → 12 + 每行 5 张自动换行、每行居中**。
   真实受益人是**结局面板**：`getEndOptions()` 最多返回 **12** 种结局，而画内面板原来卡在 6 张 ——
   也就是说 7 号之后的结局玩家根本**选不到**。12 正好把结局全量装下（顺带发现宿主注释写"内核 13 种"是小笔误，实际 12）。
2. 回归测试里对窗口可见性的修复（见 §10 末尾）。

**回退后暴露并修掉的一个真实缺陷**

`render()` 在不接管时**从来不收画布**，只 `return false`。选人在 DOM 时这就成了硬伤：
一局打到一半**重置存档回到选英雄**，画布还盖在最上面 ——
玩家看到的是一张"冻住的战斗画面"，DOM 的英雄按钮全被压在下面，点都点不到（实测：`takeOver:false` 但 `stage:visible`）。

修法：`showStage()` 维护一个 `stageShown` 标记，`render()` 的两条"不接管"分支
（`!enabled() || unavailable`、`!shouldTakeOver()`）在确实开着时才 `showStage(false)` ——
渲染调用很频繁，不能每帧无脑重排。

**提示文案落在文字界面**

- 选英雄页 `eventText`：`从 9 位英雄中选择一位，每个英雄拥有专属属性与技能。选完英雄和增益后才能进入实时战斗哦。`
  （同时把写死的"十一位英雄"改成按 `heroOptions.length` 实数走，原来早就和实际对不上了）
- 选增益页 `eventText`：`从三种开局增益中选择一个。选完这一项就进入实时战斗哦。`

**实测（真实入口流程，非注入）**

| 步骤 | mode | 画布 | 文字界面 |
|---|---|---|---|
| 点「开始游戏」 | `heroSelect` | hidden | 标题「选择英雄」+ 提示 + **9 个英雄按钮** |
| 点英雄（战士） | `bonusSelect` | hidden | 标题「选择开局增益」+ 提示 + **3 个增益按钮** |
| 点增益 | **`classic2d`** | **visible** | — 自动进入 2D：`running=true`、`engine.floor=1`、canvas 1908×988 |
| 画布开着时注入 `heroSelect` | `heroSelect` | **hidden**（修复生效） | 9 个按钮可见可点 |
