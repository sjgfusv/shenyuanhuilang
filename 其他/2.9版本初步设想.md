# 深渊回廊 2.9 初步设想：让房间不再是同一种房间

> 状态：**初步设想 v7 · 未排期 · 未动一行代码**
> v7 变更（触控与验证方式）：§7.4 读条改「停留触发」（触屏双指冲突）；§9.8 脱困改为「提示 + 崩解兜底」，**不需要任何新按键**；样板房间改为先做独立预览页 `其他/塌陷回廊预览.html`。
> v6 变更：**移除「高台阵」骨架** —— 它要求出口开在高处，等于要改出口坐标与触发判定，和竖井同属「动空间模型」的改动，超出 2.9 范围。骨架回到三种（平厅 / 双层 / 断桥），比例重排。
> v5 变更（定位修正）：**骨架不是新增房间类型，而是每个战斗房间的必选维度**（当时比例 35/30/20/15，v6 已改为 40/35/25）。§2/§3 全面重写为「骨架必选 × 机制可选挂载」。
> v4 变更：补 §3.3 新房间投放规则；§9.2 修正「不能贪」的表述并补「平台之间不连通」这个前提；新增 §9.8 平台被困死局与脱困；新增 §9.9 实现约束（移动端尺寸 / 性能 / 验收 / 音频 / 存档 / 图鉴 / 联动）。
> v3 变更：§5.5 删掉「踩头次数限制」兜底；§7.5 定案选 A（显性化）；**§9 重做压力设计** —— v2 用「怪围住你」阻止蹲终点，被作者指出「一个跳劈就全秒了」，v3 改为「出口锁 + 魂晶当钥匙」。
> v2 变更：补「魂晶出现频率」约束；重写掉落逻辑（v1 有死局漏洞）；新增 §5 怪物节奏；§11 记录第一轮拍板结论。
> 起因：用户原话 —— 「现在的平台上只有魂晶和怪，或者说只有平台，游戏只能跳来跳去捡魂晶和打怪，太单调无聊了」
> 本文只回答一个问题：**在不增加怪物、不增加遗物的前提下，怎么让「跳来跳去」重新变得有意思。**
> 文中行号均为当前工作区实测（`战斗2D.js` 13575 行），可直接核对。

## 0. 先说结论

**单调不是因为内容不够，而是因为「容器」只有一种形状。**

现在已经有 9 位英雄、13 种敌人、27 件遗物、15 条环境效果、10 条诅咒 —— 内容量在这个体量上完全够用。但每个房间都是同一张剖面图：

```
一条平地 + 4~9 段随机浮台 + 平台上的一颗魂晶 + 一两只站高台的远程怪
```

在这个结构里，平台只有一个身份：**够到魂晶的梯子**。玩家跳来跳去时，心理上做的永远是同一件事，只是背景换了。

所以 2.9 的方向不是「加东西」，而是**给房间换形状、换目的、换动词** —— 外加一条：**把怪从「沙包」改回「对手」**（§5）。

这里有一个关键定位（第二轮拍板修正）：**换形状不是「新增一种房间」，而是让「地形骨架」成为每个战斗房间的必选维度。**
平地保留、占 40%，但另外 60% 的房间有结构 —— 共存，不是替换。否则你只是把 8% 的房间变得不一样，剩下 92% 还在平地上跑（§2）。

## 1. 诊断：三个「只有一种」

### 1.1 空间只有一种形状

`spawnPlatforms()`（`战斗2D.js:7457`）现在的生成逻辑：

| 参数 | 现值 | 含义 |
|---|---|---|
| `count` | `4 + min(5, floor/2)` | 平台段数，随层数最多 9 段 |
| `topY` | `max(groundY - 350, H * 0.14)` | 最高可及高度 |
| `lowY` | `groundY - 110` | 最低平台离地高度 |
| `xMin / xMax` | `W*0.35` ~ `levelWidth - 260` | 水平可用跨度 |
| `GAP_X / GAP_Y` | `56 / 68` | 防重叠的最小间距 |

也就是说：**平台永远是「悬在半空、互不连通、不承担通行功能」的装饰物**。地面永远连续、永远安全、永远可以从左走到右。玩家没有任何一次「必须跳」的时刻。

而且它是**纯随机**的：每个房间都不一样，但每个房间都不值得记住。随机生成的是装饰，不是关卡。

### 1.2 目的只有一种

`nonCombatRoom()`（`战斗2D.js:777`）之外的所有房间，完成条件都是**清怪归零 → 开门**。

所以整局的节奏是：

```
打 → 点两下（宝箱/祭坛/商店）→ 打 → 点两下 → 打
```

宝箱、祭坛、商店、休整点提供了「非战斗房间」，但它们提供的是**休息**，不是**另一种玩法**。玩家的手在非战斗房间里是完全闲着的。

### 1.3 跳跃只有一个用途

现有的空中动作：蓄力跳（够高）、跳劈（下砸输出）、闪避（位移无敌）。

这三个都是「位移 + 伤害」，没有一个是**空间与战斗的耦合**。玩家不会因为「跳上去能打得更好」而跳，只会因为「上面有东西捡」而跳。

### 1.4 顺带一个主题问题

游戏叫《深渊回廊》，但每层都是**横向的平地走廊**，没有任何纵向的深渊感、没有纵深、没有压迫。主题和玩法是脱节的 —— 这是 3.0 可以吃的一张大牌（见 §10）。

## 2. 方向一：骨架是每个战斗房间的必选维度，不是新房间类型

**这是 2.9 最重要的一条定位修正。**

最初的想法是「新增一种叫塌陷回廊的房间」—— 但那样只解决了 8% 的房间，**剩下 92% 还是平地**，玩家大部分时间依然在平地上跑，问题没解决。

所以正确的做法是：**把「地形骨架」变成所有战斗房间的必选维度**。每个房间生成时从骨架库里抽一个，平地保留，但它只是其中一种，不再是唯一。

```
房间 = 骨架（必选，3 选 1） × 机制（可选，按类型挂载） × 房间类型（敌袭/精英/镜像/层主）
```

房间类型完全不变，变的只是**它们脚下的地形**。

### 2.1 骨架库（空间结构，每个战斗房间必选一个）

| 骨架 | 占比 | 结构 | 平台的地位 | 成本 |
|---|---|---|---|---|
| **平厅** | 40% | 现状：连续地面 + 浮台 | 可选（装饰） | 0（保留） |
| **双层** | 35% | 上下两层实体地板 + 1~2 个连通口 | **必经**（上层压制 / 上层出口） | 低 |
| **断桥** | 25% | 地面断裂 1~2 处，缺口下是坑 | **必经**（掉下去有代价） | 低 |
| **竖井** | 0%（3.0） | 纵向房间，相机跟 y 轴 | 必经 | **高** |
| **坠落井** | 0%（3.0） | 进房间自由落体 | 必经 | **高** |

**平地占 40% 是刻意的。** 它必须保留 —— 玩家需要一个「喘口气、不用想地形」的房间。但另外 60% 有结构，这才是「共存」而不是「替换」。

**分布随层数渐进**（上表是第 16 层以后的目标分布）：

| 层数 | 平厅 | 双层 | 断桥 |
|---|---|---|---|
| 1（教学） | 100% | — | — |
| 2~5 | 75% | 25% | — |
| 6~15 | 50% | 30% | 20% |
| 16+ | 40% | 35% | 25% |

这样玩家对地形的认知是**一层一层长出来的**，而不是第一层就被扔进断桥里。

> **排除项：为什么不做「出口在高处」的骨架（原「高台阵」）**
> 它看起来只是把出口往上挪，但出口位置一改，**传送门坐标、触发判定、相机取景、开门条件**全都要跟着改 —— 和竖井房间同属「动空间模型」的改动。
> 2.9 的边界是「不改空间模型，只改地形填充」。所以这个骨架留给 3.0 和竖井一起做。

### 2.2 为什么这两个新骨架值得做

**双层**：上层有独立视野，下层是主战场。远程怪站上层持续压制，玩家要么爬上去清、要么在下方被慢慢消耗。不需要新怪、不需要新 AI —— 只是把「站高台的远程怪」这个**已经存在**的设计（`platformPerches`，`:7558`）从「偶尔出现」变成「结构性存在」。

**断桥**：地面中间裂开，下面是坑。这一刀直接把「跳」从可选变成必修，而且**零新增系统** —— 只是 `layoutFloor()` 少铺几段地砖，再加一个「掉出下边界 → 扣血 + 传回」的判定。

**竖井和坠落井先不做**，原因见 §2.4。

### 2.3 骨架不等于手工关卡

不需要手写每一层的地图。做法是：

```
骨架 = 一组带约束的槽位（slot）
参数 = 房间宽 / 视口高 / 层数 / 房间类型
```

比如「双层」的骨架就是：`上层地板 y = groundY - 210，长度 = levelWidth * 0.55，起点 x 随机；连通口在右端，宽 90px`。每次生成位置略有不同，但**结构永远成立**。

这和现在的随机撒点有本质区别：**随机的是位置，不是结构**。玩家能记住「双层房间的出口通常在上面」，于是会主动去找上层。

### 2.4 为什么竖井/坠落井要留到 3.0（风险提示）

`战斗2D.js:7237-7238` 现在的边界是写死的横向假设：

```js
this.physics.world.setBounds(0, -600, this.levelWidth, H + 1200);
this.cameras.main.setBounds(0, -head, this.levelWidth, H + head);
```

而 `groundY`、`levelWidth`（`:7309`）、平台带高度（`:7463` 附近的 `H * 0.14`）、HUD 遮挡（`:7216` 那段注释）**全部是按「横向 + 单层地面」推出来的**。改纵向房间要同时重算这四样，而且手机横屏 `H` 只有 360 —— 纵向可用空间极其局促，很容易做出来「在手机上只能看到一格」。

**结论：2.9 不动相机模型。** 竖井/坠落井作为 3.0 的大版本卖点，单独一个版本专门做纵向。

## 3. 方向二：机制是「可选挂载」，让同一个骨架换一种玩法

骨架决定「空间长什么样」，机制决定「这个房间要你干什么」。

**两者是正交的** —— 同一种机制可以挂在不同骨架上，组合出完全不同的房间。

| 机制 | 挂载率 | 动词 | 说明 | 成本 |
|---|---|---|---|---|
| 无（清怪） | 剩余 | 清怪 | 现有 | 0 |
| **塌陷** | 15% | 往右跑 + 收集 | 地面逐段塌，出口锁着要魂晶 | 低 |
| **守点** | 10% | 站住 | 圈在平台上，守 N 秒 | 低 |
| **限时** | 10% | 抢时间 | N 秒内清完，超时怪强化 | 低 |
| **拆解** | 0%（不在 2.9） | 找目标 | 打掉 3 个图腾，图腾长在高处 | 中 |
| **搬运** | 0%（3.0） | 护送 | 抱着火种走，抱着时不能攻击 | 中 |

> 2.9 只做**塌陷 / 守点 / 限时**三种。拆解、搬运都不在本次范围（见 §8）。

### 3.1 组合出来的房间，比「新增房间类型」多得多

| 骨架 × 机制 | 结果 |
|---|---|
| 平厅 + 限时 | 纯粹的 DPS 检验，不用想地形 |
| 断桥 + 塌陷 | 边跑边塌，脚下还有断口 —— **最难的一种** |
| 双层 + 守点 | 守上层还是下层，是真抉择 |
| 平厅 + 塌陷 | 样板房间「塌陷回廊」（§9） |

**3 骨架 × 3 机制 = 9 种房间变化，但只需要做 3 + 3 = 6 个系统。**

### 3.2 为什么「塌陷」性价比最高

- 不用新美术：地面本来就有一条 TileSprite（`layoutFloor()`，`:7440`），把它分段销毁就行
- 不用新 AI：沿用现有敌人池，只是持续补刷
- 不用改相机：横向房间，只是「安全区在移动」
- **一个机制同时用上了移动、跳跃、时间压力、空间判断**

### 3.3 需要配套改的一件事：房间完成条件

现在所有战斗房的完成条件都是「清怪归零 → 开门」。带机制的房间要求**换完成条件**：

```
达成房间目标 = 开门 → 抵达出口 = 通关（怪是干扰，不要求清）
```

目标可以是「抵达」「集齐 N 个」「守住 N 秒」「限时清完」—— 统一成 `房间目标 = { 类型, 阈值, 奖励 }`，避免每种房间各写一套判定。

这是 2.9 唯一必须动到「房间流程」的地方，改动面不大但要谨慎：开门逻辑、HUD 的「剩余敌人」显示（`:10895`）、结算奖励都要跟着分支。

### 3.4 骨架与机制怎么投放

| 项 | 规则 |
|---|---|
| **骨架** | 每个战斗房间**必选一个**，按 §2.1 的比例抽（平厅 40 / 双层 35 / 断桥 25） |
| **机制** | **可选挂载**，按房间类型抽：2.9 只上塌陷 / 守点 / 限时三种（拆解留到后续） |
| **不叠加** | 同一个房间最多挂 1 种机制，不要出现「塌陷 + 守点」 |
| **解锁层数** | 骨架从第 2 层起生效（第 1 层保持平厅，当教学区）；机制从第 3 层起 |
| **层主房** | **不挂机制**，骨架固定平厅 —— BOSS 战不该被地形干扰 |
| **保底** | 每 5 层至少出现 1 次「带机制」的房间 |

**为什么要限制机制挂载率**：机制是「调味料」，不是「主食」。一局里如果 1/3 的房间都是塌陷，它很快会从「新鲜」变成「又来了」。而骨架不同 —— 骨架是**每个房间都要有的东西**，所以它必须占满 100%，只是分布要均匀。

## 4. 方向三：把「跳」变成战斗语言

这一块**改动最小、手感提升最明显**，建议优先做。

| 动作 | 效果 | 为什么重要 |
|---|---|---|
| **踩头弹跳** | 踩敌人头顶弹起，并重置空中攻击 | 战斗从「地面缠斗」变成「空中连击」，玩家会主动拿怪当跳板 |
| **蹬墙跳** | 贴墙时二段起跳 | 配合双层房间的侧壁，让竖直空间可往返 |
| **连携点换二段跳** | 消耗 1 点连携换一次二段跳 | 连携从「纯输出资源」变成「走位资源」，多一个抉择 |
| **加速下坠穿平台** | 按 ↓ 直接落下层 | 纯手感补丁，让双层房间通行顺畅 |

**踩头弹跳**是这四条里最想推的。它一条就能改变整个战斗的空间感：现在玩家永远在地面等怪过来，加了踩头之后，玩家会开始「跳怪」。

> ⚠️ 但它有一个直接后果：**玩家会更长时间待在空中**，而现有怪里能打空中的只有 `flyer`（影）、`shooter`（死灵法师 / 织网者）、`throw`（骷髅骑兵掷矛）。踩头弹跳上线前必须先给近战怪补「对空手段」，否则会变成新的无解打法。详见 §5.5。

## 5. 配套：怪物节奏 —— 把怪从「沙包」改回「对手」

> 来自作者拍板：「现在的平衡性并不好，比如怪的前摇太长，还没动手就被玩家秒了，只能被玩家戏耍，一点挑战性也没有。」
> 这一节不是「顺手加强怪物」，而是**踩头弹跳能成立的前提**，也是 2.9 必须做的一件事。

### 5.1 实测数据（`ENEMY_DEFS`，`战斗2D.js:1155-1177`）

| 敌人 | 血量 | 前摇 | 后摇 |
|---|---|---|---|
| 黑暗爪牙 | 24 | 340 | 420 |
| 骷髅骑兵 | 32 | 300 | 460 |
| 死尸 | 44 | 520 | 560 |
| 岩浆行者 | 36 | 430 | 540 |
| 影 | 28 | 300 | 380 |
| 镜像怪 | 42 | 300 | 400 |
| 铁壁兵 | 40 | 480 | 560 |
| 织网者 | 30 | 620 | 820 |
| 精英守卫 | 72 | 450 | 540 |
| 死灵法师 | 56 | 540 | 700 |
| 献祭者 | 48 | 560 | 700 |
| 层主 | 160 | 520 | 620 |
| 影之皇 | 240 | 460 | 520 |

### 5.2 病根不在「前摇长」，在「前摇会被打断且完全重置」

两个关键数字：

- **普通命中硬直 = 150ms**（`:8980` 注释原文：「普通命中硬直只有 150ms」）
- **受击硬直期间敌人不受控**（`:11940`）

推一下就知道为什么怪永远出不了手：

```
爪牙前摇 340ms
玩家攻击间隔 ≈ 400ms
→ 每一下命中都让怪进入 150ms 硬直、打断当前动作
→ 硬直结束回到 chase，前摇从 0 重新计时
→ 340ms 永远攒不满
→ 怪一次都打不出来
```

再叠加血量：爪牙 24 血，玩家一下十几点，**两下就死，根本活不到 340ms 的前摇结束**。

所以「前摇太长」的体感是真实的，但**病因是「前摇可以被无限打断」，不是「前摇时长本身」**。单纯把前摇从 340 改到 200 只是把问题推后一点，还会撞红线（见 §5.4）。

### 5.3 四条改法（按性价比排序）

| # | 改法 | 效果 | 成本 |
|---|---|---|---|
| **1** | **前摇计时器不因受击重置** —— 受击只进硬直，`windupUntil` 继续走；硬直结束时若 `windupUntil` 已过，立刻出手 | 玩家打它 = 提前引爆，**打反而更危险** | 低（改状态机一处） |
| **2** | **前摇后 40% 霸体** —— 起手动作最后一段不可打断 | 让「看到起手」真的意味着「必须闪」 | 低 |
| **3** | **受击硬直递减** —— 连续受击 150 → 110 → 80 → 60 → 0 | 第 4 下之后压不住，逼玩家走位而不是站桩 | 低 |
| **4** | **打断反击** —— 前摇被打断时，有概率立刻转成 200ms 的短前摇反击 | 惩罚无脑连打 | 中 |

**推荐先做 1 + 2**。这两条合起来就是一句话：**「你打它，它照样打你」**。怪立刻从沙包变成对手，而且不需要加血、不需要加攻。

> 实现前需要确认一件事：现有状态机在 `hurt` 结束后是回 `chase` 还是保留 `windupUntil`（`:11972` 起的 `windup` 分支）。如果 `windupUntil` 被清掉了，改法 1 就要动状态机的字段生命周期，不只是加个判断。

### 5.4 两条红线不能碰

1. **前摇 200ms 硬下限**（`:8133`）：
   ```js
   out.windup = Math.max(200, Math.round(def.windup * ai.windup));
   ```
   原因是**完美闪避窗口固定 150ms**，玩家要「看到起手 → 在命中瞬间闪」。前摇压到窗口附近，这一击就变成没法反应的抽奖。这条是 2.8 已经写进更新日志的设计红线（`主程序.js:8430`），2.9 不动。

2. **不能只靠加血解决问题**。加血会让怪变肉、战斗变闷，是「把沙包改成血包」，不是改回对手。

### 5.5 踩头弹跳必须配套的对空手段

玩家一旦能踩头反复滞空，近战怪（`chaser` / `charger` / `bulwark`）就完全摸不到人。需要补：

- `chaser`：**跳跃扑击** —— 玩家滞空时，怪起跳扑一次（前摇 300ms，可闪）
- `charger`：冲锋判定**纵向加高**，不再只能撞到地面高度的人

这两条都要真做，不做「踩头次数限制」这类兜底 —— 它会把「空中连击」的爽感直接削掉一半，等于用一个体验损失去补另一个体验损失。

## 6. 方向四：让平台本身有性格

| 元素 | 说明 | 成本 |
|---|---|---|
| **单向平台** | 从下面能穿上去、从上面能踩住 | **极低（几乎必做）** |
| **崩落平台** | 站上去 0.8 秒后碎裂 | 低 |
| **移动平台** | 左右或上下平移 | 中 |
| **尖刺 / 腐蚀池** | 掉下去有代价，坑才有意义 | 低（断桥的前提） |
| **风区** | 上升气流，可悬停、改变跳跃弧线 | 中 |
| **可破坏物** | 木箱、石柱，挡弹道、打碎掉金币 | 中 |

「单向平台」建议无条件做掉。现在所有平台都是实心碰撞体，从下往上跳会被顶住 —— 这是很多「跳不上去、卡一下」的体感来源。

## 7. 方向五：魂晶 —— 从「白送」变成「值得绕路的目标」

### 7.1 现在的问题：太多、太容易、零抉择

`spawnPlatformAt()`（`:7559`）：

```js
if (Math.random() < 0.62) {   // 每段平台 62% 概率长一颗
  this.spawnCrystal(midX, topY2 - 26);
```

房间有 4~9 段平台 → **平均每个房间 2.5~5.6 颗魂晶**。走一趟顺手全捡了，它从「目标」退化成「地板上的掉落物」。

而且 `takeCrystal()`（`:7620`）是「走近自动给最缺的那样」，**零风险、零操作、零抉择**。

### 7.2 出现频率：从「撒」改成「点」

| 项 | 现状 | 2.9 建议 |
|---|---|---|
| 生成概率 | 每段平台 62% | **每房间保底 1 颗 + 30% 概率额外 1 颗**（上限 2 颗） |
| 保底位置 | 最低平台（`:7527`） | 保留 |
| 平均数量 | 2.5~5.6 颗/房 | **约 1.3 颗/房** |

**减频率必须配套加单颗收益**，否则经济会缩水。建议单颗收益上调 50%~80%，让「绕路去拿」这件事本身值得。

### 7.3 三色魂晶

| 颜色 | 效果 | 代价 |
|---|---|---|
| 蓝（普通） | 现有收益（金币 / 护盾 / 回血） | 无 |
| 深渊 | 强效（遗物碎片 / 大量金币） | 房间内所有敌人强化 |
| 腐化 | 直接给 1 件遗物 | +1 条诅咒 |

### 7.4 读条拾取（已定案：停留触发）

**靠近魂晶后站住不动 0.2 秒开始读条，读条 0.6 秒，移动 / 受击 / 怪贴近都会打断。**

原本写的是「按住 0.6 秒」，改掉的原因是触屏：手机上要一边推摇杆一边按住，是两根手指，很别扭。

改成停留触发之后有三个好处：

| 好处 | 说明 |
|---|---|
| 键鼠与触屏零差异 | 不需要任何按键 |
| 「不拿」有了自然表达 | 快速跑过就不触发，不用做「取消拾取」 |
| 风险窗口更真实 | 你不能动，而地面正在塌 |

风险窗口一出来，「捡不捡」才第一次成为选择 —— 尤其是深渊/腐化魂晶挂在最难够到的平台上时。

> 实现要点：判定用「位置变化速度 < 阈值持续 0.2 秒」，不要用「没有输入」—— 摇杆回中但有惯性时会误判。

### 7.5 附：核实「低血回血」到底存不存在

作者问：「有低血回血这个机制吗，我咋不知道」——

**有，但只在魂晶里，而且完全不可见。** `takeCrystal()`，`:7619`：

```js
var lowHp = h.hp < h.maxHp * CRYSTAL.lowHpAt;   // lowHpAt = 0.6
var roll = Math.random();
if (lowHp && roll < 0.6) {                       // 血量 <60% 时，60% 概率走回血分支
  var heal = Math.max(CRYSTAL.healMin, Math.round(h.maxHp * CRYSTAL.healPct));
  // healMin = 8，healPct = 0.25 → 回复 25% 最大生命，至少 8 点
```

三个特点解释了为什么没人知道：

1. **没有 UI 提示** —— 魂晶外观、飘字、图鉴里都没有「低血会回血」这条
2. **飘字只写「魂晶 · 生命 +12」** —— 和普通回血长得一样，看不出这是保底机制
3. **触发条件藏在随机分支里** —— 玩家只会觉得「有时候捡了回血，有时候给钱」

**结论：一个玩家感知不到的机制，等于不存在。**

**已拍板：选 A（显性化）。** 具体做法：

| 要做 | 说明 |
|---|---|
| 外观区分 | 血量 <60% 时，魂晶核心与光晕由青蓝变**绿色**（`0x8ad8ff` → 绿系），旋转不变 |
| 头顶提示 | 提示文字由「拾取」改为「**救命**」，字号略大 |
| 飘字 | 保留「魂晶 · 生命 +12」，但前面加一个绿色回血图标或「急救」前缀，与普通收益区分 |
| 图鉴补一条 | 怪物/道具说明里写明「血量低于 60% 时魂晶转为急救」 |

理由：它给了玩家一个「残血时该往哪走」的判断依据 —— 正好呼应 §7 想做的「抉择」。而且这条改动只在 `paintCrystal()` / `updateCrystals()` 里加一个血量判断，成本极低。

> 注意：显性化之后，这条机制会**变成玩家会主动利用的资源**，等于隐性加强了玩家续航。2.9 上线后要观察药水使用率是否明显下降，必要时把 60% 阈值下调到 45%。

## 8. 2.9 范围建议（做五件，不做五件）

### 做

1. **三种骨架**：平厅（保留）+ 双层 + 断桥（`spawnPlatforms()` 改为骨架驱动，每个战斗房必选一个）
2. **三种机制**：塌陷 / 守点 / 限时（可选挂载，含「达成目标 → 开门」完成条件 + 投放规则，见 §3.3~§3.4）
3. **手感三件套**：踩头弹跳 + 单向平台 + 加速下坠
4. **怪物节奏**：前摇不重置 + 前摇后段霸体 + 近战怪对空（§5）
5. **魂晶**：降频 + 三色 + 读条 + 低血回血显性化 + 作为「出口钥匙」（§9.2）

> 玩家感知不到，但不做它，后面每改一处都要动主流程，出问题也分不清是谁的锅。详见施工清单 §3。

### 不做（留给 3.0）

| 不做 | 原因 |
|---|---|
| 竖井 / 坠落井 | 要重算相机 bounds、groundY、levelWidth、HUD 遮挡，且窄视口下纵向空间极其局促 |
| 钩爪 / 绳索摆荡 | 需要新的位移物理系统 |

### 为什么这么切

2.9 的定位是「**给容器换形状 + 把怪改回对手**」。上面五件事里，四件落在现有函数的既有参数上，只有 §5.3 的改法 1 需要动状态机字段 —— 但它也是收益最大的一条。

而 3.0 可以拿「纵向深渊」当大版本卖点 —— 竖井 + 坠落井 + 蹬墙跳 + 钩爪，正好是一个完整主题。

## 9. 样板房间：塌陷回廊（详细设计草案）

**这是本文档最重要的一节。** 建议 2.9 开工前先手工把这一个房间做出来，玩 20 遍，再决定要不要参数化批量生成。

> **v3 变更**：v2 用「第 8 段永不塌 + 站着等会被 3 只怪围住」来阻止玩家蹲终点 —— 这个判断是错的。玩家强度远高于三只杂兵，一个跳劈带 130px 冲击波就能清场，**怪根本压不住人**。
> v3 换了压力来源：**压力不来自怪，来自「出口锁着」**。

### 9.1 布局

```
[起点] ──1── ──2── ──3── ──4── ──5── ──6── ──7── ──8──[出口·锁]   （段数按层数变，图示为标准档 8 段）
        ↑平台A(蓝魂晶)  ↑平台B(深渊魂晶)  ↑平台C(腐化魂晶)
```

- 房间宽度：`levelWidth = W * 2`（沿用现状，`:7309`）
- 地面切 **N 段**（N 由层数决定，见下表；标准档 8 段），每段宽 `levelWidth / N`
- 平台 3 段（数量见下表），高度在「离地可用高度」内均分递增，每段平台各挂 1 颗魂晶
- 另外 2 颗魂晶放在地面够不到、只能跳起来拿的位置（共 5 颗）

**层数变体（第 1 条拍板：要做 → ⛔ 2.9.1 决定不做，见文末口径更正）**

同一个机制在不同层数下不是单纯变快，而是**结构变复杂**：

| 层数 | 地面段数 | 塌陷间隔 | 魂晶需求 | 平台数 | 定位 |
|---|---|---|---|---|---|
| 3~5 | 5 | 5.0s | 2 | 2 | 教学：慢慢塌，够你反应 |
| 6~10 | 6 | 4.5s | 3 | 3 | 标准 |
| 11~20 | 8 | 4.0s | 3 | 3 | 标准（§9.2~§9.8 描述的就是这一档） |
| 21~35 | 9 | 3.2s | 4 | 4 | 高压：来不及全收 |
| 36+ | 10 | 2.6s | 4 | 4 | 极限：只能走最短路线 |

> ⚠️ **层数变体必须和视口取交集。** 窄视口（高度不足 420 时）纵向放不下 4 段平台（§9.9 第 1 条），所以「平台数」这一列要按可用高度强制降一档。
> 塌陷间隔也要跟着段数走：段数越多、总时长越长，间隔必须相应缩短，否则高层的房间会变成「跑马拉松」。
>
> ⛔ **落地状态（2.9.1）**：这张表**没有实现**，也不会实现。实际只保留「难度」一条缩放轴
> （`MECH_DIFF`：简单 6 段/5.5s/2 颗、普通 8/4.0/3、困难 9/3.4/3、地狱 10/2.8/4）。
> 理由：普通档 8/4.0/3 是从实机数据反推出来的；再加一条层数轴就是 3 难度 × 5 层段 = 15 格参数矩阵，
> 每格都没有数据支撑，调参时无法归因。层数仍然影响敌人强度与奖励，只是不再改机制参数。
> 下方第 480 行那条「全文约定」因此也不再需要（房间里永远只有一套参数）。

> **⚠️ 全文约定（两条，都因为参数随层数变）**
> 1. **「最后一段」指当前房间地面段的末段**（标准档第 8 段、教学档第 5 段）。规则一律写「最后一段」，不能写死「第 8 段」—— 否则低层只有 5 段，第 8 段根本不存在，兜底永远不触发。
> 2. **「3 颗」是标准档的举例**，实际需求见上表（教学档 2 颗、高层 4 颗）。

### 9.2 核心机制：出口是锁的，钥匙是魂晶

**这是整个房间的支点。**

```
出口 = 锁着
开锁条件 = 收集 3 颗魂晶
魂晶位置 = 平台上（必须跳）+ 半空（必须跳）
```

于是「蹲在终点等」这条路直接不存在了 —— 你蹲在出口前，钥匙还在你身后的平台上，而地面正在塌，你回不去。

**三条压力同时成立，没有一条依赖怪：**

| 压力 | 来源 |
|---|---|
| 不能停 | 地面每 4 秒塌一段 |
| 必须跳 | 魂晶长在平台上 |
| 不能贪 | 拿魂晶要读条 0.6 秒（§7.4）—— 读条本身是安全的，但**这 0.6 秒是从「地面还连通」的时间里扣掉的** |

> **一条容易漏掉的前提：平台之间不直接相连，必须借地面过渡。**
> 平台只保证「向上够得着」，不保证「向前走得通」—— 垂直间距在跳跃范围内，水平间距故意拉大。
> 这样地面塌陷才有意义：**你站在平台上很安全，但你会被孤立。**
> 如果平台之间能直接连跳，玩家全程走平台就行，地面塌不塌都无所谓，整个房间就废了。

怪在这个房间里的角色**不是压血，是打断读条**。一只杂兵足够让你多花 2 秒 —— 而 2 秒在这个节奏里很致命。这比「三只怪围住你」有用得多。

> 魂晶数量说明：§7.2 规定普通房间 1~2 颗，塌陷回廊是**特殊房间**，按房间类型覆盖为 5 颗（呼应 §9.6 的「按房间类型动态给」）。放 5 颗只要 3 颗，是给「跑太快漏了一颗」留的容错。

#### 出口锁的具体实现（回答「怎么个锁法」）

**1. 门长什么样**

门框上嵌 **3 个符文凹槽**，竖排或横排均可，初始全暗（深紫 `0x3a1a4a`）。

| 状态 | 表现 |
|---|---|
| 0/3 | 3 个凹槽全暗，门体暗紫，边缘无光 |
| 1/3、2/3 | 已收集的凹槽依次亮起（青色 `0x5fd0e0`），其余仍暗 |
| 3/3 | 门体由暗紫转亮青，**一圈脉冲向外扩散**（复用 `spark()` / 现有圆环补间） |

**2. 玩家怎么知道进度**

- **不新增 HUD** —— 现在画面已经够挤（血条 / 遗物栏 / 怒气 / 连携点 / 腐蚀节拍）
- 进度靠两处：**门上的凹槽** + **拾取时的飘字**
- 飘字加后缀：`魂晶 · 护盾 +6　◆◆◇`
- 走到门口时，门下方显示一行小字：`封印 · 2/3`

**3. 锁着的时候走过去会怎样**

- **不打开房间地图**（现有「走进右侧传送门 → 开地图」的行为被拦下）
- 弹出一次提示：`出口封印 · 还差 1 颗魂晶`，**3 秒冷却**（防止贴着门反复触发刷屏）
- 玩家可以站在门口，但门不开 —— 这个「看得见却进不去」本身就是压力

**4. 集齐瞬间**

| 事件 | 说明 |
|---|---|
| 门脉冲 + 音效 | 复用现有 `sfx`，不需要新素材 |
| **停止刷怪** | 目标已达成，不再补刷 |
| 已有的怪不消失 | 不能靠开门白嫖清场，玩家还是得应付场上的怪 |
| 镜头轻震（可选） | 强度同普通命中，不要盖过 BOSS 战 |

**5. 兜底：最后一段开始预警时强制解锁**

- 门转为**红色**亮起 + 提示 `封印崩解`
- 此时走进去正常开门
- 结算时速度奖励 = 0（§9.6）

**6. 判定怎么写**

现有房间是「清怪归零 → 开门」。这里换成目标结构（呼应 §3.2）：

```js
this.roomGoal = { type: 'collect', need: 3, got: 0 };
// 拾取魂晶时 got++
// got >= need → this.openExit()
```

建议所有新房间类型共用这一个结构，`type` 取 `arrive` / `collect` / `hold` / `timed`，避免每种房间各写一套判定。

**7. 一个必须处理的边界**

玩家**已经站在门内**时集齐第 3 颗 → 门会立刻打开，但玩家还在门里，容易一帧就触发进入房间地图、看不到开门动画。

处理：**集齐时若玩家已在门内，延迟 0.5 秒再允许触发**（够看清开门，又不至于卡住玩家）。

### 9.3 时间轴

| 时刻 | 事件 |
|---|---|
| 进房 | 第 1 段地面开始抖动预警 |
| 预警 0.8s | 该段变红 + 抖动 + 碎石粒子 |
| 之后 | 该段消失，玩家若站在上面则下坠 |
| 每 X 秒 | 下一段开始预警（X 见 §9.1 层数变体表，标准档 4.0s） |
| 任意时刻集满所需数量 | **出口立即开启**（可以提前走，需求见 §9.1 表） |
| 最后一段开始预警时 | 出口**强制开启**（兜底，防止集不齐就死局） |
| 最后一段塌陷 | 房间强制结束：玩家被抛到出口，结算时**无速度奖励** |
| 全程 | 右侧持续刷怪，每 3s 一只，场上上限 3 只 |

### 9.4 掉落与传送：v1 的死局漏洞 + 修法

> **v1 的错误**：原文写「如果最后安全地面已经塌了 → 传回当前最左的存活地面」。
> 这个逻辑自相矛盾 —— 塌陷是从左往右推进的，「最左的存活地面」正是**最靠近塌陷前沿、马上就要塌的那一块**；而玩家掉下去的位置通常在最右，把他往左送等于往回推，方向和目标完全相反。

**修法：传送目标永远是「塌陷前沿右侧最近的一段存活地面」，也就是 `前沿段 + 1`。**

| 规则 | 说明 |
|---|---|
| 传送目标 | 「塌陷前沿**右侧**最近的一段存活地面」，即 `前沿段 + 1` |
| 为什么永远有落点 | 前沿最多推进到**倒数第二段**，最后一段此时必然还在 → `前沿 + 1` 一定存在 |
| 前沿已到倒数第二段 | 传送到最后一段 |
| 最后一段塌陷时 | 房间已强制结束，不再有掉落判定 |
| 传送后 | 0.6 秒无敌 + 0.5 秒不判定掉落（防连续触发） |
| 惩罚 | 扣最大生命 **4% / 7% / 10% / 12%**（简单 / 普通 / 困难 / 地狱），**单次不致死** |
| 累积 | 每次掉落都照扣，**不设免伤次数** —— 跳崖可以逃课，但跳 8 次照样会死（§9.8） |

四个边界全部有解：

| 边界情况 | 结果 |
|---|---|
| 掉下去，前沿在第 3 段 | 传到第 4 段（**向前**，符合目标方向） |
| 掉下去，前沿已在倒数第二段 | 传到最后一段（一定还在） |
| 站在预警段上被塌 | 同一套逻辑 → 前沿 +1 |
| 从平台跳下没落到地面 | 同上，统一由「掉出下边界」触发 |
| 最后一段塌了 | 房间结束，无掉落判定 |

### 9.5 为什么这样就不会「蹲在终点等」

v2 的答案是「怪会围住你」——**这个答案是错的**，用户指出得很准：一个跳劈就全秒了。

v3 的答案是**机制层面**的：

| 蹲终点的企图 | 为什么失败 |
|---|---|
| 直接跑到出口 | 出口锁着，需要 3 颗魂晶 |
| 蹲在出口前等塌陷推完 | 魂晶在你身后的平台上，地面已经塌了，回不去 |
| 等到最后一段强制开门 | 可以，但**速度奖励归零**，且没收集的魂晶收益全丢 |

所以「苟」是一个**存在但收益极低**的策略。这反而是好事 —— 它给了新手一条保命路径，同时让高手有明确的优化空间。**奖励差距本身就是压力**，不需要靠怪来压。

### 9.6 奖励（按拍板结论：基础 + 动态，都要）

| 来源 | 内容 |
|---|---|
| **基础（按房间类型）** | 等同敌袭房基准金币 |
| **动态 · 提前** | 出口开启时未塌段数 × 2 金币（跑得越快，剩的地面越多） |
| **动态 · 收集** | 超过 3 颗的部分，每颗额外金币（鼓励全收） |
| **动态 · 无伤** | 全程未掉落 → 额外 1 颗普通魂晶 |

守点 / 限时房同理（草案，需实测校准）：

| 房间 | 基础 | 动态加成 |
|---|---|---|
| 守点 | 敌袭房基准 | 剩余时间 × 系数 + 血量保留 >70% 额外奖励 |
| 限时 | 敌袭房基准 | 剩余秒数 × 3 + 击杀数 × 2 |

### 9.7 这个房间验证了什么

一个房间，同时验证了：

- 骨架（地面分段 + 断桥式缺口）能不能用
- 动词（往右跑 + 跳上去拿）成不成立
- 时间压力（塌陷节奏）爽不爽
- **「出口锁 + 钥匙散落」这个目标设计能不能替代「清怪」**
- 读条拾取（§7.4）在地面塌陷的节奏下是不是真的紧张
- 奖励（速度换收益）有没有吸引力
- 传送规则（§9.4）会不会把玩家送进怪堆

**如果这一个房间不好玩，说明方向错了，此时只损失一个房间的工作量。如果好玩，再把它参数化成「塌陷回廊」房间类型。**

> 设计原则：**先有一个好房间，再从它身上抽象出系统。**
> 现在的生成器是「先有系统，再找玩法」—— 这也是它做出来像装饰的原因。

### 9.8 一个必须解决的死局：玩家被困在平台上

**这是 §9.2 那条「平台之间不连通」的前提带来的直接后果，不解决就不能开工。**

| 触发条件 | 结果 |
|---|---|
| 玩家站在平台上 | 平台不塌，人是安全的 |
| 地面已经塌到他脚下 | 平台被孤立 |
| 手里的魂晶不足 3 颗 | 出口开不了 |
| 平台之间跳不过去 | **玩家永远出不去** |

最后一段预警时的「强制开门」救不了他 —— 门开了，但他走不到门。

**解法：把「掉落」从纯惩罚改成合法的脱困手段。**

```
玩家主动跳进深渊 → 扣血（按难度）→ 传送到「前沿 + 1」
```

零额外系统，而且让掉落有了双重含义：**意外时是惩罚，被困时是出路。** 玩家会慢慢学会「该跳的时候就跳」—— 这本身就是一个值得掌握的小技巧。

#### 怎么让玩家知道「可以跳」—— 不需要新按键

原本这里写的是「按 ↓ 跳下」，但触屏上摇杆向下推大概率已经对应「防御」，会冲突。

想清楚之后发现：**根本不需要新操作。**

> 玩家从平台边缘走出去就会掉下去 ——「跳下」这件事本来就能做，只是玩家不知道掉下去是好事。

所以问题不是「缺一个按键」，是「缺一个认知」。补认知就行：

| 时间线 | 事件 |
|---|---|
| 被困第 0 秒 | 平台边缘出现微光（暗示「这边可以跳」） |
| 被困第 3 秒 | 弹提示：「深渊会把你送回前方 · 跳下去（−12% 生命）」 |
| 被困第 8 秒 | 平台开始崩解：抖动 + 裂缝 + 碎石 |
| 崩解后 2 秒 | 平台碎裂，玩家自动掉落 → 传送到前沿 + 1，**不扣血** |
| 崩解时 | 提示改为「深渊吞噬了这块地面」 |

**顺带解决了一个死锁**：低血被困时主动跳可能摔死，所以给一条「等崩解」的路 —— 不扣血，但要等 10 秒且拿不到速度奖励。于是被困时有一个真选择：

```
跳下去  → 立刻脱困，代价是血
等崩解  → 不扣血，代价是时间和奖励
```

> **区分清楚**：这不是「平台会崩」那个机制（下文的备选方案，已被否掉）。这里的崩解**只在「被困 8 秒」这个极端条件下触发**，此时魂晶要么已经拿了、要么已经拿不到，不会造成额外损失。

> 其他备选（都不采用）：
> - **应急光桥** —— 强制开门时从玩家位置生成临时踏板。需要新视觉与新的临时碰撞体，成本高。
> - **新增互动按钮** —— 违反「不新增 HUD」的红线，且右下已经挤满。

### 9.9 实现约束（不写清楚会翻车的几处）

#### 1. 移动端尺寸 —— 平台高度不能写死像素

最初这里写的是「平台高度约 120 / 220 / 320px」。这是个坑：§2.4 自己说过**手机横屏 `H` 只有 360**，320px 的平台会顶进 HUD 层 —— `战斗2D.js:7216` 那段注释讲的就是这个（「跳上台阶看不见自己」）。

写死像素的问题不只是「某个尺寸下会坏」，而是**换个机型就崩**。所以一律改成比例。

**平台高度必须按视口比例算，复用现有公式，不要写死：**

```js
var topY = Math.max(this.groundY - 350, H * 0.14);   // 与 spawnPlatforms 同款
var lowY = this.groundY - 110;
// 三段平台在 [topY, lowY] 内均分
```

| 视口 | 三段平台高度 | 结果 |
|---|---|---|
| 桌面 H=720 | ≈ 120 / 220 / 320 | 与草案一致 |
| 手机 H≈360 | ≈ 50 / 110 / 170 | 自动压缩，不出屏、不压 HUD |

#### 2. 性能：地面分段不要变成 N 条 TileSprite

现在地面是**一整条** TileSprite（`groundStrip`，`:7455`），只有 1 次绘制。切成 N 段如果各建一条，就是 N 次绘制（标准档 8 次）。

建议：**碰撞体按段销毁，视觉仍用整条 TileSprite + 一个「缺口遮罩」盖住已塌区域**。这样绘制次数不变，塌陷只是移动/缩放遮罩。

#### 3. 验收标准（可直接拿去测）

| 项 | 标准 |
|---|---|
| 通关时间 | 正常玩家 20~35 秒 |
| 掉落传送 | 传送后 0.6s 无敌生效，不连续触发 |
| 死局 | 平台被困时能靠「跳下去」脱困 |
| 手机 | 任意横屏尺寸下所有平台可见、不压 HUD（按比例自适应，不针对机型） |
| 帧率 | 3 敌人 + 满段地面塌陷（最高档 10 段），仍 < 2ms/帧 |
| 锁 | 魂晶不足时走门不开、提示有 3 秒冷却 |

#### 4. 音频：三个新音效，全部程序化合成

| 音效 | 方向 |
|---|---|
| 预警 | 低频抖动 + 碎石噪声，0.8 秒渐强 |
| 塌陷 | 低频轰鸣 + 噪声爆，带一点延迟回声 |
| 开门 | 上行琶音（与现有 `sfx('crystal')` 同调性） |

都在 `AbyssAudio.js` 里加，不引入任何素材文件。

#### 5. 存档与中途退出

塌陷进度是**房间内的临时状态，不写存档**。中途退出 / 刷新 = 这个房间重来。需要确认进房间时有一个自动存档点（现有机制应该在房间切换时）。

#### 6. 图鉴

项目有 10 个分类图鉴，且说明文字与运行时代码同源。新房间类型要进图鉴，说明从 `ROOM_TYPES` 读，不要在 HTML 里另写一份。

#### 7. 与现有系统的联动（容易被忽略）

| 系统 | 影响 |
|---|---|
| 治疗类诅咒（「药水衰减」，`:437` 写明影响魂晶） | 塌陷回廊的魂晶回血会被减半 —— 需要确认这是想要的 |
| 环境效果 15 条 | **不屏蔽**（作者拍板）—— 腐蚀类与塌陷叠加就让它叠，难度由玩家自己扛 |
| 遗物「贪婪」派 | 会给金币加成，速度奖励会被放大，注意别让这个房间变成刷钱点 |
