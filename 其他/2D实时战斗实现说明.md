# 试炼模式 2D 实时战斗（实现说明）

> 本文档记录试炼模式从**回合制文字战斗**改造为**横版实时动作战斗**的实现。
> 旧版"回合制点按钮"玩法已废弃，试炼入口直接进入全屏 2D 战斗。

---

## 一、玩法

### 操作

**键盘（鼠标）**

| 按键 | 动作 |
|---|---|
| `A` / `D` 或 `←` / `→` | 左右跑动 |
| **按住** `W` / `空格` / `↑`，**松开**起跳 | 蓄力跳（按住多久决定跳多高） |
| `J` 或 鼠标左键 | 挥砍攻击（**游侠 / 法师 / 贤者**为各自的专属远程攻击） |
| 滞空时按 `J` / 点击画面 | 近战英雄：**跳劈**（下落攻击，落地产生冲击波）；远程英雄：**空中射击**（自动朝最近的敌人） |
| **按住** `S` / `↓` | **防御**（举盾：正面减伤 75%，举起来的瞬间挡下 = 完美格挡） |
| `R` | **狂怒**（怒槽满后爆发：6 秒内攻速 / 伤害 / 移速全面提升） |
| `K` | **闪避**（翻滚冲刺，消耗体力换取短暂无敌，命中瞬间闪避即完美闪避） |
| `E` | **英雄技能**（主动技能，每层一次；无主动技能的英雄按键无效果） |
| `L` | 喝治疗药水 |
| 走进右方传送门 | 打开房间地图，**点击**发光房间继续深入 |
| 画面左上「文字界面」 | 切到文字界面查看实时数据（战斗暂停），可再切回 |
| 画面左上「商店」 | 打开画面内试炼商店（战斗暂停） |
| 画面左上「退出试炼」 | 二次确认后结束本局并回到经典冒险 |

**触摸（手机 / 平板）**

| 控件 | 动作 |
|---|---|
| 左下虚拟摇杆（拖动） | 左右移动 |
| 摇杆**向上推** | 蓄力跳（推住蓄力、松开起跳），单手也能跳 |
| 右下「蓄力跳」大按钮（按住蓄力、松开起跳） | 蓄力跳，按钮随蓄力由蓝转金 |
| 中下「攻击」按钮 | 挥砍（滞空时按下即为跳劈） |
| 中上「闪避」按钮 | 闪避（按钮在可完美闪避的时机自动变亮） |
| 右侧「防御」按钮（按住） | 防御（举盾） |
| 右侧「狂怒」按钮（满值才亮） | 狂怒爆发 |
| 右侧「技能」按钮 | 英雄技能（每层一次，用过后变暗） |
| 右上「药水」按钮 | 喝药水 |
| 点画面右侧空白处 | 挥砍（单手速攻） |
| 画面左上三个小按钮 | 文字界面 / 商店 / 退出试炼（触摸设备同样可用） |

- 支持**多点触控**：可一边推摇杆跑动一边按住蓄力跳
- 控件按输入方式自动切换：用触摸操作时显示虚拟控件，用鼠标时自动隐藏保持画面干净
- 控件尺寸随屏幕自动缩放（小屏整体缩小，避免遮挡视野与互相挤压）

### 核心机制

- **实时物理**：重力、跑动惯性、跳跃（含**土狼时间**宽限，手感更跟手）
- **蓄力跳**：按住跳跃键时角色**不会起跳**，而是原地蓄力（脚底光圈随蓄力放大、由蓝转金）；
  **松开才跳**，跳跃高度由蓄力时长决定
  | 蓄力 | 起跳速度 | 跳跃高度 | 说明 |
  |---|---|---|---|
  | 轻点（0%） | 520 | 约 80px | 小跳，用于微调站位 |
  | 半蓄力（50%） | 835 | 约 205px | 上中低平台 |
  | 满蓄力（100%，620ms） | 1150 | 约 380px | 上最高平台 |
  - 蓄力期间移动速度减半，可边走边蓄力
  - 蓄满后继续按住会保持满蓄力，不会自动弹出
- **近战挥砍**：起手 → 判定帧 → 后摇的完整动作节奏，带范围判定与击退
- **远程攻击（游侠 长弓 / 法师 法杖 / 贤者 卷轴法杖）**：这三种武器本来就不是用来挥砍的，普攻直接改成专属远程攻击
  - 弹道外观与颜色由 `角色形象.js` 画出（与角色同一套代码），**谁射出来的看一眼就知道**：

    | 英雄 | 招式 | 弹速 | 伤害 | 可命中 | 特性 |
    |---|---|---|---|---|---|
    | 游侠 | 疾风箭 | 780 | ×1.00 | 2 个 | 全场最快、可穿两个，攻击间隔 300ms |
    | 法师 | 奥术弹 | 430 | ×1.15 | 1 个 | **追踪**（每秒 3.4 弧度）×**命中溅射**（半径 58、55% 伤害） |
    | 贤者 | 灵能波 | 400 | ×0.85 | 全部 | 缓慢推出一整道波，**穿透路径上每个敌人**并带 150ms 硬直 |

  - 攻击帧重读作「张弓 / 举杖蓄力 → 释放 → 收招」：长弓帧拉弦搭箭、放弦回弹，法杖帧把宝珠举高再推出
  - **连招也另有四招**（三连散 / 反击箭 / 连珠箭 / 踏地箭，见下文「连招」一节）——
    触发时机与近战一模一样，但招式是远程该有的：扇形铺开、穿透反击、连发点射、落地炸开
  - 落地平射；**滞空时自动朝最近的敌人**射击（跳着打也打得中），不再有近战下落攻击
  - 判定框贴可见弹体：比的是 body 而不是 64px 贴图框，不会「还没碰到就炸了」
  - 游侠的主动技能「精准射击」改用**他自己的箭矢**外观（放大 1.35 倍），与普攻同一套视觉语言
- **骷髅骑兵：近战 + 概率掷矛**：中远距离（96~380px）每 1400ms 掷一次判定，**35% 概率**改掷长矛
  - 贴脸（<96px）必定近战 —— 贴脸掷矛不合理；掷矛期间手里会**亮出一支矛并定在蓄力帧**，还有专属起手音效
  - 长矛走**抛物线**（自算重力 340，落点按玩家当前位置解算，不做提前量），伤害 ×1.1；落地或撞墙后**插在地上** 900ms 再消失
  - 全程看得见、闪得掉：不预判移动，所以「看到矛 → 按 `K` 闪开」永远有效
- **镜像怪自动切换攻击方式**：玩家是远程英雄时，它改成**同一种弹道 + 镜像紫**、远距离放风筝（射程 330 / 保持 200）；
  玩家是近战英雄时保持贴身近战。名字也会跟着变（「镜像怪 · 疾风箭」/「镜像怪 · 奥术弹」/「镜像怪 · 灵能波」）
- **帧率随动作数量走**：招式多的怪物动画帧率更高（骷髅骑兵 / 镜像怪 攻击 15fps，冲锋与首领单位 14fps，其余保持 10fps），
  倍率写在形象表的 `animRate` 里 —— 详见 [角色形象设定.md](角色形象设定.md)
- **跳劈（下落攻击）**：**滞空时**挥砍自动变成跳劈，角色高速下坠（960px/s），刀光跟随；
  - 下坠途中命中敌人：**1.9 倍**伤害，并带额外击退与震屏
  - 落地瞬间产生**范围冲击波**（半径 130px）：未被下坠斩命中的敌人补一次 **1.15 倍**范围伤害，
    同时伴随金色冲击环、扬尘与重击音效
  - 同一敌人一次跳劈只结算一次（下坠命中后落地不再重复计伤），两次跳劈之间有 360ms 冷却
  - 小跳也能触发，是补刀、清群、突围的主力技巧
- **闪避（翻滚冲刺）**：按 `K`（触摸为「闪避」按钮）向朝向翻滚，消耗 **30 点体力**换取 **320ms 无敌帧**
  - 冲刺 520px/s、持续 260ms、收招 110ms，可**取消攻击后摇与蓄力**；空中闪避会把下坠速度压到 30% 并逐帧衰减（近滞空）
  - 表现：团身帧 + 青蓝**残影**拖尾 + 柔和虚影（无敌期闪烁区间 0.44~0.84，角色仍看得清）；体力不足时不能闪避（体力条转红 + 飘字）
  - 体力条在**危险窗口**（附近敌人前摇 / 冲锋，或有弹幕逼近）会亮起金色呼吸光 —— 意思是「现在闪，可以完美」
- **完美闪避**：在敌人攻击**命中的瞬间**闪避成功（闪避起手 **150ms** 内挡下伤害）即触发
  - 奖励：**体力全额返还** + **震开并定身 0.9s** 半径 175px 内的敌人 + **锐利 3 秒**（伤害 ×2.2 且强制暴击）+ 化解 150px 内逼近的敌方弹幕
  - 表现：金色冲击环 + 屏幕金色闪光 + 「完美闪避!」飘字 + 专属音效；体力条右侧显示「锐利 N.Ns」倒计时
  - 判定只在**真实挨打**时结算（无敌帧挡下了伤害才算），时机不对就只剩无敌、拿不到奖励
- **体力**：上限 100、停手 420ms 后以 58/s 回复；青蓝细条位于生命条正下方，数值与「锐利」倒计时并排显示
- **防御（举盾 / 完美格挡）**：按住 `S` / `↓`（触摸为「防御」钮，按住生效）
  - 文字模式的「防御」是一次 **+3 护盾**，实时里做成一个**姿态**，并保留那个 3 的数字（给完美格挡）
  - **正面减伤 75%**（只吃 25% 伤害），**背后不减伤**（飘字提示「背后!」）—— 所以要转身顶着打
  - 举盾**持续消耗体力 14/s**，与闪避共用同一个资源池：**闪 or 挡** 是个真抉择
  - 体力低于 12 自动放下，且要回到 **30** 才能再举（迟滞，避免一放一举地抖；实测 150 帧只切换 2 次）
  - 举盾时**移动速度 ×0.42**、**不能起跳**；按 `J` 会先收盾再攻击（不阻断操作流）
  - **完美格挡**：抬盾 70ms 成型后、**200ms 内**挡下正面攻击 → 完全免伤 + 震开攻击者（定身 0.7s）+ **+3 护盾** + 化解 130px 内弹幕 + 打开 **1.2 秒盾反窗口**
  - 守护者的被动「坚壁防御」接在这里：**每次完美格挡额外 +2 护盾**（与「闪避成功 +2 护盾」对称）
  - 一直举着盾**拿不到完美格挡**（只减伤），奖励只给时机不给长按 —— 实测举稳 350ms / 650ms 后挨打都只有减伤
  - 挡下来的那一下不再把角色打得后仰，且只给 260ms 短缓冲（正常挨打是 700ms）—— 举盾不是无敌，一直举着照样会被磨
- **狂怒（实时重做）**：血条下方第三条资源槽（金色），与体力（青蓝）并排
  - **为什么重做**：文字版试炼的狂怒是「上限 10，攻击/防御/药水各 +1，满后手动爆发固定 10~14 伤害」。
    实时挥砍的频率是回合制的几十倍，10 格会瞬间满；固定伤害在攻击力几十上百的实时尺度下也读不出来
  - **现在是什么**：一管**进攻资源**，上限 **100**，攒满后按 `R` 进入 **6 秒狂怒状态**
  - **攒怒来源**：命中敌人（普通 +2 / 精英与镜像 +3 / 首领 +4）· 连招命中额外 +3 ·
    完美闪避与完美格挡各 +6 · 击杀 +5 · **挨打 +4**（逆风也能翻）
  - **举盾与走位不攒怒** —— 它奖励的是「打得凶」，正好和奖励「会躲」的体力形成一组对立
  - **狂怒状态**：攻击间隔 ÷1.35 · 伤害 ×1.5 · 移动速度 ×1.25 · 不再被后仰打断；
    表现是身周金环 + 脚下持续升起的怒焰火星 + 屏幕闪金
  - **代价**：受到的伤害 **+15%**（狂暴而不设防）—— 保留原版「亲手按下爆发」的那个时刻，
    但把一次性伤害换成一段有得有失的状态
  - **只手动触发**：满怒后一直存着，按 `R` 才爆发（2.8.3 去掉了原来「满值 12 秒没按就自动
    爆发」的兜底 —— 自动触发会在玩家不想动手的时候把资源吞掉）；狂怒期间不再攒怒（不能自己喂自己）
  - 商店的「狂怒燃料」在 2D 里**可直接使用**：买完立刻充满怒槽（宿主通过 `fillFury()` 回写）
- **图鉴（画面内，`图鉴` 胶囊按钮就在商店右边）**：全屏面板，六个分页，**只讲 2D 试炼里真实成立的规则**
  - **英雄**（9）：形象直接用 `角色形象.js` 生成的那张精灵（待机 + 出手两帧并排），
    配「普攻 / 主动技能 / 被动 / 装备 / 体型 + 一句打法」
  - **怪物**（10）：形象、层级、行为、生命攻击（含每层 +20%/+15%）、速度、攻击距离与前摇后摇、
    动画帧率倍率，以及每只的**特殊招式说明**（镜像怪照玩家、骷髅骑兵掷矛、死灵法师保持距离…）
  - **技巧**（9）：蓄力跳（含蓄力对照表）/ 跳劈 / 空中射击 / 闪避 / 完美闪避 / 防御 / 完美格挡 / 药水 / 狂怒，
    每条都写清按键、判定窗口与真实数值
  - **连招**（5）：横扫 / 盾反 / 突进斩 / 落地斩 + 连招规则（优先级、窗口、打断，以及**远程那一套**：三连散 / 反击箭 / 连珠箭 / 踏地箭 —— 每条都分「近战」「远程」两行写清）
  - **诅咒**（11）与**环境**（16）：**左边写文字模式的原描述，右边写它在 2D 里实际变成什么**，
    并标注哪一条当前正在生效（金点）、当前数值是多少
  - 内容全部从运行中的表现算（`TRIAL_CURSES` / `WORLD_ENVS` / `ENEMY_TYPES` / `角色形象.LOOKS`），
    **改数值不会让图鉴说谎**；桌面为「左栏词条 + 右栏详情」，窄屏自动切成单栏分页
- **诅咒（文字版试炼的同一份池子）**：每深入一层随机获得一条，全池不重复（与文字界面共享同一份数据）
  - 「每回合」统一译成 **每 5 秒一次的腐化脉冲**（右上角有倒计时，最后 1.5 秒转红）
  - 两条会永久削人的（虚弱 = 攻击 -1、迟钝 = 闪避 -5%）改成**同一房间内累积、清空房间后恢复**
    —— 否则一层下来角色就废了
  - 逐条实时化：脆弱 -2 盾 / 护甲腐蚀 -1 盾 → 脉冲扣盾；生命流失 -1 生命（无视护盾）→ 脉冲扣血；
    易伤 +2、荆棘诅咒 +1 → 每次受击加伤；吸血反噬 → 每次命中自身 -1 生命；
    药水衰减 → 所有治疗减半；贪婪 → 击杀与宝箱点数减半
- **环境效果（经典模式的同一套池子，15 条全部接入）**：对**双方同时**生效，是压力也是机会
  - **节奏：每进入一个房间重掷一次**（不是每层一次）。2D 的一层是 8 个房间的实时战斗，
    若只在深入下一层时重掷，一局下来只碰得到三五个，池子里另外十条永远轮不到 ——
    经典模式一层很快，所以同样 15 条显得「好多」，2D 会显得「就那么几个」，原因就在这里
  - **发牌用袋抽而不是纯随机**：15 条洗成一叠逐个抽，抽空了才重洗（`refillRealtimeEnvBag()`），
    所以**一局之内每条都会轮到、同一条不会在洗完一叠之前重复**（实测 15 抽 = 15 个不同）
  - **袋子在宿主手里**（`试炼程序.js`），掷名字 → 交给经典模式的 `generateEnvironmentEffect(floor, difficulty, forceName)`
    按当前层数与难度算数值 → 回传 2D。文字界面、图鉴、2D 画面读到的永远是同一份
  - 换层（击败层主）时**名字保留、数值按新层数重算**，进下一个房间时再换新的一条
  - 攻击类：荆棘之地（命中敌人也自伤 x% 当前生命，敌人打你也反噬它）· 虚弱之雾（双方伤害 ×(1-x)）·
    能量涌动（双方伤害 ×(1+x)，脉冲自伤 y% 最大生命）
  - 防御与恢复：治疗抑制（所有治疗打折）· 护盾崩坏（脉冲掉 x% 护盾）· 能量导管（脉冲给 x% 最大生命护盾）
  - 概率类：闪避领域（敌人有几率闪开你的攻击，飘字「闪开」）· 幸运（双方暴击率 +）·
    暴击共振（双方暴击伤害 +）· 连击风暴（你的连击加成 +，敌人命中后有几率立刻再打一下）
  - 生死类：死亡回响（每击杀一个敌人扣 x% 最大生命）· 吸血诅咒（双方命中回血）·
    缓慢凋零（脉冲双方掉 x% 生命上限）· 时间扭曲（脉冲双方掉 x% 当前生命）· 厄运（双方受到伤害 ×(1+x)）
  - **HUD：右上角「房间 · 已探索」正下方，自上而下 = 诅咒胶囊 → 环境面板 → 腐化脉冲倒计时**
    （两块面板同为 302×自适应高，窄屏自动收窄；两者是**同一套胶囊语言** —— 菱形标记 + 小标签 + 内容）
    - **诅咒胶囊**（红）：标签「诅咒」+ 名称列表（换行自动加高）
    - **环境面板**（紫）三行：`本房间环境` + 环境名 + **当前数值**（金色）／**它在这套实时战斗里实际是什么**
      （由 `WORLD_ENVS` 的 `rt` 文案代入真实数值算得，例如「双方受到伤害 ×(1+21.0%)」）
    - 诅咒隐藏时环境面板自动顶到第一位；每块的高度都按内容现算，下面的依次让位
    - 换环境时环境面板闪一下（描边 + 菱形标记加亮 1.2 秒后衰减）并播 `env` 音效；
      腐化脉冲结算时**诅咒胶囊同样闪一下**，屏幕中间还有一条横幅（见下）
    - **必须挂进 `scrollFactor(0)` 的 `hud` 容器** —— 只写 `this.add.text` 的话它会跟着镜头滚，
      走到房间中段就飘出屏幕（见缺陷 26）
    - **窄屏让位**：宽度不足时左列（属性面板 + 英雄技能 + 常驻按钮 + 目标面板）与
      右列（诅咒 / 环境）会横向撞上 —— 这时整列下移到左列之下（420px 实测：诅咒 297、环境 352），
      宁可往下走也不叠字（见缺陷 31）
    - 顺序经过**帧缓冲像素核对**（不是只看坐标）：1384 宽下红色胶囊占 y 99~146、紫色环境面板占
      y 154~231、脉冲 235~245，红色确实在紫色上方

- **左侧 HUD 的竖排三层**（自上而下，互不重叠）：
  `生命 / 体力 / 狂怒` → `攻 暴 闪 盾 棘 吸 连 斩`（属性面板，窄屏自动折行）
  → **英雄技能胶囊**（显示技能名，用过后变「XX · 已用」）→ `文字界面 / 商店 / 图鉴 / 退出试炼`
  → 目标敌人属性面板。层与层之间留 5~6px，全部由 `statPanelMetrics()` 按**当前宽度**现算
  （不读上次布局留下的值，否则开局宽度为 0 时会算错）

  | **三连散**<br>游侠「三连射」/ 法师「三重奥术」/ 贤者「三重灵波」 | 地面连按 `J` 第 3 下 | 一次射出 3 支：**场上有多个敌人时一支锁一个**（真·全覆盖），只剩一个时退回按 ±12° 扇开；主目标满伤、其余两支 ×0.68 |

  - 招式名按武器分开（弓 / 法杖 / 卷轴各一套，写在 `角色形象.RANGED[id].chains`），

  - 举盾会打断连招计数；四个窗口互相独立，各自消耗，不会叠成一次超大伤害
  - 窗口开着时主角头顶提示「接 J · XX」（远程显示的是远程招式名，连打提示为「连射 1/2」而不是「连斩 1/2」）

  - 文字模式是回合制数值（+6 护盾、「下一次攻击 +5 伤害」），2D 里按实时战斗的尺度重做，技能名与语义与英雄图鉴一致：

    | 圣骑士 | 神圣审判 | 立刻 +8 护盾并回复 4 点生命 |

    | 英雄 | 文字模式被动 | 2D 等价效果 |

- **专属角色形象**：9 位英雄与 13 种怪物各有独立的一套精灵（体型 / 头饰 / 武器 / 配色四要素组合），

- **专属远程攻击**：游侠 / 法师 / 贤者的普攻是远程（箭矢 / 奥术弹 / 灵能波），弹药同样由代码绘制、按角色配色，
  镜像怪照玩家切换近战或远程，骷髅骑兵在近战基础上概率掷矛 —— 见上方「核心机制」与 [角色形象设定.md](角色形象设定.md)
- **全屏画面**：进入试炼即铺满视口，回合制文字面板全部隐藏
- **房间地图推进**：每个房间就是一个横版关卡；清空房间 → 右方出现传送门 → 走入即**打开地图**，
  点击相邻的发光房间继续深入；击败 **Boss 房间**的层主后深入下一层（重新生成地图，敌人随层数增强）
- **属性面板**：血条下方常驻显示攻击 / 暴击 / 闪避 / 护盾 / 荆棘 / 吸血 / 连击 / 斩杀，未生效的项自动淡出
- **敌人属性显示**：每个敌人的**头顶血条 + 名字与攻击力标签**（受伤后、或最近目标、或精英/Boss 常显；
  血条为圆角渐变条，名字用层级色、攻击值用次要色）；画面左侧「目标面板」常驻显示**最近敌人**的
  名字、层级、生命、攻击、速度与行为类型（追击 / 冲锋 / 飞行 / 远程 / 首领）——详见第九节设计系统
- **环境主题**：按难度切换背景星雾与火星（简单·白星光 / 普通·蓝星光 / 困难·暖色 / 地狱·红色火焰上升）
- **平台高度**按满蓄力可达范围生成（离地 110~350px），保证所有平台都跳得上去
- **平台上不再空着**：每段平台有 **62%** 概率生成一颗**魂晶**（发光菱形，走近拾取），按当前状态给最缺的那样：
  - **低血（<60%）** → 回复**最大生命的 25%**（至少 8 点）；否则 **点数 +（3 + 层数）** 或 **护盾 +6**
  - 数值对标游戏里已有的量级（护盾 +6 = 战吼；点数 ≈ 宝箱的 1/3），**保证一眼看得见**
    （第一版给的「护盾 +1」在「护盾条 = 护盾 ÷ 生命上限」的画法下只占 0.5%、约 1px，等于没给）
  - **判定与提示**：拾取判定 46×62（原来 34×44，落在平台边缘会漏）；靠近 140×170 内魂晶会**放大 1.45 倍并发亮**，
    下方出现「拾取」小字 —— 玩家不用猜这东西能不能碰
  - **保底**：每个房间**最低的那段平台一定有魂晶**（实测平台离地 131~356px，越高的越要满蓄力；保底那颗 138~224px，跳一下就到）
  - 拾取有专属音效 + 双环爆发 + 四散火星 + 19px 彩色飘字（颜色区分三种收益）
  - 实测 8 个房间：每房 1~4 颗，保底命中率 8/8
  - 战斗房里还有 **0~2 个远程敌人站在高台上**（死灵法师 / 骷髅骑兵，名字带「· 高台」）——
    平台从「路过的地形」变成「必须处理的战术地形」（实测 10 间房 7 只）
- **宝箱 / 祭坛房间短了**：拿完东西就走，房间只留 **1.14 屏**（对比普通房间 2 屏），全程跑动从 **10.5 秒降到 5.3 秒**；
  平台也只摆 2 段，不挡路

### 房间地图系统

每层生成一张**分支网格地图**（入口 → 两列分支 → Boss），房间类型决定房间里有什么：

| 房间 | 标记 | 颜色 | 内容 |
|---|---|---|---|
| 入口 | ⌂ | 白 | 本层起点，少量敌人 |
| 普通 | × | 灰 | 普通敌人把守（数量随层数增加） |
| 精英 | ★ | 蓝 | 精英守卫 / 死灵法师 ×2 + 杂兵，点数更多（精英 5 点 / 杂兵 2 点） |
| 镜像 | ◇ | 紫 | 镜像怪，**属性复制玩家**（血量 = 攻击×3 + 最大生命×45%，攻击 = 攻击×0.6） |
| Boss | ☠ | 红 | 层主 / 影之皇 + 护卫，击败后 **+8 点**并深入下一层 |
| 宝箱 | ▣ | 金 | 无战斗，走近开箱 → 点数 +（8 + 层数×3），45% 额外获得药水 |
| 祭坛 | ✚ | 青 | 无战斗，走近祈祷 → 回复 35% 最大生命（满血时改为 +3 点） |

**地图交互**：
- 当前房间：白色边框 + 金色呼吸光圈
- 可前往房间：整体呼吸放大 + 鼠标手型，连线高亮为绿色
- 已通过房间：右上角绿色 ✓
- 鼠标悬停可前往房间：底部显示房间名与说明
- 点击可前往房间即进入；地图打开期间战斗物理暂停（不会被打）
- 每层保底至少有一个真正的战斗房间，Boss 房间固定在最右列

## 二、架构

```
深渊回廊/
├── vendor/phaser.min.js   # Phaser 3.80.1（本地引入，无网络依赖）
├── 试炼2D.js              # 【核心】实时战斗引擎
├── 试炼程序.js            # 集成层：启动 / 结算 / 回退
├── 主程序.js              # 设置项与设置同步
├── 主样式.css             # 全屏战斗布局样式
└── 主界面.html            # 引入脚本 + 2D 舞台容器
```

### 分层职责

| 层 | 职责 |
|---|---|
| `试炼2D.js` | 引擎、场景、玩家控制器（挥砍 / 跳劈 / 蓄力跳）、物理、敌人 AI、**房间地图生成与渲染**、HUD、属性面板、**敌人属性显示**、特效、环境主题、**画面内界面（死亡结算 / 商店 / 退出确认）与视图切换** |
| `试炼程序.js` | 进入/退出试炼、属性与难度注入、战斗结算、**文字视图渲染、画面内商店的数据与购买桥接、试炼点数双向同步**、引擎不可用时回退 |
| `主程序.js` | 设置面板项 → 同步给引擎 |

**引擎不参与任何养成/元游戏逻辑**，只负责实时战斗；点数、遗物、解锁等仍由原有系统管理。

## 三、对外接口（`window.试炼2D`）

### 生命周期

| 方法 | 说明 |
|---|---|
| `init(container)` | 创建 Phaser.Game（懒加载，仅首次；含热刷新场景引导兜底） |
| `startRun({heroName, points, player, difficulty})` | 开始一局；`difficulty` 决定环境主题；场景未就绪时自动缓存 |
| `stopRun()` | 结束当前战斗（静默收尾，不触发结算事件） |
| `show()` / `hide()` | 显示 / 隐藏画布（隐藏时暂停循环省性能；显示时自动校正画布尺寸） |
| `enter()` / `exit()` | 进入 / 退出试炼 |
| `destroy()` | 销毁引擎 |
| `isBooted()` / `isReady()` / `isEnabled()` / `available()` | 状态查询 |

### 运行时

| 方法 | 说明 |
|---|---|
| `syncPlayer(stats)` | 注入/更新玩家属性（商店、遗物生效；只同步派生属性，不动当前生命） |
| `pauseRun()` / `resumeRun()` | 切到文字界面时暂停本局 / 切回 2D 时恢复 |
| `snapshot()` | **实时战况快照**：层数、点数、击杀、通过房间、存活时间、房间、主角全属性、敌人列表（含层级/行为/攻速） |
| `setPoints(n)` | 直接改写当前试炼点数（文字商店购买后回写，保证两边一致） |
| `openShop()` / `closeShop()` | 直接开关画面内商店 |
| `setBridge({exit, toggleView, shopData, shopBuy})` | 注册宿主桥接（试炼文字逻辑） |
| `press(action)` | 模拟操作（`attack` / `potion` / `jump` / `charge` / `jumpFull` / `map` / `enterRoom` / `clear` / `shop` / `shopClose` / `shopTab` / `shopNext` / `shopBuy` / `shopClick` / `clickHud` / `clickDeath` / `clickShop` / `clickConfirm` / `kill`），供自动化测试 |
| `debug()` | 运行状态快照：楼层、点数、击杀、难度/环境、当前房间、地图、房间目标、**商店与死亡面板状态、目标敌人、界面按钮列表**、敌人状态、玩家位置/速度/是否落地/是否跳劈等 |
| `getGame()` | Phaser.Game 实例（调试） |

### 事件

| 事件 | 载荷 |

### AI 状态机

```
巡逻 patrol ──察觉(视野内且高度接近)──> 追击 chase ──进入攻击距离──> 起手 windup
   ↑                                     │                              │
   └──────── 失去目标 ────────────────────┘                    判定 → 后摇 attack
                                                                       │
蓄力冲锋 charge（charger）/ 远程射击（shooter）/ 跳跃砸地（boss，周期性）
```

- **巡逻**：左右走动，遇墙转身，**悬崖前自动转身**（不会掉下去）
- **追击**：朝玩家移动，被墙挡住时起跳
- **视线判定**：水平距离 < 感知范围 且 高度差 < 240
- **受击硬直**：中招后短暂失控并被击退

## 七、容错

引擎不可用时自动**回退到原有回合制文字界面**（`startRealtimeTrial()` 返回 false → 走 `bindLegacyTrialButtons()` 路径），保证任何环境下都能玩。

降级链（从好到坏，逐级尝试，详见第十二节）：

| 层级 | 条件 | 结果 |
|---|---|---|
| 1 | WebGL 探测通过 | `type: WEBGL`，桌面 high/medium；触摸设备封顶 medium |
| 2 | WebGL 探测不通过 **或创建失败** | 换 `type: CANVAS` 重试一次，**自动降为 low 画质**（Canvas 是纯 CPU 光栅化） |
| 3 | 两种渲染器都失败 | 回退文字模式，画面内显示**具体原因** + 「重试 2D 模式」按钮 |

音频、粒子、飘字任一模块缺失或被关闭时均自动降级，不影响战斗与结算。

## 八、画面内界面（死亡 / 商店 / 视图切换 / 退出试炼）

死亡与商店都在 **2D 画面内**完成，不再把玩家推回文字界面；文字界面改为**随时可切换的查看视图**。

### 画面常驻按钮（左上，层级高于所有面板）

统一控件 `craftButton()` 渲染，形态与配色**直接对齐主界面既有设计语言**（`主样式.css`）：

- 形态取 `.trial-ghost-btn` 的**全圆角胶囊**（画面之上的常驻控件），面板内的动作按钮取 `.trial-action-btn` 的 4px 圆角
- 三枚胶囊各有**作者手绘图标**（`rt_ico_text / rt_ico_shop / rt_ico_quit`，16×16 同笔宽）+ 语义色：

| 按钮 | 图标 | 语义色 | 行为 |
|---|---|---|---|
| 文字界面 | 三行文字块 | 青 `#5fd0e0`（视图类，对齐幽灵按钮） | 切到文字视图（战斗暂停），再次点按回到 2D |
| 商店 | 钱袋 | 金 `#f0d06a`（经济类，对齐顶栏回合/点数） | 打开画面内试炼商店；已打开时胶囊进入「生效」态，再点即关闭 |

- 按钮宽度按文字宽度自动测量（`文字宽 + 2×内边距 + 图标 + 间距`），中英文与不同字号都不会挤压或溢出

### 死亡结算（画面内）

- 死亡后先播死亡动画，约 0.6s 后淡入结算面板（模态面板：18px 圆角 + 白 12% 细描边，对齐 `.modal-content`）

### 画面内商店

- **数据与文字商店完全共用**：`buildTrialShopCatalog()` 统一目录，`purchaseTrialShopItem()` 统一购买入口，
  价格、递增、限购、已拥有状态两边永远一致
- 三个分组标签页：**常驻强化**（8 项，可重复购买价格递增）/ **遗物解锁**（9 项）/ **特殊商品**（2 项）

- 关闭后按来源返回：死亡结算 / 地图 / 战斗
- **击败层主后自动打开商店**，关闭后再进入地图选房间（对齐旧版"打完 Boss 逛商店"的节奏）

### 文字界面（实时视图）

- 切到文字界面时 2D 场景**暂停**（`scene.pause()`），画布隐藏、体力消耗归零

### 血条组件 `createMeter()`

所有血条（主角生命 / 护盾 / 敌人头顶 / 层主 / 目标面板）用同一个组件，参数只有高度与渐变：

- **纹理按尺寸 1:1 生成并缓存**（宽度向上取 8 的倍数），所以圆角端点不会因横向缩放而失真；
  轨道与填充各一张纹理，同一尺寸只生成一次（实测 300 帧 + 30 次换房后纹理数量恒定不增长）
- **裁剪驱动**：填充用 `setCrop` 揭露渐变的前 `pct` 段，因此渐变**锚定在整条轨道上**——
  血越少金色越先消失，只剩玫红即濒危（比 CSS 的「渐变随填充压缩」更能读出危险度）
- **缓动与残影**：数值变化按 CSS `transition: width .4s ease` 的节奏补间；掉血时残影留在原处再缓慢收起，
  治疗时残影直接跟上，不会出现空洞
- **濒危脉冲**：生命 ≤28% 时填充做呼吸式明暗（替代旧的硬闪红），主角血条另带一层随血量明暗的柔和辉光
- **极低血量**：填充窄于圆角半径时切换为单个圆头（懒创建的对象），不会出现方角碎片
- 静止帧只做位置同步，实测 `paintMeter` 0.6µs/次、`updateMeter` 1.55µs/次，5 个敌人的血条开销 <0.02ms/帧

### 敌人属性显示（重做）

- **头顶血条**：宽度贴合精灵本体（`displayWidth×1.15+8`，32~76px，不再固定比精灵宽一截）、圆角 3.5px、
  渐变 + 掉血残影；只对**屏幕内**且（最近 / 受伤 / 精英以上）的敌人显示，屏幕外的自动隐藏
- **头顶标签**：两段式 —— 名字用**层级色**（普通 `#e8909c` / 精英 `#7ab8ff` / 镜像 `#c79aff` / 首领 `#ff8a7a`，
  与地图图例同源）、攻击值用次要色 `#a8bce0`；用**柔和阴影**替代旧的 3px 黑描边，压住战场杂色
- **目标面板**（最近敌人）：内嵌卡片 + 标题分隔线，标题行为「层级色名字 + 层级胶囊 + 生命数值」，
  中间是血条，底部是属性胶囊 `[攻 N] [速 N] [行为]`；内容变化才重排（逐帧只做位置同步）

### 全局字体修正

Phaser 的 `Text` 默认字体是 **Courier**，导致画面内数字与主界面的微软雅黑不一致。现在在引擎初始化时统一给
`GameObjectFactory / GameObjectCreator` 的 `text()` 补默认 `fontFamily`，一处生效、无需逐个样式手写。

### 开发中修复的关键缺陷

1. **缺失物理碰撞器**：玩家无限下落 → 补 `collider(hero, solids)`、`collider(enemyGroup, solids)`、`collider(hero, enemyGroup)`
2. **启动条件死锁**：`isEnabled()` 依赖 `available`（初始化后才为 true），导致永不启动 → 改为只看设置开关
3. **楼层推进卡住**：过渡 tween 的 `onComplete` 未触发 → 改为**同步切换楼层** + 相机闪白过渡
4. **存档恢复路径不启动战斗**：该路径不经过 `startTrial()` → 在渲染同步中补自动启动
5. **地图房间点不动**：房间方块放在 `Container` 里且 `scrollFactor=1`，命中检测会把屏幕坐标当世界坐标再加上相机偏移，导致永远判不中 → 给房间方块 `setScrollFactor(0)`（渲染不变，命中恢复）
6. **飘字/粒子频繁创建销毁**：命中密集时产生 GC 抖动 → 改为对象池 + 发射器池（逐帧驱动，不再 tween/destroy）
7. **地板逐块渲染**：长房间 46+ 个地板精灵、40+ 个平台精灵 → 碰撞体不可见 + TileSprite 整条铺满
8. **热刷新后场景永不入队**：Phaser 在内置纹理已被解码缓存时，会在场景管理器注册 READY 回调**之前**发出 READY，
   `_pending` 为空导致 `bootQueue()` 什么都没创建 —— 现象是刷新后全屏黑屏、试炼打不开。
   已加**引导兜底** `ensureSceneBooted()`：检测到「引擎已在运行但场景列表为空」时手动补齐队列（多次延时重试）
9. **隐藏舞台后画布被压成 0×0**：`display:none` 期间父容器尺寸为 0，Phaser 的 RESIZE 模式把画布改成 0×0，
   再次显示时所有界面坐标都按 0 计算（实测商店标签宽度曾变成 −14px）→ 新增 `fixCanvasSize()`：
   显示时按父容器实际尺寸 `scale.resize()`，并给 `onResize` 与各面板构建加最小尺寸守卫
10. **测试辅助函数作用域坑**：`press('clickDeath', 'shop')` 在 `filter` 回调里读 `arguments[1]`，拿到的是数组下标而不是动作名 → 改为先取出参数变量
11. **倒下瞬间血条停在满格**：`updateMeters()` 原本排在 `if (!this.running) return;` 之后，主角一死就不再补间，血条会以满格状态被结算面板盖住 → 移到该守卫之前（结算动画期间血条照样落到真实数值）
12. **窄屏血条数值脱节**：生命数值横坐标由 `layoutHudButtons()` 计算，但重排后没有刷新文本位置，窗口变窄时数值仍停在旧位置（实测 420 宽时数值距条尾 90px）→ 重排末尾补 `refreshHud()`
13. **常驻胶囊「看得见点不动」**：胶囊层级（2600）高于所有面板，但命中判定排在面板之后，商店/死亡面板打开时点击胶囊会被面板吞掉 → 命中与绘制层级对齐（确认框仍为严格模态）
14. **闪避无敌把角色闪「没」了**：无敌闪烁沿用受击逻辑（0.10~0.80），闪避时角色几乎看不见、接着操作会跟丢 → 拆成两档：闪避用柔和虚影（0.44~0.84）、受击无敌保持快速闪烁；同时体力不足时不再亮起「可完美闪避」的提示光
15. **清空房间后传送门失效、房间卡死**：走进传送门时 `portalOpen` 被置 false，若玩家在地图上选择关闭，传送门不会恢复，而 `checkFloorClear` 只在击杀 / 开启房间目标时才会被调用 → 玩家被困在已清空的房间里出不去。修复：关闭地图时按「房间是否已清空」恢复传送门（并给 0.5s 宽限，避免站在门口又被弹进地图）+ 主循环每 0.5s 自愈检查 + 传送门对象丢失时补建 + 敌人被打飞 / 坠落出关卡范围时判定为脱离战斗（否则房间永远剩一个打不到的敌人）
16. **专属形象被 64px 单元裁切**：多款头饰（尖帽 / 角冠 / 鹿角 / 顶羽）与几乎全部武器都探出了单元上沿，长柄武器更是顶穿——被 `generateTexture` 静默裁掉。修复：头部整体下移、手部位置与武器长度按可用空间重算、长柄武器改斜持、两位首领改为「宽而不高」；并加了一道遍历全部帧的越界检查
17. **弹丸比视觉早 40px 判中**：命中判定原本用 `getBounds()`（64px 贴图框），而判定框（body）只有 22~34px —— 奥术弹会在离敌人还有 49px 时就炸开，看着像「没碰到就炸」，法师的溅射也因此打偏（实测邻居 -11 而主目标 0）。修复：改为 body 对 body 判定（复用两个矩形，不逐帧 new）；溅射中心从「弹丸擦到敌人的位置」改为**被打中那只的中心**
18. **弹丸出手角度用过期瞄准点**：`tryRangedAttack` 先算瞄准点，90ms 后才 `fireShot`，而枪口位置取的是 90ms 后的主角位置 —— 这 90ms 里主角落地或位移，弹丸就会歪着飞（实测游侠平射变成 -25° 斜射，直接飞过一排敌人）。修复：瞄准点在离手那一刻**重算**
19. **弹丸越界判定跟着视口走**：`p.y > scale.height + 240` 用的是画布高度，而关卡坐标是独立的一套（部分房间地面在 y<0、部分在 y≈677），窗口一改判据就失真 → 改为关卡相对判据 `groundY + 800`
20. **改帧率不生效（热刷新）**：怪物动画的复用判断只比纹理 key，不比帧率 —— 调整 `animRate` 后再次进入房间会复用旧动画，帧率改动看不到。修复：复用条件补上 `frameRate` 比对
21. **宝箱 / 祭坛房间长得和战斗房一模一样**：房间长度本来写了 `base -= 320` 的缩短量，但紧接着的 `Math.max(W * 2, base)` 用「两屏」把它整个吃掉了 —— 宽屏下两种房间都是 2768px，玩家在空房间里跑半天。修复：非战斗房间改用 **1.14 屏**的独立下限（`W*0.85`）与基准（`W*0.95 + 260`），并把平台从 4 段降到 2 段
22. **狂怒在实时里失效**：文字版是「上限 10、每次行动 +1、手动爆发固定 10~14 伤害」，实时挥砍频率高几十倍 → 10 格瞬间满；固定伤害在攻击力几十上百的尺度下读不出来。重做为「上限 100 的进攻资源 + 满值后 6 秒狂怒状态」，并把攒怒来源从「行动」改成「进攻行为」（见第十一节说明）
23. **环境效果载荷在测试里被静默丢弃**：验证脚本的包装函数只转发两个参数，`setCurses(name, values, env)` 的第三个参数（环境对象）被丢掉，导致 7 条环境效果全部"看起来没生效" —— 排查后确认是测试脚手架的缺陷，产品代码本身正确（改用直接调用后逐条精确命中期望值）。记录在此以免下次误判
24. **魂晶「加成并未生效」**：机制是通的（点数/护盾/生命都确实加到了结算里，飘字也在报），真正的毛病是**收益小到看不出来**：
    第一版是「点数 +2 / 护盾 +1 / 生命 +4」，而护盾条按「护盾 ÷ 生命上限」画，**+1 护盾 = 条体的 0.5%（约 1px）**，回血 4 点在 200 血里也读不出来；再加上判定框偏紧（34×44，落在平台边缘会漏判）、没有"这东西能碰"的提示，
    玩家体感就是"捡了没反应"。修复：收益放大到游戏里已有的量级（护盾 +6 = 战吼、点数 3+层、低血回 25% 最大生命）、判定放宽到 46×62、靠近时魂晶放大发亮并出「拾取」提示、每个房间最低那段平台保底一颗
25. **顺手改出来的同类错误**：修魂晶时把 `lowHp` 的阈值写成配置字段 `CRYSTAL.lowHpAt` 却忘了在配置表里定义 → `h.hp < h.maxHp * undefined` 恒为 false，**回血分支整条失效**（实测三次都落到点数/护盾）。补上定义后复核通过。
    为此加了一道固定检查：把每个配置表（`CRYSTAL / GUARD / CHAIN / FURY / PULSE / RANGED_ATTACK / MOB_THROW / DODGE / STAMINA / SKILL`）的**引用字段与定义字段做差集**，现在全部为 0
26. **环境/诅咒条跟着镜头飘出屏幕**：`curseText` 与 `pulseText` 是用 `this.add.text` 建的，**没有加进 `scrollFactor(0)` 的 `hud` 容器**（`floorText` / `roomText` 等都加了）——
    于是它们停在**世界坐标** `(W-24, 110)`：镜头在房间起点时看着位置正确，往右一走整条就往左滑出屏幕，走到房间中段基本看不见。
    玩家反馈的「把环境效果显示右上角，就是房间进度下面」正是这个现象。修复：环境效果重做成独立面板 + 诅咒条 + 脉冲行，全部挂进 `hud` 容器，
    并逐条断言 `parentContainer === hud` 且镜头滚动后坐标不变
27. **环境池没少，是节奏太慢**：排查「环境效果换来换去就那么几个」时逐名比对，**15 条一条都不少，键也全对**；
    真正的原因是 2D **只在击败层主时重掷一次**环境，而 2D 的一层是 8 个房间的实时战斗（好几分钟）——
    一局只碰得到三五个，池子里另外十条永远轮不到。经典模式一层很快，所以同样 15 条显得「好多」。
    修复：改成**每进入一个房间重掷一次** + **袋抽发牌**（洗完一叠才重洗，一局内每条都会轮到），并给每类房间都加了「这次是什么」的可读文案
28. **字段名覆盖方法名（自己改出来的，最危险的一个）**：新加的环境面板把显示数值的文本框命名成 `this.envValue`，
    而类上本来就有 `envValue(key, fallback)` 方法 —— 实例字段**直接覆盖了方法**，导致所有读取环境数值的调用变成
    `TypeError: this.envValue is not a function`（除零条不读数值的环境外，**其余 14 条全部当场失效**）。
    改名为 `envValueText` 后复测通过。为此加了一道固定检查：抽出类方法名集合与 `this.X = ` 字段名集合做交集，现在为空
29. **图鉴里的环境文案是未替换的模板**：环境详情直接印 `WORLD_ENVS` 的原始串，玩家看到的是
    「所有单位攻击力 `{value}`（最低1）」「双方伤害 ×(1`{value}`)」这种占位符；且 `虚弱之雾` / `治疗抑制` 两条的模板写成 `×(1{value})`，
    代入**正数**削减量后会读成「×(120.5%)」（正确是 ×(1-20.5%)）。修复：模板补上减号，图鉴统一把占位符渲染成 `<数值>`
    （真实数值只有当前生效那条才有），当前环境则显示代入真实数值后的文案
30. **试炼环境泄漏进经典模式**：`exitTrial()` 只还原玩家 / 遗物 / 增益 / 英雄，**不还原环境效果** ——
    退出后经典界面显示的是试炼里最后那个房间的环境，而且数值是按**试炼层数**放大过的（试炼能到十几层，经典可能才 3 层）。
    修复：退出时按经典模式当前层数重新生成一个环境
31. **英雄技能胶囊与属性面板叠在一起**：技能胶囊排的是「狂怒条下方 28px」（y≈104），
    而属性面板那一行（攻 / 暴 / 闪 / 盾 / 棘 / 吸 / 连 / 斩）中心就在 y=106 —— 两者完全重叠。
    修复：把左侧 HUD 改成显式三层叠加 —— 属性面板（按当前宽度现算行数）→ 英雄技能 → 常驻按钮 → 目标面板，
    层间各留 5~6px；`statPanelMetrics()` 抽出来给两处共用，避免读到上一次布局留下的旧宽度。
    同时发现**窄屏（420）左右两列会横向撞上**（左列按钮行伸到 x≈387，右列从 x≈124 起），
    补了一条「撞上就把诅咒/环境整列下移到左列之下」的规则（宁可往下走也不叠字），
    并用 12 档宽度（420~1600）逐档断言六个不变量
32. **远程英雄的连招只是「换了个更大的弹丸」**：连招表是按近战写的（横扫 / 盾反 / 突进斩 / 落地斩），
    远程英雄直接复用同一套，只在 `fireShot` 里把弹丸放大 1.25 倍 —— 弓和法杖既挥不出横扫，
    也不可能为了打人把自己突进到怪脸上；而且**远程根本没有跳劈**，「落地斩」的窗口（跳劈落地）永远不会打开，
    等于远程英雄少一招。修复：新增 `RANGED_CHAIN`，四招换成远程该有的东西，触发时机 / 窗口 / 优先级**一个不改**：
    三连散（多目标时一支锁一个的真扇形）、反击箭（穿透取大值 + 强击退，自己不冲）、
    连珠箭（三发连点、每发重新锁定）、踏地箭（下坠弧线 + 插地爆炸，窗口改挂在「空中射击后落地」上）；
    招式名按武器分开写在 `角色形象.RANGED[id].chains`，图鉴连招页每条都分「近战 / 远程」两行讲清楚
33. **顺手发现的一处削弱**：反击箭原本把穿透写成固定 3 —— 对游侠（2）是增强，但对**贤者（穿透全场 99）是削弱**。
    改成 `Math.max(基础, 连招)`，只加不减（击退同理）
34. **腐化脉冲只剩"一圈光"**：脉冲的屏幕中央横幅写的是 `if (msgs.length) showCenter(...)`，
    而 `msgs` 只收集**「生命流失 / 虚弱 / 迟钝」三条** —— 于是最常见的「脆弱 / 易伤 / 贪婪 / 护甲腐蚀」
    以及所有纯环境类（护盾崩坏、能量导管、缓慢凋零…）结算时，屏幕中间**什么都没有**，只剩角色身上那圈紫环。
    修复：所有结算项都进 `msgs`（护盾 / 生命 / 攻击 / 闪避 / 环境各条），横幅**无条件弹出**并逐条写清；
    同时在右上角给脉冲一个落点 —— 结算时**诅咒胶囊与环境面板一起闪一下**。
    实测九种组合（含"没什么可结算"）每次都有横幅
35. **诅咒与环境两块面板视觉权重不对等**：诅咒原来只是一行 12px 的细红字（无底框），
    和环境那块带底框的三行胶囊摆在一起时，很容易被读成"下面那块的附属说明"。
    修复：诅咒也换成同一套胶囊（红色菱形标记 + 「诅咒」小标签 + 名称列表），
    两块成为明确的同级堆叠，顺序一眼可辨；底板绘制抽成共用的 `paintInfoBox()`
36. **连珠箭的"每发重新锁定"原来是假的**（做这一招时自己抓出来的）：招式说明写的是「每一发都重新锁定最近的敌人」，
    但代码里用的是 `rangedAim()` —— 那套逻辑**只有滞空时才瞄准敌人，落地时是固定朝正前方平射**。
    于是实测把目标从地面挪到高台，三发角度全是 `0°`，根本没有跟随。
    修复：新增 `lockAim(maxDist)`，连珠箭每一发都重锁最近敌人（520px 内，超出则退回平射）；
    复测三发角度变成 2.7° → −35.7° → −34.9°，后两发确实跟着目标改角度了。
    教训：**写进图鉴的机制必须逐条实测，不能只看函数名像不像**

## 十一、深渊回响（试炼 → 经典模式的产出闭环）

### 为什么做这个

在这之前，试炼与经典模式之间只有**单向的快照复制**：

- 进入：`startTrial()` 备份经典状态（`试炼程序.js` 的 `_backup`，4 个字段），把玩家属性复制成副本；
  副本里 `gold: 0, xp: 0` —— 经典模式的两大资源在试炼里直接消失，试炼另起一套「试炼点数」。
- 退出：`exitTrial()` 用 `_state.player = trial._backup.player` **整体还原**。
- 结果：**试炼里赚的点数、买的强化、打的层数，一样都带不回来。产出为零。**

再加上两边的商店商品表、诅咒表、环境表各写一份，2D 试炼又长出了自己的一整套系统
（房间地图 / 平台 / 连招 / 体力 / 狂怒 / 图鉴），体量已是独立游戏级，
而它与经典模式的接口还停在最初那 5 行备份/还原代码 —— 所以玩起来像两个游戏。

### 产出规则

试炼成绩折算成经典模式的金币与经验：

```
层数倍率 = 1 + (到达层数 - 1) × 0.15
结算倍率 = 层数倍率 × (主动撤离 ? 1.25 : 1.0)
金币 = 试炼点数 × 2 × 结算倍率
经验 = 试炼点数 × 1 × 结算倍率
```

| 到达层数 | 层数倍率 |
|---|---|
| 1 | ×1.00 |
| 5 | ×1.60 |
| 10 | ×2.35 |
| 15 | ×3.10 |
| 20 | ×3.85 |

**「稳 vs 贪」的抉择**：继续深入 → 层数倍率线性上涨；活着撤离 → 额外 ×1.25。
战死**不打折**（基础倍率照结），但层数就此定格 —— 所以"贪"的代价是丢掉那次 ×1.25，
而不是倒扣主线已有资源（保底无损、上限很高）。

### 一并修掉的四个真问题

1. **跨模式数值泄漏**：`applyTrialUnlocks()` 原本直接写 `_state.thornLevel` /
   `_state.vampireLevel` / `_state.critDamage`，而这三项既不在 `_backup` 里、
   `exitTrial()` 也不还原 → **每进一次试炼就永久累加一次**，经典战斗还会真的读到，
   与图鉴写的「仅试炼模式生效」自相矛盾。
   现在改为**一律写在试炼副本上**（`_state.trial.*`），并把 `startTrial()` 的调用点
   挪到副本建好之后（旧代码是先改 `_state.player` 再靠复制带进来）。
   同时删掉 `handleTrialEnemyDefeat()` 里那句多余的 `applyTrialUnlocks()` ——
   旧实现改 `_state` 时它"看不出来"，改成副本后就会变成真的反复叠加。
2. **两个退出入口行为不一致**：顶栏「退出试炼」原本直接 `exitTrial()`，
   不回写 2D 里的 floor / points，会丢刚打到的成绩。现在统一走 `_realtimeExitTrial()`。
3. **「重新开始」绕过 `exitTrial()`**：原本直接 `_deleteSave()` + `_initGame()`，
   备份没还原、试炼副本残留在 `_state` 里，等于把经典进度弄丢。现在先让试炼正常收尾再删档重开。
4. **退出试炼会动主线位置和环境**：`exitTrial()` 原本固定把 `mode` 设成 `'event'`，
   再走 `enterCurrentRoom()` / `advanceRoom()`，并重新 `generateEnvironmentEffect()`。
   三个后果：
   - `enterCurrentRoom()` 在敌人房会 `startCombat()` —— **平白重开一场已经打完的战斗**
   - 房间索引越界时它内部会 `advanceRoom()` —— **玩家白跳过一个房间**
   - 环境被重新随机 —— 进去前是「荆棘之地」，出来变成别的

   试炼是副本，「退出」的语义就是回到进去之前。现在把
   `mode` / `currentRoom` / `combat` / `environment` 一起放进 `_backup` 并在退出时原样还原
   （用引用而非深拷贝 —— `environment` / `combat` 里带钩子函数，JSON 克隆会把函数丢掉；
   而试炼只是整体替换这些字段、不会就地改，所以引用是安全的），退出路径不再调用任何房间操作。
   注意 `exitTrial()` 里需要先留住 `const backup = trial._backup` 再置空 `trial._backup`。

## 十二、移动端兼容（手机 / 平板）

### 12.1 问题：手机上 2D 试炼打不开，直接回退文字界面

根因是 **`Phaser.AUTO` 的降级不完整**。

`AUTO` 只在「Phaser **加载时** `Device.features.webGL` 为 false」时才改用 Canvas，
**不覆盖**「加载时检测通过、真正创建 context 时才失败」这种情况。而后者恰恰是手机的典型表现：
浏览器省电模式、硬件加速被关、显存吃紧、WebGL context 数量超限。
此时 `new Phaser.Game({ type: AUTO })` 会直接抛错：

```
[试炼2D] 初始化失败： Error: WebGL unsupported
[试炼] 2D 引擎初始化失败，回退到文字模式
```

异常被 `init()` 的 `catch` 兜住 → 整个 2D 层被判为不可用 → 回退文字模式。
**强制刷新无效**，因为这不是缓存问题；换浏览器也未必有用，因为触发条件是运行时环境而非版本。

### 12.2 修复

**① 渲染器主动探测（`probeWebGL()`）**

不信 Phaser 的加载期结论，自己在 `init()` 时真的建一个 WebGL context 试一次，
并且**额外编译一个顶点着色器** —— 部分设备拿得到 context、着色器却编译必失败。
探测用的 context 立刻 `WEBGL_lose_context` 释放：移动端 context 名额有限（通常 8~16 个），
漏掉一个就可能让真正的游戏 context 建不出来。

顺带修掉 `detectQuality()` 里同一个坑：它原本也建 context 探测，但**从不释放**。

**② 逐个尝试渲染器（`createGame()`）**

```
探测通过 → 先试 WEBGL，失败再试 CANVAS
探测不通过 → 直接 CANVAS
```

失败的那个实例会 `destroy()` 掉再试下一个，两个都失败才回退文字模式。

**③ Canvas 模式自动降画质**

Canvas 渲染器是纯 CPU 光栅化，沿用 WebGL 那套星尘 + 粒子必掉帧，所以落到 Canvas 时强制 `low`。

**④ 画质决策加移动端约束**

```js
cores <= 2            → low
deviceMemory <= 2     → low   // 低端安卓机
WebGL 不可用           → low   // 走 Canvas
触摸设备               → 最多 medium
```

**⑤ 失败原因上屏 + 一键重试**

手机上玩家看不到 console，只写日志等于没写。现在失败时画面内直接显示原因，
并给一个「重试 2D 模式」按钮 —— 重试走 `force` 路径，**会重新探测渲染器**，
所以「先失败、后来开了硬件加速」不必刷新页面。

**⑥ 初始化前置步骤全部纳入 try**

`loadSettings()` / `detectQuality()` / `installFontDefault()` 原本裸奔在 `try` 之外，
任意一步抛异常都会直接冒泡出去、绕过降级逻辑。现在全部包住。

### 12.3 布局：`100vh` 会吃掉底部按钮

移动端 `100vh` 是**含地址栏**的高度，而地址栏又会随交互收起/展开。
`.trial-screen.realtime-mode .trial2d-stage` 用 `height: 100vh` 会让全屏舞台比可视区高一截，
**底部那排触摸按钮正好落在地址栏底下，点不到**。

改为 JS 按 `visualViewport` 实时写入 CSS 变量，并监听 `resize` / `orientationchange`：

```css
height: 100vh;                      /* 兜底 */
height: var(--trial2d-vh, 100dvh);  /* 真实可视高度 */
padding: env(safe-area-inset-*);    /* 刘海屏 / 手势条 */
box-sizing: border-box;
touch-action: none;                 /* 禁止下拉刷新、双击缩放打断操作 */
```

viewport meta 也从 `width=device-width, initial-scale=1.0` 补成
`maximum-scale=1.0, user-scalable=no, viewport-fit=cover`。

### 12.4 触摸控件：小屏上摇杆会「吞掉」攻击键

原判定的问题：

- 按固定顺序判定，**摇杆排在最前面**
- 摇杆容错半径（`pad = 34`）又是最大的

小屏下按钮本来就挨得近，结果就是「手指明明按在「技能」上，触发的却是摇杆」。

改为 **最近优先**（`hitTouchButton()`）：用 `距离 / (按钮半径 + 容错)` 归一化后比大小，
手指落在哪个按钮中心附近就是哪个；隐藏的按钮（技能未解锁、狂怒未满）不参与判定。

### 12.5 触摸控件：竖屏专属布局

横屏那套「以右下角为圆心、向左上辐射」的摆法，在竖屏（宽约 360px）下会让摇杆直接压在攻击键上。

现在按 `W < H * 0.85` 判定竖屏，改用**左右分区**：摇杆独占左下角，其余动作键收进右侧两列网格。

竖屏 360×800 实测：

| 项 | 结果 |
|---|---|
| 按钮越界 | 无（8 个按钮全部在屏幕内） |
| 按钮圆相交 | 无（相邻中心距 > 半径和，视觉分得开） |
| 每个按钮正中心命中自己 | 8/8 通过 |
| 按在攻击键上是否被摇杆抢走 | 修复前会，修复后返回 `attack` |

### 12.6 验证结果

模拟「WebGL 不可用 + 触摸设备」环境实测：

| 项 | 修复前 | 修复后 |
|---|---|---|
| 引擎初始化 | ❌ `Error: WebGL unsupported` | ✅ 成功 |

| 场景就绪 | — | `ready: true`，英雄 / 敌人 / 46 块地形全部生成 |
| 画面渲染 | — | 推进 5 帧后 15 种颜色、23/120 非背景采样 |
| 角色精灵 | — | `rt_hero_warrior` 精灵表 16 帧 960×64 正常 |

> 排查提示：若在后台标签页测量画面，`requestAnimationFrame` 会被浏览器暂停

> 那是测量环境造成的假象，不是渲染失败。用 `game.loop.step(t)` 推进真实帧再采样。

### 12.7 进入 2D 试炼时自动切横屏

2D 是横版动作玩法，竖屏下战场视野很窄（手机竖屏可用宽度只有约 360px）。
进入 2D 战斗时会尝试自动切到横屏。

**但浏览器没有「强制旋转屏幕」的能力**，唯一的路是「全屏 + Screen Orientation API」，
而这条路本身有一堆限制：

| 限制 | 说明 |
|---|---|
| 必须先全屏 | `screen.orientation.lock()` 要求文档处于全屏状态 |
| 必须在用户手势里 | `requestFullscreen()` 不在手势的同步调用链里会被直接拒绝 |
| iOS Safari | 完全不支持 `orientation.lock()` |
| 手机开了「方向锁定」 | `lock()` 直接 reject |

调用点选在 `startRealtimeTrial()` —— 它由按钮点击同步触发、中间没有 await，
所以还在用户手势的调用链里，满足 `requestFullscreen` 的前置条件：

```
请求全屏（先）→ 成功后 lock('landscape') → 任一步失败都静默吞掉
```

**降级：顶部提示条，而不是阻断**

自动旋转失败时，顶部弹一条「横屏视野更开阔，建议旋转手机」，
而不是把玩家挡在外面 —— 竖屏布局已经适配过（见 12.5），横竖都能玩。
提示条的行为：

- 只在「触摸设备 + 2D 全屏战斗中 + 竖屏」三个条件同时成立时出现
- `pointer-events: none`，**只有「知道了」按钮接收点击**，绝不挡住战斗操作
- 点「知道了」后本局不再打扰，下次进试炼重新给一次
- 转到横屏、切到文字界面（`showRealtimeTextView`）、退出试炼都会自动收起

**退出时必须解除**：`_trial2DExit()` 里 `unlock()` 方向并退出全屏 ——
否则玩家会被锁在横屏全屏里出不来。这是这套 API 最容易漏的一步。

**误伤防护**：有些触摸屏笔记本的 `maxTouchPoints > 0`，会被判成触摸设备。
所以再加一道「必须处于竖屏」的条件 —— 桌面本来就是横屏，
既不需要切方向，也不该被强制全屏。

### 12.9 手机横屏的按钮布局：七个键挤进 228×163 的一块

#### 问题（800×360 实测）

6.7 寸手机横屏的 CSS 视口只有约 800×360，而右手要在里面放下七个键。
旧版沿「以右下角为圆心、向左上辐射」摆，量出来的结果是：

| 项 | 实测 |
|---|---|
| 七个键的包围盒 | 228×163（x 499–727，y 120–283） |
| 最小键直径 | **42px**（低于 44px 的触摸下限） |
| **判定圈重叠** | **5 对**，`蓄力跳 + 攻击` 重叠 **25px** |
| 最小视觉间隙 | 15px |

判定圈重叠 25px 意味着：手指按在「蓄力跳」的边缘上，触发的是「攻击」——
**「挤」不只是难看，是直接按错**。而 `pad` 之所以要开那么大（跳跃 22、攻击 18、
摇杆 34），正是因为按钮本身太小、需要额外容错；容错一开，判定圈就互相吃了。

同时左侧也挤：HUD 一列从 y=12 一路堆到 y=277（属性面板 → 技能胶囊 → 常驻按钮 → 目标面板），
而摇杆在左下角 (91,269) r46 ——

| 重叠 | 尺寸 |
|---|---|
| 摇杆 × 目标敌人面板 | 92×54 |
| 摇杆 × 药水数量 | 59×11 |

也就是说左下角那一块，玩家想看敌人血量就会误触移动。

#### 修复

**一、布局改成「两行网格 + 半径驱动间距」**

```
        药水    防御    技能    狂怒      ← 上排：次键 r=25
            闪避    跳跃    攻击          ← 下排：主键 r=32（攻击占最右下的拇指位）
   [摇杆]                       [按键区]
```

关键是**间距不再写死像素，而是现算**：

```js
var dB = rA + rA + gap;   // 主键 ↔ 主键
var dS = rB + rB + gap;   // 次键 ↔ 次键
var dM = rA + rB + gap;   // 上下两行之间
var col3 = W - m - rA;
var col2 = col3 - dB;     // 从右往左逐列推开
```

以前是 `W - pad - 124 * k` 这种硬编码偏移，换一个屏幕比例就会算错；现在列位置由
「实际半径 + 净空」推出来，任何尺寸上都保证不重叠。半径另设**绝对下限 23px
（直径 46px）**，小屏上不会缩到点不中。

**二、容错半径从 18~34 降到 4**

按钮本身已经够大，且布局保证了 10px 净空，判定圈再各外扩十几像素就会重新叠上。
摇杆是拖动操作、且离按键区很远，保留 16。

**三、目标面板搬到顶部中央**

触摸设备 + `H < 460` 时，目标面板移到顶部中央（x 让开左侧「生命数值」的实际宽度，
且必须排在 `refreshHud()` 之后才能取到正确宽度）。左右两侧都排满了 HUD，
只有这一条是空的；而且锁定目标的血量本来就该在视线正前方，比挤在左下角更好读。
层主名字同时从 y=82 让到 88。

**四、底部文字避让**

药水数量原来固定在 `H-48`，横屏落进摇杆判定圈、竖屏直接被圆盖住；现在按
`摇杆顶 - 26` 摆放。操作提示文字在横屏时放进「摇杆右缘 ~ 按键区左缘」这条窄缝里
（实测 x 110~521），并缩短为「摇杆移动（上推=蓄力跳）· 右下按键出手」。

| 视口 | 最小直径 | 最小间隙 | 判定圈重叠 | 中心命中 | 药水离摇杆 | 目标面板离摇杆 | 越界 |

> 无 padding 容器，等价于 `safe-area = 0` 的情形。

### 12.10 画布之上还有一层：DOM 按钮会盖住攻击键

12.9 的全部测量都发生在 Phaser 内部，**看不到 DOM 层**。而手机实测截图暴露了一个
几何测不出来的问题：

| 元素 | 位置（800×360 视口） |
|---|---|
| `.sidebar-toggle`（☰ 侧边栏开关） | `[724, 284] – [776, 336]`，z-index **100001** |
| 「攻击」键中心 | **(754, 314)** |
| `.trial2d-stage` 画布 | z-index **5** |

☰ 是 `position: fixed; bottom/right: 24px`（移动端断点 12px），所以它在真机上必然
落在**屏幕右下角**——也就是攻击键的位置；而它的 z-index 比画布高四个数量级。
结果是**攻击键既看不见也点不到**：触摸事件被这个 DOM 按钮吃掉。
这是手机上最严重的一个问题，比「按钮挤」严重得多。

修法是直接收起它 —— 实时战斗里也不需要：切文字界面 / 商店 / 图鉴 / 退出试炼，
画布内各有按钮。

```css
body.realtime-trial .sidebar-toggle,
body.realtime-trial .sidebar-overlay { display: none !important; }
```

### 12.11 减少遮挡：把战斗中不变的信息收起来

手机横屏只有 ~360px 高，而 HUD 是一整列从顶部往下堆。第一眼看到的几乎全是面板。
实测后做了三处减法（都只在「触摸设备 + `H < 460`」时生效）：

| 改动 | 效果 |
|---|---|
| **属性面板整块收起** | 8 个小格（攻/暴/闪/盾/棘/吸/连/斩）在整场战斗里一个数字都不会变，却是左侧最密的一块。收起后 `statPanelMetrics().rows = 0`，后续元素整体上移 |
| **底部操作提示 5 秒后淡出** | 它常驻会一直占着摇杆与按键区之间那条窄缝。开局亮一次够用——按钮上本来就写着名字，摇杆上也有箭头 |
| **药水文字去掉 `[L]`** | 触摸设备没有键盘，这个快捷键提示只是噪音 |

上个改动带来的位移（800×360 实测）：

| 元素 | 改前 | 改后 |
|---|---|---|
| 技能胶囊 y | 150 | **116** |
| 功能按钮行 y | 178 | **145** |
| 左侧 HUD 下沿 | 190 | **157** |
| 属性面板 | 2 行 × 4 格 | 收起 |

左侧状态列因此从 y=2–190 收到 y=2–157，把画面多让出一条。

### 12.12 按键自定义：把布局交给玩家

响应式布局解决的是「默认值在每台设备上都合理」，但每个人的手指长度、握持姿势、
常用招式都不一样。所以再加一层：**设置 → 2D 试炼按键自定义**，玩家可以移动、
缩放、调透明度、隐藏任意面板与按钮。

#### 架构：基准 + 覆盖

关键是**分层**，而不是让玩家直接改坐标：

```
布局函数（layoutTouchControls / layoutHudButtons / layoutEnvHud …）
        ↓ 算出「响应式基准位置」
applyCustomLayout()  ← 在基准之上叠加玩家的偏移 / 缩放 / 透明度 / 隐藏
```

好处：

- 基准永远由布局函数算，玩家的自定义只是一层覆盖 —— **换分辨率、转屏、切视图都不会把布局算坏**
- `applyCustomLayout()` 总是紧跟在布局函数之后，所以「基准 + 偏移」每次都是从
  同一个起点重算（**幂等**），拖动时不会越拖越偏
- 上一节那套「手机横屏自动改布局」的规则全部保留，自定义只在其上叠加

坐标按**屏幕比例**（0~1）保存，同一份配置在任何分辨率下都成立。

#### 24 个可编辑单元

每个单元是「一组一起移动、一起缩放的对象」。三类部件互不重叠，避免同一个对象被平移两次：

| 部件 | 移动方式 | 例子 |
|---|---|---|
| `meters` | 走 `placeMeter`（血条子对象由它统一重定位） | 生命条 / 体力条 / 狂怒条 / 层主血条 |
| `btns` | 数据按钮，改 x/y 后重绘 | 技能胶囊 / 四个功能按钮 |
| `objs` | 普通显示对象，直接平移 x/y | 摇杆 / 七个动作键 / 各文本 |

| 分组 | 单元 |
|---|---|
| 按钮 | 摇杆、蓄力跳、攻击、闪避、药水键、防御、技能键、狂怒 |
| 信息面板 | 主角名、生命条、体力条、狂怒条、属性面板、技能胶囊、功能按钮行、药水数量、右上信息列、环境面板、诅咒面板、脉冲倒计时 |
| 战斗 | 目标敌人面板、层主血条、操作提示、连击数 |

两个容易踩的坑：

- **生命数值这类文本必须改源头**。它们的位置来自 `_hpTextX / _hpTextY`，
  每次 `refreshHud()` 都会用它重新摆位 —— 直接挪文本会被下一次刷新弹回去。
  所以这些单元在 `apply` 回调里改的是那些变量，而不是对象的坐标。
- **属性面板 / 环境面板 / 诅咒面板 / 目标面板都是 Container**，内部子对象按局部
  坐标排；整体挪容器即可，不会干扰内部布局。

#### 编辑模式

进入后**冻结战斗**（不然一边挨打一边调布局），所有单元画上外框：

| 框色 | 含义 |
|---|---|
| 白 | 默认位置 |
| 金 | 改过（`isCustomized()`） |
| 绿 | 当前选中（带淡绿底） |

- **拖动** = 移动，带 4px 网格吸附（手指拖动本来就有几像素误差，不吸附很容易摆歪）
- **工具条**（画布底部）：缩放 40%~250%、透明度 10%~100%、显示开关、重置此项 / 全部重置、吸附开关、导入 / 导出
- **单元列表**：横向滚动的胶囊，比在画面上点更准（小元素也不怕点不到），改过的标金色、隐藏的划掉

工具条放**底部**而不是顶部：顶部是 HUD 区，工具条压上去就没法拖动顶部那些面板了。

#### 修掉的两个自查发现的问题

| 问题 | 现象 | 原因 |
|---|---|---|
| `getBounds()` 返回值没有 `clone()` | 画外框时抛错，**工具栏压根打不开** | Phaser 各显示对象的 `getBounds` 实现不一，改为手动求并集 |
| 重置后缩放 / 透明度残留 | `resetLayout()` 后位置回去了，但缩放还是 1.5 | `applyCustomLayout` 只写「有配置的」项（避免覆盖血量濒危脉冲这类动态 alpha），配置删掉后旧值就没人推回去了 —— 改成在 `resetCustomLayout` 里显式还原 |

「隐藏」还做了一个刻意的不对称设计：**只处理「玩家要隐藏」，不强制显示** ——
否则会盖掉技能未解锁 / 狂怒未满这类游戏逻辑。取消隐藏时也只还原
「我们自己隐藏过的」那部分（用 `_hiddenUnits` 记账）。

#### 验证结果

| 项 | 结果 |
|---|---|
| 可编辑单元 | 24 个全部注册，工具条 24 个胶囊全部生成 |
| 拖动 | 攻击键 (1284,715) → (1164,647)，实测位移 (−120,−68)，符合 4px 吸附 |
| 拾取 | 拖动时自动选中 `t.attack` |
| 缩放 | `scaleX: 1.5`，且**不改半径**（用 `setScale` 而非改圆半径，保证判定圈同步放大） |
| 隐藏 → 取消隐藏 | `false` → `true` |
| 透明度 | 右上信息 `alpha: 0.4` |
| 退出编辑 + 重算基准 | 位置 / 缩放 / 透明度全部保持，战斗恢复运行 |
| 全部重置 | 位置回到基准、缩放回 **1**、透明度回 **1** |
| 导出 → 重置 → 导入 | 完整还原 |
| 落盘 | `abyss_trial2d_layout`，含 `dx / dy / s / a / v` |

#### 一个自作自受的闭环问题：设置入口够不着

12.10 为了不让 ☰ 压住「攻击」键，把右下角的侧边栏开关收起来了。但**设置正挂在
侧边栏里** —— 于是 2D 实时战斗里既进不了设置，上面这个编辑器也就够不着。
（是玩家指出来的，不是自查发现的。）

补法是**在画布内加一颗「设置」按钮**，常驻功能按钮行从 4 个变 5 个：

```
文字界面 · 商店 · 图鉴 · 设置 · 退出试炼
```

800×360 下右边缘到 x≈410，而右上环境面板从 x≈504 起，放得下。
「设置」不带图标（`rt_ico_*` 里没有对应纹理，缺省即不画）。

设置面板是全屏模态（`.modal` 的 `z-index: 114514`，画布只有 5），**会盖住战场**，
所以打开时必须冻结战斗 —— 否则玩家在调设置时会被看不见的敌人打死：

```js
this._viewPaused = true;      // update() 里遇到就冻结
window.openSettingsModal();
this.watchSettingsClosed();
```

`watchSettingsClosed()` 用 **MutationObserver** 盯住面板的 `class`，而不是定时轮询 ——
面板可能被好几种方式关掉（关闭按钮 / 点遮罩 / Esc / 从里面点「打开编辑器」时它自己
隐藏）。关闭后放开 `_viewPaused` 恢复战斗；编辑模式那条路自己管 `running`，两者不冲突。

完整链路实测：

| 步骤 | 结果 |
|---|---|
| 点画布「设置」 | 面板打开，`_viewPaused: true`（战斗冻结） |
| 设置列表 | 14 项，最后一项是「2D 试炼按键自定义」 |
| 点「打开编辑器」 | 面板自行关闭 → 进入编辑模式，`running: false`，工具栏显示，24 个胶囊 |
| 点「完成」 | `editing: false`，`running: true`，`_viewPaused: false`，战斗正常恢复 |
| 关设置面板（不编辑器） | `_viewPaused: false`，战斗恢复 |

### 12.13 设置面板在 2D 试炼里滑不动

12.10 刚把「设置」搬进画布，玩家马上反馈：**设置界面无法滚动**，滑不下去，
底部那些开关永远够不到。（又是玩家指出来的。）

根因不在设置面板，而在实时战斗给 `body` 加的那个类：

```css
body.realtime-trial {
    overscroll-behavior: none;
    touch-action: none;    /* ← 元凶 */
}
```

`touch-action` **不是可继承属性，而是「触摸目标元素 → 根元素」整条祖先链的交集**。
根元素上是 `none`，后代写 `auto` / `pan-y` 都救不回来 —— 弹窗内部的触摸滚动全部失效。
（同一条链上 `.trial2d-stage` 自己已经声明了 `touch-action: none`，
禁止战斗手势的职责其实完全不需要 `body` 再声明一次。）

修法：

1. **删掉 `body.realtime-trial` 上的 `touch-action: none`** —— 舞台与画布各自声明就够了；
   页面本身的滚动早被 `overflow: hidden` 挡住，下拉刷新由 `overscroll-behavior: none` 兜住。
2. `.modal` 与 `.modal-content` 显式补上 `touch-action: pan-y` + `overscroll-behavior: contain`
   + `-webkit-overflow-scrolling: touch`，把「弹窗内可纵向滚动」写死。

顺手把矮视口（手机横屏 800×360，可视高度只有 360px）的弹窗也修剪了一遍，
减少需要滑动的距离：

```css
@media (max-height: 560px) {
  .modal-content {
    max-height: calc(var(--trial2d-vh, 100vh) - 12px);  /* 优先用 JS 实测的可视高度 */
    padding: 12px 14px;
  }
  .setting-item { padding: 6px 10px; }
  .setting-label { font-size: 0.78rem; }
}
/* 横屏：14 项设置排双列，一屏基本放得下 */
@media (max-height: 560px) and (min-width: 600px) {
  #settingsModal .modal-content { max-width: min(96vw, 820px) !important; }
  #settingsModal .settings-list {
    display: grid;
    grid-template-columns: minmax(0, 1fr) minmax(0, 1fr);  /* 不能直接写 1fr */
  }
}
```

两个坑：

- **这段必须放在样式表最末尾。** 文件前面有一段
  `@media (min-width: 768px) and (max-width: 1200px) { .modal-content { padding: 20px } }`，
  手机横屏的 800px 宽正好落进那个区间，同优先级下先出现的会被它盖掉（第一次就踩了）。
- **grid 列宽必须写 `minmax(0, 1fr)`。** 直接用 `1fr` 时列宽下限是 `min-content`，
  设置项里「标签 + 开关」的最小宽度会把两列撑破容器，弹窗被压窄、内容横向溢出。

实测（iframe 精确视口，`body.realtime-trial`）：

| 视口 | body touch-action | 弹窗 touch-action | 可滚动 | 需滚动距离 | 布局 |
|---|---|---|---|---|---|
| 800×360 | `auto` | `pan-y` | ✅ | 132px | 双列，`max-width: 768px` |
| 892×412 | `auto` | `pan-y` | ✅ | 80px | 双列 |
| 740×360 | `auto` | `pan-y` | ✅ | 151px | 双列 |
| 360×800（竖屏） | `auto` | `pan-y` | ✅ | 192px | 单列 |
| 1384×797（桌面） | `auto` | `pan-y` | ✅ | 442px | 单列 |

### 12.14 常驻功能按钮压在面板最上层

玩家的第二句反馈：**看图鉴和结算时，「设置 / 图鉴 / 退出试炼」这排按钮还显示在最上层**。

原因是这排按钮的层级从一开始就压着所有面板：

| 图层 | depth |
|---|---|
| 地图 `mapLayer` | 2000 |
| 商店 `shopLayer` / 死亡结算 `deathLayer` | 2200 |
| 图鉴 `codexLayer` | 2310 |
| 撤离确认 `confirmLayer` | 2400 |
| **常驻功能按钮行 `uiBar`** | **2600** |

（当初注释写着「独立容器且层级最高：地图、商店、死亡面板打开时依然可用」——
是有意的，但那意味着面板打开时这排按钮横穿面板中央。）

改为**面板一打开就整行让位**：

```js
panelOverlayOpen() {
  return !!(this.mapOpen || this.shopOpen || this.codexOpen ||
            this.deathOpen || this.confirmOpen || this._viewPaused);
}
syncUiBarVisibility() {
  if (!this.uiBar) return;
  var want = !this.panelOverlayOpen();
  if (this.uiBar.visible !== want) this.uiBar.setVisible(want);
}
```

放在 `update()` 里 `if (!this.running) return;` **之前**每帧对齐：
面板打开时战斗虽然被暂停，但场景 update 仍在跑（只有切文字界面才会 `scene.pause()`），
所以不必去每个开关点插调用。`pauseForView()` / `resumeFromView()` 额外显式补一次，
因为那条路会真的把场景 pause 掉。

**连带两处必须跟着改**，否则会变成「看不见却点得到」：

```js
// handleUiClick / uiHitTest 里，hudButtons 的命中原本无条件排在面板之前
if (!this.panelOverlayOpen()) {
  var hb = this.hitBtnList(p, this.hudButtons);
  if (hb) { this.onHudAction(hb.id); return true; }
}
```

**还要给地图补一个退出口。** 地图是唯一没有自带关闭按钮的面板（原来靠
「点一个相邻房间」才能走，常驻按钮行又提供了商店 / 图鉴 / 退出的入口）。
整行收起后会把人困在「必须选一个房间」里，所以在右上角补了一颗「返回房间」
（`panelButtons.map`，走新加的 `onMapAction` → `closeMap()`）：

```js
var backW = mini ? 80 : 100, backH = mini ? 26 : 30;
this.uiButton(this.mapLayer, this.panelButtons.map, 'close', '返回房间',
  W - 12 - backW / 2, mini ? 34 : 48, backW, backH, false);
```

实测（800×360，逐面板开关）：

| 面板 | 打开时 uiBar | 面板自带出口 | 点出口后 |
|---|---|---|---|
| 图鉴 | 隐藏 | 「返回战斗」 | 关闭，uiBar 恢复 |
| 商店 | 隐藏 | 「返回」 | 关闭，uiBar 恢复 |
| 死亡结算 | 隐藏 | 「试炼商店 / 退出试炼」 | 关闭，uiBar 恢复 |
| 撤离确认 | 隐藏 | 「继续战斗 / 确认退出」 | 关闭，uiBar 恢复 |
| 地图 | 隐藏 | 「返回房间」（新增） | 关闭，uiBar 恢复 |
| 设置（DOM 模态） | 隐藏 | 「×」「关闭」 | 关闭，uiBar 恢复 |

另外验证：图鉴打开时点在 5 个功能按钮中心，`onHudAction` **一次都没被触发**（此前面板
关闭时同样的点击会正常触发）。

### 12.15 编辑器三个问题：缩不小、整体联动、改了不生效

12.12 把布局交给玩家之后，玩家一次性提了三条（都是实测出来的）：

**① 「取消勾选目标敌人面板的显示，点完成一看面板还在」**

不是保存失败，是**战斗逻辑每帧把它顶回来**：

```js
// updateEnemyMeters() —— 每帧都会跑
if (!nearest || this.heroDead) { ...setVisible(false); return; }
this.targetPanel.setVisible(true);           // ← 无视玩家的选择
```

同类还有层主血条、环境面板 / 诅咒面板（`updateCurseHud`）、连击数、操作提示。
原来只做了「隐藏」这一侧的强制，没有反向兜底。

修法不是在每个 `setVisible(true)` 处插判断（`update()` 中途有十几处 `return`，迟早漏），
而是挂到**场景的 postupdate**上统一落实：

```js
this.events.off('postupdate', this.enforceHiddenUnits, this);
this.events.on('postupdate', this.enforceHiddenUnits, this);
```

`postupdate` 在 `update()` 所有 `return` 之后的最后一站，渲染又排在它后面，
所以既不会漏，也不会出现「先显示一帧再被按回去」的闪烁。
被藏对象在 `applyCustomLayout` 隐藏时就记进 `_hiddenStyles`（含按钮的底板 / 文字 / 图标），
`enforceHiddenUnits()` 只遍历这份清单 —— 没人隐藏时开销为零。

**② 「让编辑器支持能把元素往小了改」**

三个独立的原因叠在一起：

- 缩放滑块下限是 **40%**，不够小 → 放到 **20%**（`importCustomLayout` 的钳位同步 0.4→0.2）。
- **血条类单元的缩放完全无效**：`unit()` 的样式作用对象默认只有 `objs`，而生命条 / 体力条 /
  狂怒条 / 层主血条的条体在 `meters` 里，只有旁边的数字会缩。现在把 meter 的
  `track / trailImg / fill` 也纳入（纹理宽度就是条宽、`setDisplaySize` 后 scale 恰为 1，
  直接 `setScale` 就是等比缩小）—— 但**必须排除 `glow`**，它用的是固定尺寸纹理、
  scale 不等于 1，再叠一层会把它算成一个小点。
- **按钮类单元的缩放同样完全无效**，而且不能照搬 `setScale`：按钮底板是 `craftButton`
  用绝对坐标画在 Graphics 上的，缩放会以 `(0,0)` 为原点把整颗按钮拖到画面左上角去。
  所以按钮的缩放落在**数据尺寸**上：

```js
applyButtonStyle(b, s, a, hide) {          // 缩放 → 改 baseH/baseW × s，再重绘
  b.h = Math.max(12, Math.round((b.baseH || b.h) * s));
  b.w = Math.max(16, Math.round((b.baseW || b.w) * s));
  ...
}
```

`paintButton` 里字号（`_baseFont × s`）、内边距、图标尺寸也跟着缩放走，
否则缩小后文字与图标是固定像素，会把按钮撑成又矮又宽的一条。
触摸按钮的**判定半径 / 摇杆行程**同样联动：`reach = c.radius * c.scaleX + pad`
（视觉分开了、手感还在打架，等于没改小）。

**③ 「似乎有些更改都没生效」**

原来是「只在值为非默认时才写样式层」：

```js
if (s !== 1 || a !== 1 || hide || wasHidden) { ...写... }
```

于是**把缩放从 40% 拖回 100% 毫无反应** —— 滑块在动、画面不动。
现在改成跟上一帧真正写过的值比，只要变了就写，包括写回默认：

```js
var prev = self._appliedStyle[u.id] || { s: 1, a: 1, hide: false };
if (s !== prev.s || a !== prev.a || hide !== prev.hide || wasHidden) { ...写... }
```

附带好处：`resetCustomLayout(null)` 现在能自动推回默认，不再依赖那段手工补偿。

**④ 顺带：把「一整行」拆成一颗一颗**

玩家要求「功能按钮行每个按钮、右上角信息列每行信息都能单独调整」：

| 原来 | 现在 |
|---|---|
| `h.funcBtns`（整行一个单元） | `h.fn.text / shop / codex / settings / quit`（5 个） |
| `h.info`（4 行一个单元） | `h.info.floor / point / enemy / room`（4 个） |

可编辑单元 24 → **31** 个。

光拆单元还不够：功能按钮原来是「读上一颗的宽度往后累加」排的，缩放其中一颗会把它
右边的全部推走 —— 那还是整体联动。改成**固定槽位**：

```js
layoutPillRow(btns, x0, by, bh, gapX) {
  // ① 先按「未缩放」量一遍原生宽度 → baseW
  // ② 按 baseW 累加分配槽位 → slotCenter
  // ③ 位置 = 槽位中心，缩放只改自身绘制尺寸
}
```

800×360 实测（每颗独立）：

| 操作 | 结果 |
|---|---|
| 「退出试炼」缩到 50% | w 93→58、h 25→13、字号 11→8、图标 16→8；**其余 4 颗位置一个都没动** |
| 缩到 20% | w 56、h 12、字号 8（下限） |
| 改回 100% | 与初始状态逐字段完全一致（`identicalToBefore: true`） |
| 单独隐藏「图鉴」 | 只有 codex 消失，其余不受影响 |
| 单独把「商店」透明度调到 35% | 只有 shop 变淡，且不被 `paintButton` 顶回（它会重设 text/icon 的 alpha） |
| 单独右移「商店」 | 只有 shop 位移，右边的 codex / settings / quit x 不变 |
| 只动「层数」一行 | 只有层数右移 40px，点数 / 敌人数 / 房间三行纹丝不动 |
| 技能胶囊缩到 60% | w 67→59、h 22→13、字号 11→8，`gfx.scaleX` 保持 **1**（没走 setScale） |
| 隐藏目标敌人面板后强制显示 | `events.emit('postupdate')` 后仍为隐藏 |

### 12.16 「导出」之后横屏回不来了：方向锁是绑在全屏上的

现象：2D 试炼里本来是横屏，编辑完按键点「导出」（或「导入」），屏幕转回竖屏，
**之后再也回不到横屏**，只能退出重进。

#### 根因是一串连锁反应，不是「横屏功能坏了」

```
导出 →（局域网 http 不是安全上下文，navigator.clipboard 不存在）
     → 落到 window.prompt 分支
     → 系统对话框把页面顶出全屏
     → Screen Orientation 的锁随全屏一起失效（规范就这么定的）
     → 屏幕转回竖屏，而这时玩家并没有离开试炼
     → 没有任何代码会去把锁重新拿回来
```

第 3、4 步是关键：`orientation.lock()` 的生命周期**绑定在全屏上**。之前只在
`_enterLandscapeMode()` 里锁一次，那之后的任何一次全屏丢失（系统对话框、下载栏、
来电横幅、玩家自己下滑退出全屏）都会让横屏静默失效，而且提示条只认「竖屏」，
玩家看到的还是一句「建议旋转手机」—— 明明转回去过一次，却转不回来了。

#### 两处改动

**① 去根因：导出 / 导入不再用 `window.prompt`**

换成一个铺满视口的 DOM 面板 `#trial2dIoPanel`（`LayoutBar.showIO`）：

| 模式 | 可见按钮 | 说明 |
|---|---|---|
| 导出 | 全选复制 / 关闭 | textarea 只读，防止手抖改掉原布局 |
| 导入 | 读取剪贴板 / 确定导入 / 关闭 | 可编辑，进面板即聚焦 |

顺带解决两个老问题：`prompt` 里看不了带缩进换行的长 JSON；手机上几乎没法长按选中。
剪贴板 API 在局域网 http 下不可用（或被拒），此时退化成**自动全选 + 提示「长按复制」**，
而不是报错。

**② 兜底：把「2D 试炼期间横屏」当成持续维持的约束**

```js
// 每个真实触摸都是一次抢救机会：只有手势里浏览器才给全屏
document.addEventListener('pointerdown', _relockLandscapeFromGesture, true);
```

- 发现竖屏就重发 `requestFullscreen` + `lock('landscape')`；
- 全屏**还在**但只是被顶回竖屏时，只补 `lock`，不重复请求全屏；
- 节流 1000ms，连续触摸不会反复闪；
- 连续失败 3 次（iOS / 系统方向锁定）就放弃，回到原来的「建议旋转手机」提示；
- 一旦真的横过来，失败计数归零，下次被打断还能继续抢救；
- 玩家点过「知道了」= 本局明确不想被管 → 彻底不再自动干预（竖屏布局本来就是适配过的）；
- 点提示条上那颗「知道了」按钮时的 pointerdown 要排除掉，否则「喊停」的动作本身
  会先把屏幕锁回去。

提示文案也分成两句：

| 情况 | 文案 |
|---|---|
| 本局曾成功横屏过（设备支持，被顶掉了） | 点一下屏幕恢复横屏 |
| 从头到尾没成功过（只能玩家自己转） | 横屏视野更开阔，建议旋转手机 |

#### 顺手修掉一个会被这次改动放大的坑

`_inRealtimeTrial()` 原来写的是 `_state.trial && ...`，而 `_state` 由主程序注入、
**注入前是 `null`**。这个函数以前只在 `resize` 时被调到，现在挂在了全局
`pointerdown` 上 —— 也就是说页面一加载，**每一次触摸都会抛 `TypeError`**。
已加空值保护，并把最便宜的 `body.classList.contains('realtime-trial')` 提到最前面短路。

#### 验证（stub 掉全屏与方向锁，用同步自增的 `_landscapeRetry` 当判据）

| 场景 | 期望 | 实测 |

| 全屏丢失后再触摸 | 重新全屏 + 重新锁定 | `req+1`、`lock+1` |

| 已经是横屏 | 完全不干预 | `retryDelta: 0` |
| 不在 2D 试炼（主界面 / 图鉴 / 设置） | 完全不干预 | `retryDelta: 0` |
| 点过「知道了」 | 不再自动锁 | `retryDelta: 0` |
| 连败到上限 3 | 不再折腾 | `retryDelta: 0` |
| 点「知道了」按钮那一记 pointerdown | 不算「在玩」 | `retryDelta: 0` |

### 12.17 从试炼回来之后，经典模式的英雄技能点了没反应

现象：经典模式战斗中技能按钮好端端地摆在那，点下去**什么都没发生** —— 没有日志、
护盾不涨、伤害不变。

#### 根因：试炼备份把技能函数丢在了 JSON 里

```
进入试炼   _backup.hero = JSON.parse(JSON.stringify(_state.hero))
           → JSON 不保存函数
           → skill.active 这个**对象还在**，但 execute 已经是 undefined
退出试炼   _state.hero = backup.hero        ← 把残缺的英雄装了回来
按钮显示   只判断 `state.hero?.skill?.active` 是否存在 → 照样通过，按钮照画
点击处理   if (typeof execute === 'function') { ... }   ← 没有 else
           → 静默掉到函数末尾，什么都不做、什么都不说
```

最讽刺的是同一段备份代码里，`environment` / `combat` 特意用了引用，旁边还写着注释
说明「JSON 克隆会把钩子函数丢掉」—— 唯独 `hero` 漏了。

#### 修法（四层，任一层都能挡住这个 bug）

| 层 | 改动 |
|---|---|
| 根治 | `_backup.hero` 改用引用（试炼期间不会就地改 `_state.hero`，安全） |
| 收口 | 抽出 `restoreHeroSkillBinding(hero)`，把散在 5 处的手写重绑全换成它 |
| 防御 | `exitTrial` 恢复完 hero 后统一重绑一次 |
| 兜底 | `activateHeroSkill` 先尝试自动重绑；仍失败就 `addLog` 明说，而不是静默 |
| 最后防线 | 按钮显示条件加 `typeof execute === 'function'`；`render()` 里发现缺函数就顺手接回来 |

最后一条是必须的：光把按钮条件收紧，会出现「按钮干脆不显示」—— 玩家连点都点不到，
比「点了没反应」更难排查。

#### 验证

| 场景 | 结果 |
|---|---|
| `state.hero` 换成 JSON 克隆后 render | `execute` 自动恢复为 function，按钮正常显示 |
| 随后点击 | 护盾 0→6、日志「你发动了战吼，立刻获得 6 点护盾。」、`heroSkillUsed: true` |
| 连英雄表里都找不到（伪造 id） | 按钮不显示；直接调用则给出可见日志，不再静默 |
| 正常载入存档后点击 | 一次成功 |
| 进试炼 → 退出 → 立刻打一场 | `_backup.hero` 与 `_state.hero` 是同一个对象，`execute` 完好 |

### 12.18 台阶叠成一坨，以及怪被打到屏幕外面

#### 台阶：4~9 段平台硬塞进 46px 的高度里

```js
var topY = this.groundY - 350;                       // 手机横屏 H=360 → -86（屏幕外）
var y = rnd(Math.max(H * 0.3, topY), lowY);          // 实际范围 [108, 154] —— 只有 46px
var x = rnd(W * 0.35, Math.max(W * 0.5, levelWidth - 260));   // 跨度 1060px
var len = ri(3, 6);                                  // 平均 288px 宽
```

四段平台平均宽度合计 1152px > 1060px 的水平跨度，而高度只有 46px 可用 —— **必然互相压上去**。
第 10 层的 9 段更是全叠成一坨。玩家看到的是「一个台阶」，实际是好几层碰撞体，
跳上去落在哪一层全凭运气。

修改：

- `topY` 的上限从 `H*0.3` 下探到 `H*0.14`（桌面端 H 大，仍由 350px 那段决定，不受影响）；
- 平台长度跟着可用空间伸缩：`maxLen` 由每个槽位的宽度反推，而不是固定 3~6 格；
- 摆位改成**槽位优先 + 冲突检测的拒绝采样**：前 28 次尝试限制在自己的槽位里，
  之后才放开全局；冲突定义是「水平投影挨着（< GAP_X=56）**且** 高度差不够（< GAP_Y=46）」；
- 48 次都放不下就 `continue` —— **少放一段，而不是叠上去**。

抽出了 `spawnPlatformAt(left, y, len)`：碰撞体、视觉条、落脚点记录一次铺好。

实测 60 个房间、390 段平台：**重叠 0 处**（平均 6.5 段/房间）。

#### 敌人：只有主角设了世界边界

```js
this.hero.setCollideWorldBounds(true);   // 主角一直有
// spawnEnemy 里 —— 没有
```

于是被击退的敌人会带着速度一路飞出关卡，而 `updateEnemies` 里的「脱离战斗」判定
（`x < -400 || x > levelWidth + 400`）还排在**硬直检查之后** —— 硬直期间敌人不受控地飞，
等硬直结束才去检查，它早飞远了。判定的结果是把敌人直接抹掉，玩家看到的就是
「怪被打飞到屏幕外面，然后凭空消失」。

修改：

- `spawnEnemy` 里补 `spr.setCollideWorldBounds(true)`；
- 「脱离战斗」的判定挪到硬直检查**之前**，阈值从 ±400 收到 ±120（那是「已经离开关卡」，
  而不是「跑出去两个屏幕」）。正常情况下有世界边界兜着，这一条只接住坠落。

实测：把敌人直接丢到 `x = 2200`（关卡右边界 1600），`physics.world.postUpdate` 把它
拉回 **1585** —— 正好是右边界减去半宽。同一条边界也挡住了超大击退。

### 12.19 手机横屏下，几个面板的文字叠在一起

用户报的是图鉴「文字会叠在一起」。查下去发现是**三个独立原因**叠在一起，
而且不止图鉴一个面板。

#### 原因一（最关键）：Phaser 的 wordWrap 默认按空格断行

`wordWrap: { width: N }` 用的是 `basicWordWrap` —— **在空格处断行**。中文句子没有空格，
于是整段文字对宽度限制视而不见，一路横穿出去，压在旁边的元素上。

```
图鉴「实时战斗没有「回合」，脉冲是能看懂也能预…」，限制宽 529px，实际宽 588px
```

修法是全局性的：加了一个 `wrapCN(width)` 工具函数，把 `useAdvancedWrap: true`
（按字符断行）包进去，4 处中文正文全部换成它。

#### 原因二：`mini` 只判断宽度

`var mini = W < 760` —— 而手机横屏是 **800×360**：宽度过关、高度只有 360。
于是它落进「不是 mini」的分支，直接套桌面尺寸（22px 内边距、138px 高的形象卡、
300px 侧栏），内容被挤出面板。

改成两个开关：

```js
var mini  = W < 760;              // 真的窄：摆不下左右两栏，只能单栏
var tight = !mini && H < 520;     // 不窄但很矮：照样双栏，只是尺寸收一档
var compact = mini || tight;      // 字号 / 间距走哪一档
```

800×360 现在走「紧凑双栏」：侧栏 165px（原 300）、每页 5 条（原 8）、内边距 14px。

商店是同一个毛病（`W < 700`，商品格被压到 37px 而内容要 40px+），一并按高度收紧。

#### 原因三：字段行按形象卡的高度往下推

```js
var listTop = y + Math.max(hasArt ? artH : 0, mini ? 74 : 86) + 12;
```

字段行是并排画在形象卡**右边**的（`textX = x + artW + 16`），却按形象卡的高度（138px）
往下推。手机横屏下整个详情区只有 212px 高，字段行直接被推到面板外，叠在页脚按钮上。

真正需要避开的只是上面那三行标题块，改成 `y + (compact ? 74 : 86) + 12`。

另外：标签列宽改成按该条目最长的标签**现算**（固定 64px 遇到 7 个字的
「两类改成每房间」就被撑破，压到右边的值上）；字段行与备注都加了「放不下就不画 /
整体缩一点」的兜底，任何内容都不会越出详情区下沿。

#### 顺带修掉的

| 问题 | 说明 |
|---|---|
| 图鉴左栏「第 N / M 页」 | 画在 `bodyBottom + 12`，而那正好是页脚按钮那一行，提示压在「上一页 / 下一页」上；挪进左栏内部 |
| 单栏翻页会跳条 | 单栏没有列表可点，一页却按 5 条算，按一次「下一页」直接跳过 4 条；单栏改成一条一页，并把「第 N / M 条」放到页眉右端 |
| 单栏页眉叠字 | 「收录 9 英雄 · 10 怪物…」有 30 来个字，360px 面板里一路顶到左边压住副标题；单栏时改为不画 |
| 商店在 800×360 叠字 | 见原因二 |
| 地图「返回房间」按钮溢出 13px | `uiButton` 的 x 是**左边缘**，当初按中心坐标传了 `W - 12 - backW/2` |
| 地图提示压在房间名上 | 格子排到 y≈275、提示在 272；矮屏时把提示挪到图例下方 |

对每个面板收集所有 `Text` 的 `getBounds()`，检查两件事 —— **越出画布**，

| 商店（22 个文本） | 0 / 0 | — | — |

### 12.20 「怪全打完了还显示剩余敌人 1」和「狂怒 x/100 会动」

#### 先纠正我自己的一次误判

第一轮检测我用的判定是 `Phaser.Geom.Intersects.RectangleToRectangle`（**相交即为真**），
又直接在 `spawnEnemy` 之后读 `body.x/y` —— 得出「70 个敌人里 26 个嵌在地形里」。
这个结论是错的，两个原因：

1. **相接的矩形会被判成相交**：物理引擎把敌人推到「刚好贴着平台」时，
   两者边缘相等，浮点误差就会让相交判定为真；
2. **`body.position` 不会在 `setOffset()` 之后立刻重算**，读到的是过时值。

换成「真实物理步进 + 重叠面积 > 4px² 才计数」之后：**realOverlap 0、touchingOnly 0**。

教训写在代码注释里了：判定物理重叠要用面积阈值，且先让 body 同步。

#### 那「剩余敌人 1」到底是什么

把 40 个房间的敌人跑完物理、逐个量过位置与脚底对齐之后，**没有找到卡死的敌人**。
剩下的解释就是位置问题：关卡有两屏宽（1600px），怪又可能站在高台上，
「剩余敌人 1」经常是它在关卡另一头、或者在高台上没被注意到。

所以加了一个**屏幕外方向指示**：存活敌人跑到视野之外时，在对应的屏幕边缘画一个
金色三角箭头（`updateOffscreenEnemyMarkers`，每帧重画，一个 Graphics 就够）。
这样「还剩一个」至少知道往哪边走，不用满地图瞎找。

#### 顺带修掉两个真能卡住怪的隐患

| 隐患 | 说明 |
|---|---|
| 敌人会卡在两层平台之间 | 平台防重叠的 `GAP_Y` 是 46，而怪高约 48、平台体厚 20 —— 净空不够，怪钻进去就出不来。改成 68（= 48 + 20），并把「碰撞体偏移按帧真实尺寸算」也修了 |
| 碰撞体整体上移十几像素 | `setOffset((CELL - def.w) / 2, CELL - def.h)` 里的 `CELL` 写死 64，而角色的精灵帧实际只有 52 高 —— 碰撞体比视觉高 12px：怪打的时候判定偏上，站在平台上时脚底也对不上。改成按 `spr.frame.realHeight` 算，修完 `bodyBottom === sprite.y`，脚底误差 **0** |

另外把敌人生成的两处也理顺了：地面怪从**所有平台之上**落下（不再是固定 `groundY - 80`，
那个高度正落在平台层里），水平方向改成**均匀铺开**（原来按「上一只 + 150~260」累加，
靠右的会被挤回同一段区间，几只怪叠在一个点上 —— 看起来一个怪实际两个，打死一个还有一个）。
飞行怪则直接关掉与地形的碰撞：手机横屏下平台几乎占满地面以上的空间，没有能避开的高度。

实测 20 个房间 105 个敌人：互相重叠 0、出界 0、卡在平台间 0。

#### 狂怒 x/100「会动」是两个独立 bug

**① `applyCustomLayout()` 不是幂等的**

```js
u.meters.forEach(function (m) { self.placeMeter(m, m.x + ddx, m.y + ddy, m.w); });
```

它读的是**当前**坐标，所以每被调用一次，整个单元就往自定义方向再走一截。
实测连续调用三次：

```
起点        meter.x 24  → text.x 258
拖 10%      meter.x 104 → text.x 338
再 apply    meter.x 184 → text.x 418   ← 又走一截
再 apply    meter.x 264 → text.x 498   ← 再走一截
```

条和数字一起往右飘 —— 这就是「会动的」。

改成记录「上次真正应用过的偏移」，只搬**差量**（和 `_appliedStyle` 同一套路子），
并在 `onResize` / `relayoutForEdit` 里、基准重算之后清空记录（不清的话会以为早就搬好了）。

**② 数字记的是布局时算死的坐标**

```js
this.furyTextPos = { x: x0 + barW + 10, y: furyY };   // 条还没被缩放时的右边缘
```

而布局编辑器可以把条缩放到 20%~250%。条一变短，这个固定坐标就留在原地：

```
条缩到 60%：条的右边缘 328 → 238，数字还在 338 → 空隙从 10px 裂成 100px
```

这就是「不是固定在狂怒条旁边」。改成存 **gap（离条右边缘多远）**，
实际位置由 `meterTextX()` 按条的 `displayWidth` 现算 —— 生命值 / 体力 / 狂怒
三处「贴在条右边的文字」都是同一个毛病，一并改了。

修完的实测：

```
拖 10%          gap 90
再 apply ×4     gap 90   ← 不动了
条缩到 60%      gap 90   ← 条 224→134px，数字跟着条走
条放回 100%     gap 90
全部重置        gap 10
```

### 12.21 「把敌人砸进地里」：从物理事故升级成正式特性

现象：跳劈有概率把敌人打到地面以下。敌人沉下去之后**打不到、也清不掉**，
「剩余敌人 1」挂着不走 —— 整局卡死；而且它还在视野里，连方向箭头都不会给。

#### 根因：它不是设计，是 Arcade 物理的挤出效应

```js
this.physics.add.collider(this.hero, this.enemyGroup);   // 英雄和敌人互相阻挡
```

跳劈时英雄以 **960 px/s** 向下砸。两个动态体重叠时 Arcade 会把它们互相推开，
而这个推力方向正好朝下 —— 英雄一帧挤敌人一点，挤几十帧之后敌人就穿过了地面。
地面是静态体，但它每帧都被重新挤下去一次，追不回来。

修法分两条腿：**把「砸进地里」变成显式机制**（保留这个手感），
**同时把物理事故的可能性从根上关掉**。

#### 一、下坠期间关掉「英雄 ↔ 敌人」碰撞

```js
// tryDiveAttack
if (this._heroEnemyCollider) this._heroEnemyCollider.active = false;
// diveImpact
if (this._heroEnemyCollider) this._heroEnemyCollider.active = true;
```

英雄直接穿过敌人体。手感上也更像「砸穿」——本来就不该被怪挡住。
实测：英雄踩着敌人做跳劈，敌人最低点始终在地面以上（`pressedBelowGround: false`）。

#### 二、`buryEnemy()`：显式的「砸进地里」

跳劈命中后按 `DIVE.buryChance`（38%）触发：

| 项 | 值 | 说明 |
|---|---|---|
| 视觉 | `scaleY × 0.42` | **只压扁视觉**，物理体一动不动 |
| 时长 | 1300ms | 期间敌人不行动（复用硬直通道） |
| 特效 | 地裂 + 尘土 + 震屏 + 「砸进地里!」浮字 | |
| 结束 | 自己拱出来（`Back.easeOut` 弹回） | |

**为什么只压扁视觉、不动位置**：位置一动就可能真的沉进地面，
「打不到又清不掉」的死局就回来了。压扁之后玩家照样打得到它、清得掉，
实测「埋在土里被打死」一切正常（伤害照算、缩放还原、死亡动画不畸形）。

**注意**：这里踩到一个连带 bug —— `damageEnemy()` 里是
`e.hurtUntil = this.time.now + 150`，**直接赋值**会把 bury 的 1300ms 长硬直砍成 150ms，
怪就一边压扁着一边站起来乱跑。改成 `Math.max(...)`。同处的击退
`setVelocity(dir * 180, -130)` 也会把埋在土里的怪打飞，加了 `if (!e.buried)` 保护。

#### 三、英雄的砸地动作

`HERO_FRAMES = 15` 里没有专门的落地帧（0-1 待机 · 2-5 跑 · 6 跳 · 7 落 ·
8-10 攻击 · 11 受击 · 12 死 · 13 翻滚 · 14 举盾），所以用 7 号 fall 帧当蹲伏姿势：

```js
// diveImpact：定格 150ms
this._landingUntil = this.time.now + 150;
this.groundCrack(h.x, h.y + 2, 460);
// updateHero 的动画选择里优先判定
else if (this.time.now < (this._landingUntil || 0)) h.play('hero_fall', true);
```

比落地瞬间就弹回待机有分量得多，而且**不动英雄的 scale** ——
改 scale 会改 `displayOriginY`，body 位置跟着动，有穿地风险。

#### 四、方向箭头补上下

上一版只指左右。沉到地面以下的敌人水平位置还在视野里，所以一个箭头都不会给 ——
「打不到也没提示」。现在上下也指：视野外的敌人贴到最近的屏幕边缘，
左右优先（这一关是横向的），水平在视野内时才用垂直方向。

#### 五、兜底：沉下去就拉回地面

```js
// updateEnemies，排在「脱离战斗」判定之前
if (spr.y > self.groundY + 40 && spr.y <= self.groundY + 700) {
  spr.y = self.groundY;
  spr.body.reset(spr.x, self.groundY);
  spr.setVelocityY(0);
}
```

注意这里是**拉回地面**而不是 `dropEnemy()`：掉出关卡下方 700px 的那种按「脱离战斗」
处理没问题，但只是沉进地面几十像素的，判它脱离战斗等于把房间草草清空 ——
玩家会看到怪凭空消失。

#### 验证（用 `game.loop.step()` 真正驱动整个 loop）

后台标签下 `requestAnimationFrame` 是停的，之前只能手动喂 `scene.update()`，
推不动 tween 和物理。这次换成 `scene.game.loop.step(t)` —— 完整跑 update + tween + physics：

| 项 | 结果 |
|---|---|
| 跳劈时碰撞被关掉 | `colliderActive: false`（下坠中）/ `true`（落地后） |
| 英雄踩着敌人跳劈 | 敌人最低点 75 < groundY 264，**没被压进地面** |
| 端到端跳劈命中 | 伤害生效、`hurtUntil` = 1300ms（说明 bury 真的触发了） |
| bury 生命周期 | 压扁 0.42 → 拱回来 1.00，`buried` 置位再清除，敌人全程存活 |
| 埋在土里再挨打 | 伤害照算、硬直仍是 1300ms、**没被打飞**（velocity 0） |
| 埋在土里被打死 | `alive: false`、缩放还原、死亡动画不畸形 |
| 触发率 | 60 次跳劈命中触发 19 次 = 32%（设定 38%） |
| 位置兜底 | 手动塞到 `groundY + 120` → 拉回 264，**没有被判「脱离战斗」移除** |
| 箭头 | 视野内 0 条；下 / 上 / 左 / 右各 20 条 |

### 12.22 苹果设备（iPhone / iPad / macOS Safari）适配

目标是「苹果用户也能正常玩上 2D 试炼，而不是被丢回文字界面」。

#### 12.22.1 先分清两类差异

排查时最容易犯的错是把 iOS 的问题当成「全都不支持」。实际是两类，处理方式完全不同：

| 类别 | 具体表现 | 处理方式 |
|---|---|---|
| **结构性做不到** | Safari 不提供元素全屏 API → `orientation.lock()` 也就永远不可用（它要求先进全屏） → 「进 2D 自动横屏」在 iPhone / iPad 上无解 | 不硬来，降级成提示条 + 引导「添加到主屏幕」（web app 模式没有地址栏，是最接近原生的形态） |
| **能做但现在没做** | 双指/双击缩放、长按 callout、横屏 text autosizing、WebGL context 被系统回收、渲染器创建失败后直接判死刑 | 逐条补上 |

#### 12.22.2 渲染启动：两条路 → 四条路

原来只按探测结果排 `[WebGL, Canvas]` 两条。问题在于 `probeWebGL()` 建的是 1×1 的小 context，
**探测通过 ≠ 真能建出 960×540 的游戏 context** —— 省电模式、Safari 里关掉硬件加速、
context 名额被上一个页面占着、低内存机型，都会让第二次创建失败。反过来某些老 WebKit 上
Canvas 渲染器又会因像素格式不兼容而失败。

现在固定排四条，逐个试，每条各自的失败原因都留下来：

```
标称 WebGL → 标称 Canvas → 极简 WebGL → 极简 Canvas
```

「极简档」（`renderConfig(true)`）只动渲染与显存相关的开关，**scale / physics / scene 一字不改**，
所以退到极简档只是画面糙一点，玩法一模一样：

- `preserveDrawingBuffer: false` / `desynchronized: false` —— iOS 上最吃显存的两项
- `powerPreference: 'low-power'` —— 省电模式下 `high-performance` 会被直接拒绝
- `batchSize: 4096 → 2048` —— 顶点缓冲占用减半
- `failIfMajorPerformanceCaveat: false` 显式关掉

`lastError()` 现在返回全部四条的原因，长这样：

```
四种渲染方式都失败 → WebGL（WebGL unsupported）；Canvas（渲染器创建失败）；
WebGL(兼容)（同左）；Canvas(兼容)（同左）
```

#### 12.22.3 失败不再一票否决：自动重试

原来一次 `init` 失败就把整局钉死在文字模式，理由是「手机上白等好几秒」。
这个判断对苹果设备是有害的：iOS 上「第一次建 context 失败、第二次就好了」极其常见 ——
页面刚加载完时名额可能还被首页特效占着、Safari 还在做首帧布局、省电模式刚切回来。

现在 `_realtimeTryStart()` 失败后按 **350ms / 1.4s / 3.2s** 再试三次，
期间显示「正在启动 2D 实时战斗…」而**不是**回退告示（否则玩家先看到「本机无法启动」，
几秒后又自己好了，像故障）。三次都过不去才 `_realtimeGiveUp()` 真正回退。
玩家手动点「重试 2D 模式」会把配额重新给满。

另加一层防重入（`_realtimeBooting`）与「重试排队中就别抢跑」的守卫 ——
`_syncTrial2D()` 是被 `renderTrialUI` 高频调用的，没有这层守卫会反复走完四条渲染路径。

#### 12.22.4 手势守卫

iOS Safari 从 10 开始就**忽略 `user-scalable=no`**：双指捏合、双击仍然会缩放页面。
横版动作里这是灾难 —— 手指一并拢画面就被放大到只剩半个屏幕，而界面上没有任何入口能缩回去。

`installGestureGuard()` 拦 Safari 专有的 `gesturestart / gesturechange / gestureend`，
双指 `touchmove` 作兜底。**刻意不碰 `touchend`** —— 在它上面 `preventDefault` 会连带吃掉
DOM 按钮的 click 合成，设置 / 图鉴 / 退出试炼就全点不动了；双击缩放交给 CSS 的
`touch-action: manipulation`（iOS 13+ 生效）。

配套 CSS：`-webkit-text-size-adjust: 100%`（禁掉横屏 text autosizing）、
`-webkit-touch-callout: none`（长按不弹菜单，输入框单独放开）、
`-webkit-tap-highlight-color: transparent`。
meta 里加 `format-detection: telephone=no`，免得数字被长按识别成电话号码。

#### 12.22.5 渲染健康看门狗

iOS 上「切出去看一眼消息 / 锁屏 / 来电横幅」之后回来，WebGL context 被系统回收是常态。
原来的表现是全黑，只能刷新重进。`bindRenderHealth()` 补三件事：

- 拦 `webglcontextlost` 并 `preventDefault()` —— **不拦的话浏览器根本不会再发 `restored`**
- `restored` 之后补 `fixCanvasSize()` + 场景 `onContextRestored()`（Phaser 自己会重传纹理）
- 回到前台主动 `loop.wake()` + `scale.refresh()`，修掉 rAF 被系统掐掉后不再续上的情况

`fixCanvasSize()` 同时改用 `visualViewport.height` 作为高度上限：iOS 上
`window.innerHeight` 是「含地址栏」的高度，容器比可视区还高时，底部那排触摸按钮
正好落在地址栏底下 —— 看得见却点不到。

#### 12.22.6 添加到主屏幕（iOS 唯一能拿到真全屏的路）

iPhone / iPad 的 Safari 没有元素全屏 API，而从主屏幕图标启动是 web app 模式：
没有地址栏、没有底部工具栏。加了 `apple-mobile-web-app-capable` 等 meta 与
`manifest.webmanifest`（`display: standalone`、`orientation: landscape`）。
在 Safari 里正常访问时这些不产生任何影响。

舞台头部那行提示在苹果设备上会换成对应的引导（`_applyTrial2DHintForIOS()`）——
顶部提示条窄到只放得下 20 个字，塞不下这句话。横屏提示条则缩短为「请旋转手机横屏」，
因为 iOS 上这里**不能**承诺「点一下就能救回来」，那是结构性不支持，不是被打断。

#### 12.22.7 顺带查出的两个真 bug

这两个都不是苹果专属，只是在苹果上触发概率最高：

1. **`.trial-screen.hidden` 的 `transform: scale(0.97)` 会毁掉全屏舞台。**
   它不是 `display: none`，而是 `opacity: 0 + transform + pointer-events: none`。
   祖先带 `transform` 时，孙级的 `.trial2d-stage`（`position: fixed`）会改成相对该祖先定位 ——
   实测舞台从铺满视口变成偏移 `(21, 12)` 且缩小 3%。更糟的是 `transition: 0.5s`：
   Phaser 在进入战斗那一刻就按容器尺寸算好了画布大小，0.5 秒后动画结束尺寸却不会再算一次，
   画布就永远小了 3%。现在 `.trial-screen.realtime-mode` 显式压掉
   `opacity / transform / pointer-events` 并设 `transition: none`。

   验证：修复前 `stage = {x:21, y:12, w:1342, h:773}`（视口 1384×797），
   修复后 `stage = {x:0, y:0, w:1384, h:797}`，画布尺寸与视口一致。

2. **回退面板掉到屏幕外面。** 回退时 `realtime-mode` 会被移除（不移除的话文字界面被
   `display: none` 压着，玩家连「退出试炼」都点不到），而面板的浮层定位恰恰只挂在
   `realtime-mode` 下 —— 于是面板回到正常流，落到可视区下方。`#trialScreen` 是
   `position: fixed` 且没有滚动条，玩家只看到一块黑，永远够不到「重试 2D 模式」按钮。
   补一个显式的浮层态 `.trial2d-stage-alert`（由 `_set2DAlertOverlay()` 挂载），
   启动提示与回退面板共用。

   顺带修掉 flex 居中的经典溢出问题：`justify-content: center` + 内容高于容器时，
   顶部会被推进滚动区之外且滚不回来。改成 `flex-start` + 首尾 `margin: auto` 的
   「安全居中」，并给子元素 `flex: 0 0 auto` —— 不然 flex 会把文字块压扁，
   压扁后内容并不缩小而是溢出重叠。

### 12.23 按键自定义编辑器：把拖动从「全量重排」里摘出来

#### 12.23.1 症状

手指拖起一个按键，画面**一卡一卡地跟不紧**，也就是常说的「不跟手」。

#### 12.23.2 原因

原来的 `layoutEditMove` 每收到一个 `pointermove` 就做一整套：

| 步骤 | 成本（本机实测） |
|---|---|
| `relayoutForEdit()`：把整个 HUD 从基准重算（摇杆 / 属性面板 / 环境面板 / 功能按钮行 / 三条槽） | 1.52ms |
| `drawEditOverlay()`：对 31 个单元逐个 `unitBounds()`（内部调 `getBounds`，Container 还要遍历子节点） | 0.82ms |
| `notifyLayoutBar()`：31 个 chip 的 class 开关 + 一串文本 | 0.53ms |
| 合计 | **约 1.6～4.7ms / 每次 move** |

而拖动**只改变一个单元的位置** —— 上面三件事里没有一件是必要的。

更要命的是两处放大：

1. **一帧内不止一个 move 事件。** 触摸设备采样 120Hz 起步，高刷屏更高，浏览器把同一帧内的多个 `pointermove` 都派发出来，于是每帧要付好几套。手机 CPU 只有本机的三分之一到五分之一，一帧轻松吃满 16.7ms 的预算。
2. **`update()` 里还有一句 `if (this.editMode) this.drawEditOverlay();`** —— 每帧再全量重画一次外框。原注释写着「编辑时战斗已冻结，这里的开销无关紧要」，但冻结的是**战斗**，玩家正在拖手指，这笔开销直接变成手感。
3. 每帧重建 `editableUnits()` 会造出上百个闭包，触发周期性 GC，卡顿就变成一顿一顿地来。

另外两处独立的阻塞：

- **吸附发生在拖动过程中**（`c.dx = Math.round(c.dx * W / 4) * 4 / W`）。4px 步进让位移一格一格地跳，手上就是「涩」。
- **滑杆每次 `input` 都同步写 localStorage**（`JSON.stringify` + `setItem` 是同步磁盘 I/O）。拖一次缩放会甩出几十个 `input`，主线程被堵几十次。

#### 12.23.3 改法

把拖动拆成「只动那一个单元」：

| 原 | 现 |
|---|---|
| 每帧全量重排（1.5ms） | `_moveUnitBy(id, dx, dy)` 只搬被拖的单元 |
| 每帧对 31 个单元重算包围盒 | `_editBounds` 缓存；只重算被拖的那一个（`_redrawUnitFrame`） |
| 每帧同步 DOM | 拖动期间**完全不动**，松手时同步一次 |
| 拖动中吸附 | **拖动中不吸附**（连续跟手），松手时补一次对齐 |
| 每帧重建 `editableUnits()` | `_editUnits()` 缓存，基准变化时才重建 |
| 滑杆每次 input 写盘 | `saveCustomLayoutSoon()` 去抖 250ms；退出编辑立刻补一次 |
| 滑杆每次 input 同步 DOM | `syncLayoutBarSoon()` 合并到「一帧最多一次」 |

几个细节：

- 缓存的失效入口只有两处 —— `relayoutForEdit()` 和 `onResize()`（它们各自是「基准重算」的唯一入口），都调 `_invalidateEditCache()`。
- `syncLayoutBarSoon` 用 `setTimeout(0)` 而不是 `requestAnimationFrame`：页面切到后台时 rAF 会停，挂着的标记再也清不掉，DOM 同步会**永久卡死**。
- 偏移记录 `_appliedOffset` 与显示对象必须同步前进（`_shiftUnit` 一起维护），否则下一次重排会按 `c.dx` 再搬一遍，位置就飘了。

#### 12.23.4 顺手修掉的旧 bug：缩放会把拖动位置拽回原位

`applyButtonStyle` 是**按 `slotCenter` 绝对定位**的（`b.x = Math.round(b.slotCenter - b.w / 2)`），而它在 `applyCustomLayout` 里的执行顺序排在位置分支**之后** —— 玩家拖出来偏移刚加上去，立刻又被这一句抹掉。

表现：**把「退出试炼」按钮拖到别处，再动一下缩放滑杆，它就跳回原来的位置。**

修法是在 `applyButtonStyle` 之后把本轮该有的偏移补回去（此时 `_appliedOffset[u.id]` 已经是本轮算好的总偏移）。触摸按键不受影响 —— 它们是普通显示对象（`objs` 路径），不走 `slotCenter`。

#### 12.23.5 验证

| 项 | 结果 |
|---|---|
| `layoutEditMove` 单次成本 | **1.645ms → 0.0275ms**（约 60×） |
| `drawEditOverlay`（每帧） | **0.817ms → 0.0075ms**（约 109×） |
| `unitAt`（按下命中） | **1.162ms → 0.0033ms**（约 350×） |
| 单次拖动落点 | 位移 (100,50) 精确命中，归一化偏移记录一致 |
| 重排 / 转屏后 | 位置**不跳变**（`relayoutForEdit`、`onResize` 各测一次） |
| 连续 5 轮拖动 | 累加 (150,100) 无漂移；再重排仍不跳变 |
| 退出 / 重进编辑 | 位置保持 |
| 落盘 | 布局正确写入 `abyss_trial2d_layout` |
| 复杂单元 `h.hp`（meters + objs + apply 三路） | 血条 (60,30)、数值文本 gap 源头同步；重排后不跳变 |
| 容器单元 `h.stats` | 位移正确 |
| 隐藏 / 透明度 / 单项重置 | 全部生效 |
| 拖动 + 缩放 | 中心守在拖动位置；**偏移零污染**（连缩 10 轮偏差 0.00px），回到 100% 精确复原 |
| 滑杆去抖 | 拖动期间不落盘，停手后写一次；退出编辑立刻补保存 |
| 命中测试 | 框内可选中、框外不误选、按钮可命中 |

（缩放过程中按钮中心有 1～4.5px 的取整抖动，来自 `b.w = Math.round(baseW * s)` 与 `paintButton` 的 pill 宽度自适应，属既有行为且不累积。）

### 12.24 v2.8：菜单中枢、设置横版，以及两个"看不见"的 bug

#### 12.24.1 「重新开始」之后诅咒还在

根因：实时化诅咒存在 `state._rtCurses`（纯字符串数组，可安全存档），而它**只由 经典2D.js 在玩家第一次中诅咒时随手挂到 state 上** —— `state` 的字段表里根本没有它，于是 `resetCurrentSlot()`（「重新开始」唯一实质动作）与 `initGame()`（新开一局）也都没清它。新局 `startRun` 时 `curses: rtCurses(s)` 就把上一局的诅咒原样带进了引擎。

修法：三处一起收口 —— 字段表里显式声明 `_rtCurses: []`、`resetCurrentSlot()` 清空、`initGame()` 清空。**读档续玩不清**（存档里的诅咒本来就该带进来，见 12.16 那段）。

实测：`state._rtCurses = ['易伤','生命流失']` → `resetCurrentSlot()` → `state._rtCurses` 为空、`mode` 回到 `heroSelect`；再走完整的「选英雄 → 选增益 → 进 2D」，引擎侧 `scene.curses` 也是空的。

顺带修掉一个同源的死按钮：作弊面板的「清除诅咒」只认已关停的试炼状态（`state.trial.active`），在经典 2D 模式下第一行就 `return` —— 点了没反应。

#### 12.24.2 窄屏上「最后那颗按钮不见了」

现象：HUD 常驻功能按钮行的最后一颗（当时的「退出」）在窄窗口里看不见，连布局编辑器的外框也在屏幕外、点不到。

根因：字号与按钮高度都有绝对下限（字号 11px、高 24px），于是这一行存在一个**最小可能宽度**（4 颗约 320px）。旧 `layoutPillRow` 无论窗口多窄都按原生宽度从左往右排 —— 窗口比它窄时，行尾那颗被整个推出画面。

修法：`layoutPillRow` 新增 `maxRight` 参数，超出时给整行乘一个统一的收缩系数 `fitScale`。三个必须注意的点，都是实测踩出来的：

1. 收缩系数要与编辑器的 `userScale` **分开存**，否则每次重排都会在上一轮的系数上再乘一遍，越排越小；
2. `paintButton` 里的字号 / 内边距 / 图标也要跟着缩 —— 只缩底板不缩内容的话，`if (b.w < need)` 会按原字号把宽度撑回去，收口等于没做；
3. 槽位要用 **floor** 后的宽度累加，且收口期间**禁止** pill 的自动加宽，否则每颗会悄悄长回 1~2px，4 颗累积下来行尾照样越界。

实测（`layoutHudButtons(W)` 逐档探针）：

| 画布宽 | 行尾 x | 允许上限 | 收口系数 | 越界 |
|---|---|---|---|---|
| 1920 | 348 | 1908 | 1.000 | 否 |
| 800 | 329 | 788 | 1.000 | 否 |
| 520 | 315 | 508 | 1.000 | 否 |
| 360 | 315 | 348 | 1.000 | 否 |
| 320 | 307 | 308 | 0.976 | 否 |
| 300 | 287 | 288 | 0.907 | 否 |
| 280 | 267 | 268 | 0.838 | 否 |

#### 12.24.3 HUD「更多」+「退出」→ 一颗「菜单」

两颗按钮的功能与名字本来就对不上：「更多」只是打开 DOM 侧边栏，而「退出」点下去弹的其实是暂停菜单（里面叫「结束本局」）—— 于是玩家的感受是"退出不见了"，布局编辑器里点「退出」的框也像是选错了按钮。现在合并成一颗「菜单」，打开画布内的**本局中枢**：

- 左栏「本局」：生命 / 护盾 / 体力 / 金币 / 遗物 / 诅咒 + **诅咒明细**（诅咒在持续结算，只给计数说不清代价）
- 右栏「系统」：通关条件 / 图鉴 / 教程 / 设置 / 存档管理 / 作弊 / 切换老版 2.6，外加难度胶囊一排（当前项 primary 高亮）
- 底部：继续战斗（primary）/ 结束本局（danger）
- Esc 开关，再按一次收起

界面全部画布内绘制，复用既有的 `addPanel` / `craftButton`；图标是照 `ensureIconTextures` 既有规格新画的 9 枚（16×16、2px 笔宽、白色描边、运行时 tint），**不用 emoji** —— 它们的字形、基线、粗细跨平台都不可控，一混进来整排图标的视觉重量就散了。面板尺寸**由内容算出来**（先量几何再画）：固定高度在窄屏上必然顶出画面。

桥接只传 id：`bridge.openPanel(id)` / `bridge.setDifficulty(v)`。引擎不认识"作弊面板"这类业务语义，由宿主决定开哪个；难度那条特意**驱动顶栏 `#difficultySelect` 走它原有的 change 处理器**，保证"难度怎么变"只有一个实现、两边不可能漂移。侧边栏本体保留（开始界面 / 文字界面照旧用），只是 2D 画面里不再有它的入口。

冻结时机有个坑：`openPanel` 里必须**先冻结再打开**。DOM 面板的显示靠一次 class 切换，而 `watchDomPanels` 的观察器是异步回调的 —— 等它发现面板开了，中间已经过去若干帧，那几帧里敌人照样在打你。

| 项 | 结果 |
|---|---|
| Esc 开 / 关 / 再开 | 全部正确；物理世界同步暂停与恢复 |
| 点「设置」 | `settingsModal` 打开，`_viewPaused === true`（战斗已冻） |
| 点「困难」 | `state.difficulty` 立即变更且高亮刷新（`hard:primary`） |

#### 12.24.4 设置界面改横版

原来是「一列 14 项」的竖长条（inline `max-width: 440px`）：一屏装不下、必须滚动，而里面全是"扫一眼就调完"的开关。改成**按类别分列**（画面 / 音频 / 系统与操作），弹窗宽而扁，与 2D 画面的横版布局同构。

- 分类**只是呈现**：`SETTINGS_DEFS` 仍是唯一数据源；漏归类的 key 会被兜底逻辑收进「其他」列 —— 宁可多一列，也不能让某一项设置因为没人给它归类就从界面上消失。
- `minmax(0, 1fr)` 不能省：列宽下限默认是 min-content，而「标签 + 开关」那一行有最小宽度，会把两列撑破容器、内容横向溢出。
- 断点：桌面 `min(94vw, 980px)` 三列；≤720px 降两列；≤620px 降一列；横屏手机（`max-height: 560px` 且 `min-width: 600px`）**显式写回三列** —— 否则 800×360 会同时命中 ≤720px 的降级规则，塌成两列、内容高度几乎翻倍（实测需滚动 704−346 = 358px，写回三列后是 467−346 = 121px）。

iframe 实测（真实 800×360 视口）：三列各 230.7px、弹窗 730×331 完全落在屏内、横向零溢出、14 项一个不少。

#### 12.24.5 菜单里切难度会卡死（叠层 + 整层重建）

现象：在菜单里连点几次难度，画面一次比一次卡，最后拖不动。

两个原因叠在一起：

1. **重画不销毁旧层。** 切难度后要重画一次菜单刷新高亮，而 `buildPauseLayer` 只做 `this.pauseLayer = 新层` —— 旧层既没销毁、也没人引用。每切一次就叠一层：55 个显示对象 + 一层暗幕，旧层的按钮仍然留在场景里被渲染；而 `closePauseMenu` 只销毁**最后**建的那层，前面几层永远回收不掉（引用已丢，连手动清都做不到）。
2. **整层重建本身就很贵。** 菜单有 55 个显示对象（14 颗按钮 × 底板/图标/文字 + 面板 + 各处文字），实测一次 `buildPauseLayer()` = **18.2ms**，比一帧预算（16.7ms）还长。而这件事真正变化的只有 5 颗胶囊的语义色。

修法三条：

- `buildPauseLayer` 重画前先 `destroyLayer('pauseLayer')`。这条路径不只切难度会走 —— 转屏 / 重排同样会重画。
- 新增 `refreshMenuDifficulty()`：切难度只重画那 5 颗胶囊，**实测 0.53ms**。注意三个字段要一起改 —— `craftButton` 建立时按 `variant` 定了底板 tint 与文字颜色，只改 `variant` 的话重绘出来还是旧色。
- 胶囊引用 `_menuDiffBtns` 统一在 `destroyLayer` 里清：销毁路径有四条（关闭 / 重画 / 重排 / 转屏），分散在各调用点写迟早漏一条。

实测（真实浏览器）：

| 项 | 修复前 | 修复后 |
|---|---|---|
| 单次切换 | 17.95ms，叠层之后还要乘以层数 | **4.29ms**（引擎侧只重画胶囊 0.53ms，其余是宿主 `render()`） |
| 整层重建 | 18.2ms / 次 | 不再发生 |
| 连切 15 次后的层数 | 逐次递增（每层 55 个对象） | **恒为 1** |
| 关闭菜单后的残留 | 前几层永久留在场景里 | **0 层**，`children.list` 回到基线 |
| 难度高亮 | — | 正确（`hard:primary`），真实指针点击后立刻跟上 |
| 物理 / 帧率 | — | 关闭后物理恢复，FPS 57.6 |

顺带记一条排查经验：`战斗2D.js` 是**按需加载**的（`window.__加载2D引擎` 动态注入 script，见 主界面.html 的说明），所以改完引擎文件之后**进一次 2D 就会拿到新代码**，不必刷新整个页面。第一次复现"没看到叠层"正是因为这个 —— 差点把真 bug 判成误报。

### 12.25 全面加强怪物：三个维度，而不是一条倍率

用户反馈「怪物太弱了，所有难度下都全面加强」。改之前先把"弱"拆开：

敌人属性只有一个入口 —— 宿主的 `enemyScaler(info)`（经典2D.js），返回 `{ hp, atk }`；而**移速 / 前摇 / 后摇 / 索敌范围是 `ENEMY_TYPES` 里的固定值，完全不受难度与层数影响**。所以"只加血加攻"能得到的只是一只更肉更痛的沙包：它还是那么晚发现你、还是那么慢地追、还是那么久才出第二刀。

于是分三层一起动：

#### 12.25.1 难度倍率（主程序.js 的 `difficultyModifiers`）

| 难度 | 血量（旧→新） | 攻击（旧→新） |
|---|---|---|
| 简单 | 0.9 → 1.10（+22%） | 0.9 → 1.00（+11%） |
| 普通 | 1.0 → 1.30（+30%） | 1.0 → 1.22（+22%） |
| 困难 | 1.15 → 1.55（+35%） | 1.2 → 1.50（+25%） |
| 地狱 | 1.35 → 1.85（+37%） | 1.4 → 1.80（+29%） |

「简单」也涨了 —— 用户明确要求所有难度；但它仍然是最弱的一档，档位顺序没动。经济那几项（金币 / 商店 / 休整 / 护甲）刻意**不动**：这次只谈敌人强度，混进经济改动就没法判断哪一项造成了体感变化。

#### 12.25.2 层数成长曲线（经典2D.js 的 `enemyScaler`）

```
血量基数  floor×2 + 4   →  floor×2.5 + 5
攻击基数  floor ÷ 2     →  floor×0.62
```

这条修的是**后期**：原来玩家攻击一涨，前期怪和后期怪就都是两三刀的事。改完第 50 层爪牙 104→169 血、28→41 攻，而第 1 层是 6→10 血（玩家初始 5 攻，两刀砍死 —— 开局手感刻意保持不变）。

#### 12.25.3 AI 侵略性（新增通路）

难度表里新增 `enemyAi` 倍率包（移速 / 前摇 / 后摇 / 索敌），宿主 `enemyScaler` 把它随 `hp/atk` 一起回传，引擎侧新增 `boostEnemyDef()` 消费它：

```js
var stats = this.enemyStats(def, floor, key);
if (stats.ai) def = this.boostEnemyDef(def, stats.ai);   // ← 换 def，而不是改读取点
...
var e = { def: def, ... };
```

为什么不逐个去改 AI 状态机里那十几处 `def.speed` / `def.windup` / `def.recover` / `def.detect`：**换掉 def 本身**就行，`e.def` 跟着换，后面所有读取自然生效。这和 `mimicDef` 是同一个套路。实测原表没有被污染 —— 地狱难度下爪牙移速是 89（= 72×1.24），说明每次都是从基数重新算的。

| 难度 | 移速 | 前摇 | 后摇 | 索敌 |
|---|---|---|---|---|
| 简单 | ×1.02 | ×0.98 | ×0.96 | ×1.10 |
| 普通 | ×1.08 | ×0.94 | ×0.90 | ×1.22 |
| 困难 | ×1.16 | ×0.88 | ×0.82 | ×1.36 |
| 地狱 | ×1.24 | ×0.82 | ×0.76 | ×1.50 |

**两道护栏是刻意的**：

- **前摇硬下限 200ms**（后摇 140ms）。完美闪避的窗口是固定的 150ms，玩家要"看到起手 → 在命中瞬间闪"；前摇一旦压到窗口附近，这一击就变成没法反应的抽奖 —— 那不是变强，是变坏。
- **索敌上限 ×1.5**（引擎与宿主两侧各有一道闸）。索敌太远会让怪隔着半个房间就冲过来，「一个一个引」的节奏就没了。

#### 12.25.4 量化：`测试/怪物强度测试.js`

和 `测试/房间节奏测试.js` 同一套做法：**从源码正则抽真实常数**（难度表直接 `eval` 那段对象字面量、层数曲线抽 `floor × A + B` 与 `round(floor × M)`），再按老版 2.6 的旧公式算一遍基线，两边对照。它同时是回归护栏：

- 四档难度的 `enemyHp` / `enemyAtk` 必须严格递增 —— 调参最容易犯的错就是把两档调反；
- 每一档都必须强于旧版（用户要求"所有难度"）；
- 第 1 层爪牙血量必须落在 8~14（不能为了后期把开局搞成磨血）；
- 引擎侧必须存在 200ms / 140ms 那两条下限。

实测输出（普通难度爪牙，旧→新）：第 1 层 6→10 血、第 10 层 24→39、第 50 层 104→169；地狱第 50 层 140→241 血、39→61 攻。

### 12.26 读档之后 2D 回不去：一个自我封闭的死锁

用户反馈：「局内加载外部存档没正确加载 —— 文字界面应该也变了，只有 2D 界面没变」。

#### 12.26.1 根因

引擎的接管判定（经典2D.js 的 `shouldTakeOver`）里有这么一条：

```js
if (!s.currentRoom) return false;   // 还没进第一间房
```

而 `state.currentRoom` 是 **2D 自己的 `rt:room` 回调**写进去的（`onRoom` 里 `s.currentRoom = { type }`）。于是当换进来的存档**存的时候恰好不在房间里**（刚打完层主、正在选结局、居间时刻），`currentRoom` 就是 `null`：

```
currentRoom === null
   → shouldTakeOver() 为 false
   → render() 判定"不接管"：把 mode 从 'classic2d' 改回内核的 'event'、收起画布
   → 引擎不 startRun
   → 永远不会产生 currentRoom
   → 永远不接管        ← 自我封闭
```

**外在表现正是用户描述的那样**：`state` 确实换过了（文字界面 / 日志 / 金币全对），唯独 2D 停在旧局的原地不动 —— 因为引擎根本没重开，canvas 上还是上一帧。

实测复现（构造一份 `currentRoom=null` 的存档，走真实导入顺序）：

```
after: { running: false, engineFloor: 9, stateFloor: 12,
         mode: 'event', currentRoom: null,
         takeOver: false, reason: 'currentRoom=null', stageShown: false }
```

#### 12.26.2 修法

新增 `ensureHostRoomMark()`：换局之后**在 `render()` 之前**，按存档自己的 `rooms` / `roomIndex` 把入场标记补上。三个入口都要走：

| 入口 | 位置 |
|---|---|
| 启动时读档 | `initGame()` 的 `_继续读档` |
| 存档管理的「加载」 | `handleSaveAction('load')` |
| 导入外部存档 | `legacyFileInput` 的 `change` |

顺序不能动：**补标记 → render → 补拉**。补标记必须早于 `render()`，因为 `render()` 一旦判定不接管就会改写 `mode`、收起画布；补拉（`ensureHostRunAlive()`）只是第二道保险 —— 它在"该接管却没跑"时补一次 `start()`。

**判据写法上有个坑值得记**：第一版我拿 `mode === 'classic2d'` 当门票，结果完全不生效 —— 实测一份**正常存档里的 `mode` 就是 `'event'`**（`'classic2d'` 是宿主自己的标记，引擎一旦判定不接管就会把它改回去，那之后这个标记永远回不来，修复本身被卡死）。现在判据与 `shouldTakeOver()` 对齐：有 hero、非 gameOver、mode 不在内核界面态（选英雄 / 选增益 / 开始 / 结算）、**且有房间表**。

`ensureHostRunAlive()` 的判定交给引擎自己（`debug().takeOver`），所以选英雄 / 选增益 / 结算这些**本来就不该接管**的情形不会被误拉起来。三种场景实测：正常运行时不动（返回 true）、停掉未接管时补拉成功（引擎层数跟着 state 走）、`mode=heroSelect` 时拒绝补拉。

修复后同一份"问题存档"：

```
mode: 'classic2d', currentRoom: { type: 'enemy' },
running: true, takeOver: true, engineReady: true,
engineFloor: 12, enemies: 9, stageShown: true
```

#### 12.26.3 顺带：浅合并留下的旧局残留

`loadGame()` 与导入路径用的都是 `Object.assign(state, savedData)` —— **浅合并**：它只覆盖"存进去有的键"，**不会删除** `state` 上已有的键。旧版本导出的档没有 `_rtCurses`，于是上一局的诅咒原样留在新局身上。这和 12.24.1 那个「重新开始后诅咒还在」是同一类问题，只是入口不同；两处都补了兜底（档里没有这个键就归零）。
